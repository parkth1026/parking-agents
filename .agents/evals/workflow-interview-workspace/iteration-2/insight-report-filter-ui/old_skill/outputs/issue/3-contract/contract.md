# Goal Contract: 给 insight HTML 报告加按 facet 筛选的下拉框

- Status: Ready
- Target: .copilot/agents/insight/generate-insight-report.js
- Updated: 2026-08-13

## 原始请求

> .copilot/agents/insight/generate-insight-report.js 生成的报告现在是一份很长的静态大页面，想加一个按 facet 筛选的下拉框，选了之后只显示对应 facet 的内容，不用整页翻。

## 目标

打开报告后能用一个下拉框只看某一个 facet（页面区块）的内容，不用再整页滚动翻找。

## Why

- 现状：报告一次生成就是 23 个纵向排列的区块（At a Glance、对话动力学、Agent 分布……到 Session 详情列表），日常读者每次只关心其中一两块，却要滚过全部内容才能找到。
- 做到之后：打开报告先看到一个顶部常驻的筛选下拉框，选中一个 facet，页面只留那一块内容，浏览成本从「整页翻」降到「选一下」。

## 范围

做什么：
- 在报告顶部加一个 sticky 的 facet 筛选栏，含下拉框、当前 facet 高亮徽标。
- 下拉框覆盖除页面头部横幅（标题/统计条）外的全部区块，含 Session 详情列表；选项文案用人话，不用内部 id。
- 选中某个 facet 后只显示对应区块，其余隐藏（不删除 DOM）；无数据的 facet 选项照常出现，选中后显示固定空态文案。
- 现有左侧 nav-toc 侧边导航保留，点击其中的锚点链接联动切换筛选状态，三处选中态（下拉框/顶部徽标/nav-toc 高亮）保持一致。
- 页面打开默认展示第一个 facet，不做跨次持久化。

不做什么：
- 不改变 `generate-insight-report.js` 的命令行参数、退出码、输出文件路径。
- 不新建可视化回归/端到端测试基建。
- 不把 mock.html 的具体配色/间距当成像素级还原标准（结构与关键交互对齐即可）。
- 不引入任何持久化机制（localStorage/cookie 记住上次选择）。
- 不改动报告里与筛选无关的既有功能（`copyCode`、`toggleCollapse`、`slSort` 等）。

## 强约束

- 现有 `nav-toc` 侧边栏结构（`#navToc`、`toggleNav`）与既有锚点跳转能力必须保留，只允许新增「点击锚点联动同步筛选状态」这一行为，不得删除或替换成别的导航方式。
- 页面头部横幅（标题、统计条，对应现有 `id="sec-header"` 区块）在任何 facet 选中状态下都必须保持可见，不参与筛选隐藏。
- 报告必须仍是 `generate-insight-report.js` 一次性生成的自包含静态 HTML：不得引入外部 CDN 脚本/样式/字体，不得依赖构建步骤。
- 不做「记住用户上次选择」的持久化；每次打开报告默认展示的都是列表里第一个 facet。
- 确认版对照物 `../2-prototype/mock.html` 声明为不可修改：执行 Agent 改的是 `generate-insight-report.js` 生成的报告本身，不是这份 mock。

## 自主边界

不用问，直接定：
- 具体 CSS 类名、JS 函数命名。
- 下拉框沿用原生 select 元素还是自绘组件，只要交互与 mock 一致。
- 选中态高亮的具体配色数值、圆角、间距等像素细节。
- facet 清单在代码里用什么数据结构表达（数组/对象/常量表都可以）。
- 空态提示的具体 HTML 结构，只要求显示「这个 facet 暂无数据」这句话。
- 响应式/窄屏适配的具体写法。

必须停下来问：
- 要不要把 facet 覆盖范围从「除 header 外全部区块（含 Session 列表）」改成别的范围。
- 要不要引入任何持久化（记住上次选择）。
- 要不要把 mock.html 的样式当成像素级硬性还原标准。
- 需要新增任何命令行参数、外部依赖，或改变现有输出文件路径时。

## 术语说明

本契约里的「facet」指报告页面上纵向排列的区块（现有 `<div class="section" id="sec-*">`
结构，也就是既有 `nav-toc` 侧边栏锚点列表指向的那些）。代码里另有一个同名变量
`facetsData`/`facets-cache`，指每个 session 的 LLM 语义抽取字段（`briefSummary`/
`goalCategories`/`outcome` 等），是数据层概念，与本契约的「facet」是两回事，不要混用。

## 读什么

- `../2-prototype/mock.html` — 确认版界面对照物，唯一权威来源，逐条验收都指回这里。

## 验收条件

- AC-001: 在报告页面选中下拉框里的某个 facet 后，主内容区只显示该 facet 对应的区块，其余区块隐藏但不从 DOM 里删除；页面首次打开时默认展示的是列表里第一个 facet，刷新后仍回到第一项（不做跨次持久化）。
  - Verify: [C] 打开 `../2-prototype/mock.html`，依次选中下拉框中的每一项（含 “At a Glance 总览”“对话动力学总览”“Session 详情列表” 等），确认每次只有一个 `.section` 可见、其余带 `.is-hidden`；刷新页面确认回到第一项。
- AC-002: facet 筛选栏位于页面顶部醒目位置，向下滚动页面时始终留在视口内（sticky）。
  - Verify: [C] 打开 `../2-prototype/mock.html`，向下滚动到页面中部，确认 `.facet-filter-bar` 始终可见于视口顶端，不随内容滚出画面。
- AC-003: 当前选中的 facet 在至少两处产生明显、彼此一致的视觉反馈（顶部筛选栏内的高亮徽标 + 侧边 nav-toc 里对应链接的高亮态），且下拉框的值、顶部徽标文案、nav-toc 高亮三者随时保持一致；通过点击 nav-toc 锚点链接切换 facet 时同样触发这一整套联动。
  - Verify: [C] 在 `../2-prototype/mock.html` 中分别用「下拉框选择」和「点击 nav-toc 链接」两种方式切换 facet 各一次，确认每次切换后徽标文案、nav-toc 高亮项、下拉框选中值三者都指向同一个 facet。
- AC-004: 下拉框选项固定覆盖全部候选 facet，不因某次报告实际数据是否齐全而增减；选中一个当次没有数据的 facet 时，主区域显示固定文案「这个 facet 暂无数据」，对应的区块容器仍会生成（不是整个选项消失或渲染空白）。
  - Verify: [C] 在 `../2-prototype/mock.html` 中选中示例里刻意设为无数据的 “叙事洞察”，确认它仍出现在下拉框选项列表里，选中后主区域显示「这个 facet 暂无数据」。
- AC-005: 下拉框覆盖除页面头部横幅（`sec-header`）外的全部区块，含 Session 详情列表；选项文案是人话（复用现有 `nav-toc` 侧边栏已经在用的中文标签），不出现 `sec-*` 这类内部 id 或代码变量名；无论选中哪个 facet，头部横幅都保持可见。
  - Verify: [C] 对照 `../2-prototype/mock.html` 里下拉框（select 元素）的选项文案与 `nav-toc` 现有链接文案逐条核对一致；任意切换 facet 后确认 `#sec-header` 始终可见。

## 设计取舍

本次无需取舍：改动范围限定在单文件 `generate-insight-report.js` 内追加一段筛选栏 HTML/CSS/JS，沿用既有内联样式与原生 JS 的实现方式，没有出现两条成本结构不同、都算成熟的实现路径需要权衡。唯一实质性分歧发生在 mock 迭代阶段（筛选栏位置、选中态反馈），已通过两轮 mock 修改直接收敛，不构成需要单独记录取舍的架构决策。
