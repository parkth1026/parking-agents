# Impact Surface: 2026-08-13-insight-report-facet-filter

## 用户可见界面 — 有
`generate-insight-report.js` 生成的 HTML 报告新增一个 facet 筛选下拉框，页面顶部
醒目位置常驻；选中某个 facet 后，主内容区只显示该区块，其余 22＋1 个区块隐藏
（不删除 DOM，只是不显示）；无数据的 facet 选项照常出现，选中后主区域提示
「这个 facet 暂无数据」。既有左侧 `nav-toc` 滑出导航保留，点击其中的锚点链接时
联动切换下拉框的选中值。
→ 出 `mock.html`。

## 可观察行为 — 无（并入界面对照物）
这次改动完全体现为「同一份数据、同一次生成，浏览时看到的内容范围不同」，是纯客户端
展示层的显隐切换，没有独立于界面之外的、需要单独对照表描述的行为分支（没有新的
CLI 参数、没有新的数据处理路径、没有分支输出不同文件）。筛选行为本身（选中 A 只显示
A、选中无数据项显示空态提示、nav-toc 联动）已经是 `mock.html` 里可以逐处点击验证的
交互状态，不再另出 `behavior.md` 重复描述同一件事。

## 可运行输出 — 无
`generate-insight-report.js` 的命令行调用方式、参数、退出码、生成文件路径都不变；
生成出来的仍是同一个 `.html` 文件，脚本本身在终端里跑起来的样子不变（不打印新的
筛选相关信息）。不出 `example-run.md`。

## 对外接口报文 — 无
这是纯前端静态报告脚本，不对外提供网络接口，也不消费网络接口；`--facets-path` 等
现有 CLI 参数的输入 JSON 结构不变。不出 `api-mock.md`。

## 用户配置 — 无
不新增命令行参数、环境变量或配置文件字段。下拉框覆盖哪些区块由代码里的固定清单
决定（对照 `1-interview/rounds.jsonl` Q1 的确认结果），不做成可配置项——需求里也
没人要求可配置。
