# Impact Surface: 2026-08-13-cli-list-grouping

## 用户可见界面
无。`session.mjs` 是纯命令行脚本，没有任何图形界面或网页界面被这次改动触碰。不出 `mock.html`。

## 可观察行为
有。`list` 子命令：
- 不带任何 flag 时，输出必须与现状字节级一致（这是访谈阶段锁定的强约束）。
- 带 `--stage <stage>` 或 `--status <status>` 时，输出从摊平表变成按 stage 分组、每组标题带 issue 数量，并按 flag 过滤。
- 过滤后 0 命中时要明确提示，不能空输出。
出 `behavior.md`。

## 可运行输出
有。这是一个终端命令，「怎么调用、退出码是什么、人看到什么字面文本」需要用具体、可复制的调用示例钉死，且要覆盖「现有调用方式必须逐字节不变」这条强约束本身能不能被验证。
出 `example-run.md`。

## 对外接口报文
无。`session.mjs` 不对外提供网络接口或结构化报文（stdout 是给人读的文本，不是给程序消费的 JSON）。不出 `api-mock.md`。

## 用户配置
有，但很薄：新增两个命令行参数 `--stage`、`--status`，没有配置文件、没有环境变量改动。作为 `behavior.md` 的「配置差异」小节处理，不必单开一份文档。

## 历史兼容性
有，且是这次改动里代价最高的一面。已确认的事实：用户在自己电脑上有一个不在这个仓库里的 PowerShell 脚本，靠 `list` 现在输出的固定列宽/列顺序解析文本，喂给一个提醒工具。这条路径完全在仓库边界之外，无法用自动化测试覆盖到那个外部脚本本身，只能保证「不加 flag 时这边吐出来的字节和现在一模一样」，把风险钉在我们控制得到的这一侧。写进 `behavior.md` 的「不变清单」。
