# FINAL REPORT — Insight Report 按板块筛选下拉框

## 我对这个需求的理解

`generate-insight-report.js` 生成一份零依赖、单文件、暗色主题的静态 HTML 报告，目前纵向平铺 25 个 `<div class="section" id="sec-xxx">` 板块，仅靠左侧 `nav-toc` 做锚点跳转，页面很长。需求是加一个下拉框，选中某个板块后只显示该板块，其余隐藏，减少整页滚动。

原始需求里的"facet"一词有歧义，我把它拆成了两个候选（`facets-schema.json` 的语义字段 vs. 报告的 25 个 nav-toc 导航分区），通过模拟访谈确认：**要做的是后者**——即按报告现有的 25 个板块筛选，与 `facets-schema.json` 的字段没有强绑定，`facets-schema.json` 本身不用改。这是我认为最容易被误做错的一点，所以放在方案文档最前面单独澄清。

其余关键决策：单选、不做持久化、默认"全部"、下拉文案必须是人话（复用 nav-toc 现有中文标题）、header/stats-row/footer 全程不受筛选影响、以及最重要的边界情况——多数板块是条件渲染的，没数据时对应 DOM 节点根本不存在，所以筛选逻辑不能假设 25 个 id 都能在 DOM 里查到，选中"没数据"板块时必须给出明确提示而不是空白。

## 我认为的验收标准

详见 `OUTPUT.md` 第 6 节，摘要如下：

1. 默认"全部"，行为与现状完全一致。
2. 下拉框 25 个选项文案 = nav-toc 现有中文标题，不暴露内部 id/字段名。
3. 选中某板块 → 只显示该板块，其余板块整体隐藏（不是空白占位），header/stats-row/footer/nav-toc 不受影响。
4. 单选，无记忆（无 localStorage/URL 参数）。
5. 选中"当前报告里没生成"的板块时，必须显示"暂无数据"一类明确提示，不能空白。
6. 保持零外部依赖（内联 CSS/JS）。
7. 暗色主题与现有响应式样式不出现明显回归。

## 还没搞清楚 / 留给实现判断的地方

1. **无数据选项的视觉区分**（下拉框里置灰或标记"无数据"）——访谈中维护者说这是加分项、非硬指标，具体做不做、怎么做没有钉死。
2. **nav-toc 点击行为在筛选态下如何联动**——比如用户切到"满意度分析"单板块视图后，又点了 nav-toc 里"Agent 分布"的锚点（此时该板块已隐藏），要不要自动切回"全部"或自动跳转到该板块——访谈没覆盖，我在文档里给了一个建议（自动重置为"全部"），但这不是维护者亲口确认的决策，实现前最好再对一句。
3. **"暂无数据"提示的实现方式**——是让所有 15+ 处条件渲染都改成"容器常驻、内部按数据分支渲染"，还是只在下拉框筛选逻辑里做"DOM 节点缺失就动态插入提示"的补丁——两种都能满足验收标准，工程量差异较大，文档里列了两个选项但没有替维护者拍板选哪个，因为这纯粹是实现成本 vs. 代码整洁度的取舍，不影响用户可见行为。
