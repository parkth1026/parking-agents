   「跑一遍端到端」的真实代价被写成「先建一套现在不存在的基建」而不是「代价较高」。
8. **F8** 下游 body 形状 `{"events":[...]}` 是硬的（`docs/schema.md` + `forwarder.mjs` 注释）。

`Agent-owned` 明确留给执行 Agent 的：哈希函数选型、`sample` 节字段命名、判定代码放

## 3. 用户推翻的默认项 / 确认项 / 我的候选（逐条列出原文）

**推翻 1 — D4 的档位（默认区 → 强约束）**

> 「**D4 我要多说一句，这条不是「不反对就算定」的级别，是必须。** 采样率默认值必须是 1.0，
> 也就是默认不采样。线上配置是 infra 仓库的模板渲染下发的，发布是分批滚动的，滚动过程中
> 新老配置文件会共存——**新增的配置项在老模板里根本不存在，那一刻代码里的默认值就是实际
> 生效值。** 要是默认写成 0.1，灰度开始那一刻所有还没拿到新模板的机器会立刻开始丢九成

## 4. 对照物判定及理由

**判定：出行为对照表，不出界面 mock。**

理由（在第 1 轮事实汇报里明写给用户了）：

- 这次改的是现有可观察行为的今昔差异 —— 落盘条数、转发条数、`/metrics` 数值口径与新增行、
  HTTP 响应体在采样场景下的取值。按 skill 的分类这属于「改变现有可观察行为或兼容性」，出对照表。
- 不存在用户可见界面：`src/index.mjs` 只有 `POST /v1/events`、`GET /metrics`、`GET /healthz`
  三个端点，仓库里没有任何前端资产（`find` 出来的 26 个文件里没有 html/css/前端框架）。所以
  界面 mock 一栏为空，不出 html，契约目录里只有契约本身一个文件。

对照表的执行细节：17 行变化场景 + 10 条不变清单，用具体数据写（沿用 `test/fixtures/event-batch.json`
的 `u-1` / `u-2` 和 `event-valid.json` 的 `u-10293` / `s-88f21`，不写抽象规则），边界值单独成行
（空串 `user_id`、两个 id 都缺、`byApp` 配 `0`、无 `sample` 节的老模板机器）。迭代 2 版后用户
