# Goal Contract: 满减规则调整为满 200 减 30 并叠加会员先减后折 95 折

- Status: Ready
- Target: shop-pricing（src/pricing.mjs）
- Updated: 2026-08-07

## Goal

购物车结算的优惠规则由「满 300 减 40」调整为「满 200 减 30」，会员订单在满减之后再享 95 折（先减后折，四舍五入到分），未满 200 元的订单应付金额与现行完全一致。

## Why

- 现行满 300 减 40 门槛过高，大量 200 多元的订单不凑单直接流失，转化率明显下降。
- 门槛降至 200 并叠加会员 95 折后，流失区间的订单可直接享受优惠，挽回该区间转化。

## Read First

- docs/testing.md（测试约定：价格改动必须补边界值断言，金额一律精确断言）
- README.md（现行规则描述，需随本次调整同步更新）

## Scope

- In: 调整 src/pricing.mjs 满减规则为满 200 减 30、新增会员先减后折 95 折逻辑、按新规则更新并补充测试断言、同步 README 中的规则描述。
- Out: 不新增其它优惠类型或多档满减，不改动购物车合计（数量乘单价求和）逻辑，不涉及任何界面、存储或外部系统改动。

## Success Criteria

- AC-01: 合计满 200 元的非会员订单应付金额为合计减 30 元，现行满 300 减 40 规则同时废止；示例：合计 200 应付 170，合计 250 应付 220，合计 300 应付 270。
  - Verify: [A] `npm test` → 退出码 0，含上述金额的精确断言
- AC-02: 边界：恰好 200 元的订单也算满减，合计等于 200 时非会员应付 170 元。
  - Verify: [A] `npm test` → 退出码 0，含合计恰好等于 200 的边界断言
- AC-03: 会员叠加顺序为先减后折：合计满 200 元的会员订单应付金额为（合计减 30）再乘 0.95，结果四舍五入到分；示例：合计 200 应付（200 − 30）× 0.95 = 161.5，合计 300 应付（300 − 30）× 0.95 = 256.5。
  - Verify: [A] `npm test` → 退出码 0，含会员先减后折的精确断言
- AC-04: 未满 200 元的订单（无论会员与否）应付金额与现行一分不变；示例：合计 199 应付 199，会员同价。
  - Verify: [A] `npm test` → 退出码 0，含未满 200 会员与非会员的边界断言
- AC-05: 测试套件整体更新到新规则：旧规则断言全部改写，价格改动按 docs/testing.md 补齐边界值精确断言。
  - Verify: [A] `npm test` → 退出码 0，无跳过或失败用例

## Constraints

- 未满 200 元的订单价格一分不能变，会员 95 折不得作用于未触发满减的订单。
- 商品数量乘单价的合计逻辑保持不变。
- 除满 200 减 30 与会员先减后折 95 折外，不引入任何其它新优惠。
- 金额断言遵循 docs/testing.md：一律精确断言，不做范围判断。
