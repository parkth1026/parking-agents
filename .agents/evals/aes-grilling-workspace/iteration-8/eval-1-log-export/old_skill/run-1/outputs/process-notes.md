## 第 1 步：查了哪些事实

### 请求牵涉的代码事实（全部来自 `workdir/export_logs.py`，47 行）

- 完全没有命令行参数解析：无 `argparse`，无 `sys.argv` 读取。**推论很关键**：现在传任何参数都不会报错，而是被静默忽略、照样全量导出。这条事实直接决定了第 3 步对照表里「现在的行为」那一整列（12 行里有 11 行的现状都是「参数被静默忽略」），也决定了 AC-002 的后果陈述（「参数打错却静默导全量」是今天就存在的坑，不是新引入的风险）。
- 输入：`glob(logs/*.log)` 按文件名排序，路径基准是 `os.path.dirname(os.path.abspath(__file__))`（脚本所在目录，与当前工作目录无关）。这条事实是第 2 轮问题 9（`--output` 相对路径按哪个基准解析）能问到点子上的前提。
- 解析：`^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})\s+(DEBUG|INFO|WARN|ERROR)\s+(.*)$`，不匹配即 `continue`，不计数、不告警、不影响退出码。
- 输出：写死 `脚本所在目录/export.csv`，`encoding="utf-8"`、`newline=""`，总是覆盖；表头写死三列 `timestamp,level,message`。
- 输出信道现状：stdout 恰有一行 `exported N rows -> 路径`；**stderr 完全没有输出**；退出码恒 0。这条决定了「跳过统计走 stderr」是一条干净的新通道，且能写成「0 行时 stderr 为空」这种可判定的边界。
- `workdir/logs/app.log` 精确内容：6 行，可解析 5 行（07-30 两行、07-31 两行、08-01 一行）+ 1 行 `garbage line that does not match the format`。**跨 3 天 + 恰好 1 行脏数据**，这两个性质让对照表的每一行都能写成具体行数（3 行 / 4 行 / 2 行 / 0 行 / skipped 1），不必写抽象规则，也让第 4 步不必再向用户索取数据。

## 第 3 步：判定出不出对照物，以及理由

**判定：出行为对照表，不出 mock HTML。**

- 不出 mock：本次改动的对象是命令行脚本，没有任何用户可见的图形界面，也没有设计稿。给一个 CLI 画 HTML 界面稿是假动作，产出物没人能拿它质疑什么。这一点在给用户的第 1 轮原文里明确说了，并附带留了个口子：「如果你其实还想看 `--help` 的文案长什么样，说一声」——把「CLI 的界面就是 `--help` 文本」这个可能的解释交给用户，而不是替他决定。
- 出对照表：请求改变了既有可观察行为，而且是三类都碰到了——输入面（新增参数，且现状是静默忽略）、输出面（写到哪、写多少行、stdout / stderr）、状态流转（退出码 0 vs 非零）。这正是「改变现有可观察行为或兼容性」的定义。
- 这个判定读得出来，不需要问用户：仓库里没有任何界面代码或设计稿，是 `Fact` 而不是 `User decision`。

对照表最终 12 行，其中 6 行标了「边界行」（同日闭区间、空结果、from 晚于 to、格式错、父目录不存在、跳过 0 行），并附 9 条不变清单。用户第 1 版即确认，无修改行；他主动点出「不变清单第 1、2、3 条是我最在意的」——这正是不变清单的价值所在（确认「不变的是他依赖的」）。

对照表没有单独成文件，整张写进契约「访谈记录」一节（符合 shape 的规定：只有界面 mock 才另存 html）。因此本次 `outputs/` 下没有 mock 文件，属预期。

## 遇到的困难

1. **「跳过行统计」差点被当成表面需求接下来。** 用户只说「打到 stderr」，但 B / C / D 三个选项（知道丢了多少 / 知道丢了什么 / 一行都不许丢）通向三种不同实现。如果不把这一层挖出来，就会照字面实现一行统计，而万一他真正想要的是回查脏行内容，做完才发现不够。判据用的就是「两个选项是否落到同一个实现」。
2. **AC 与强约束的分筐反复权衡。** 「零参数必须完全等价」「CSV 表头不变」「UTF-8 不变」在用户嘴里是最强烈的要求，直觉上想立成 AC。按 shape 的自查（「把它去掉，会放过哪一种具体的错误交付」）它们确实属于「不许变什么」，方向与 AC 相反，全部归入强约束（9 条不变清单一条都没进 AC）。但「默认路径不变」有一半是可观察的正向结果（`--output` 与默认路径的落点判定），所以把这一半以 AC-003 的形式留在验收里，剩下的不变量部分留在强约束。这是本次最难切的一刀。
3. **Verify `[A]` 需要写命令，而仓库里没有任何命令可写。** 契约不该预写猜测性命令，但 `[A]` 档必须给命令。处理办法：把「建 pytest 基建」显式写进 `范围 · 做什么` 和 `要落盘的东西`（D-01 / D-02），让 `-k range` / `-k invalid` / `-k output` / `-k skipped` 这四个选择器成为本契约定义的约定，而不是对既有仓库的猜测；同时在第 4 轮向用户报清这条路径的 0.5 人日代价，由他裁决。
4. **不能替用户发明「代表性数据」。** `[B]` 档一直摆在候选里（不是选了才追问），并明确写出「合成数据说明不了真实日志的脏行形态（多行栈、非 UTF-8 字节、超长行）」，把「你的真实日志里有没有这些」交给用户。他答「没有，编码一直是 UTF-8」，所以四条 AC 全走 `[A]`，`要落盘的东西` 里也不需要黄金用例 fixture。
5. **校验器的占位符规则需要绕开。** 校验器会把 `<字母...>` 形态当模板占位符直接拒，所以契约正文里所有「路径」「数字」占位一律用中文词或反引号包住的具体值（例如 `exported N rows -> 路径`），不使用尖括号。最终校验一次通过，无 WARNING、无 ERROR，`AC_COUNT: 4`，退出码 0。
