**Q1. 「老板报告」的格式基准是什么？（核心歧义：仓库里没有样例，"一致"无从判定）**

- 证据：workdir 仅含 README、summarize.mjs（透传）、bill-2026-07.csv，无任何报告样例。
- 选项：
  - A. 你直接给出那份报告的样式（列名、列顺序、是否有合计行/占比列、金额格式），按它逐项对齐。【推荐】
  - B. 没有现成样式，按常见格式：`分类,金额`（两位小数），按金额降序，末行合计。
  - C. Markdown 表格形式输出。
- 代价：选 A 需要你提供具体样式，否则「格式一致」这条验收标准写不出来；选 B/C 存在与老板实际看到的版本对不上的风险，可能返工。

**Q2. 输出到哪里？**

- 选项：
  - A. 打印到 stdout（保持现有 CLI 用法，复制/重定向都方便）。【推荐】

  - C. 两者都要。
- 代价：B/C 需要额外约定输出文件命名规则。

**Q3. 复用范围：只处理 2026-07，还是通用？**

- 证据：README 说每月都会从银行 App 导出 CSV 到 `data/`。

  - A. 通用：CSV 路径作命令行参数，任何同列结构的月度文件都能汇总。【推荐】

- 代价：A 需要约定遇到缺列/坏行时的行为（建议：报错退出并指出行号）；B 下月又要改代码。

**Q4. 数值口径与排版细节？**

- 选项：
  - A. 金额保留两位小数，含合计行；排序与是否加占比列以 Q1 的基准为准（无基准则金额降序、不加占比）。【推荐】

- 代价：口径不写死，执行 Agent 只能猜，验收时容易在格式上打回。
