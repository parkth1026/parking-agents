# 设计：笔记按分类统计 + 近 7 天新增统计

## 要解决什么

用户攒了几百条笔记，想知道精力分布在哪些分类、最近是否还在活跃地记。
需要一个统计入口（网页为主、CLI 为辅），两边数字口径一致。

## 关键决策

### D-1 统计逻辑放在哪一层

| 方案 | 怎么做 | 代价 | 为什么没选 |
| --- | --- | --- | --- |
| A 各自实现 | 网页和 CLI 各写一份统计计算 | 实现简单，但两处逻辑分叉后容易出现「网页 3 条、命令行 4 条」这种矛盾，且强约束明确要求共用 | 违反强约束（两边数字必须一致、不允许两套口径），排除 |
| B（选定）共用一份统计函数 | 新增一个统计计算模块，`src/cli.mjs` 的 `stats` 分支和 `src/web/server.mjs` 的统计页/接口都调用它 | 需要新增一个模块并被两处引用，改动面比 A 略大，但一次改对两处都对，符合强约束 | 无 |
| 什么都不做 | 保持现状，不提供统计 | 不解决用户的原始诉求 | 用户明确要这个功能，排除 |

选定 B。理由：CLI 与网页数字必须一致是访谈里定下的强约束，唯一能保证这一点的方式
是让两个入口调用同一份计算逻辑，而不是分别实现后靠人工同步。
落进任务的形态：`强约束` 写「网页统计页与 CLI `notes stats` 必须共用同一份统计计算
逻辑，不允许两套口径分别实现」。

具体这份逻辑放在哪个文件、函数签名怎么设计、「近 7 天」的参照时刻怎么注入以便
测试可重复，都是局部、可逆、不改变外部契约的实现选择，留给执行 Agent 自行决定，
不在此处预写。

## 影响面

- 不删除、不修改任何现有文件的现有行为：`src/cli.mjs` 的 `add`/`list`、
  `src/web/server.mjs` 的 `/api/notes` 与只读列表页、`src/store.mjs` 的 `loadNotes`
  均保持原样，新增统计逻辑复用 `loadNotes` 读取数据，不改它的返回形态。
- 新增内容：CLI 新增一个命令分支（`stats`），网页新增一个页面/路由，新增一份
  统计计算逻辑，测试新增覆盖 stats 逻辑的断言与两份 fixture。

## 边界与失败

- 顺利时：`data/notes.jsonl` 有笔记数据，统计页和 CLI 输出的分类计数、
  近 7 天新增数字彼此一致，且与数据实际内容吻合。
- `data/notes.jsonl` 为空或不存在时：这是 `loadNotes` 已有的读取路径，
  统计逻辑应当能拿到空列表并展示「暂无数据」这类状态，而不是抛未捕获异常；
  具体空态文案不在验收范围内，属于执行 Agent 的自由发挥，只要不报错即可，
  不写入 AC 是因为原始请求没有对空态提出可判定的期待。
- `category` 为空字符串或缺失：按访谈定下的规则归并进「未分类」，见 AC-004。
- 统计计算中断后重跑：统计是无副作用的读取 + 计算，重跑就是重新算一遍，
  不存在需要恢复的中间状态。
