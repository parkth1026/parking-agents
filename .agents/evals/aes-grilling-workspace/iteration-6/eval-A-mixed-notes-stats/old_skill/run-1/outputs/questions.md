## 第 1 步：调查事实（不占提问轮次）

Agent 直接调查仓库，未询问用户，结论写入上下文：

- `README.md`：notes-tool 是 CLI（`add`/`list`）+ 只读网页，数据存 `data/notes.jsonl`。
- `src/store.mjs`：`loadNotes()` 读取并 parse `data/notes.jsonl`，每条笔记含 `category`、
  `text`、`created`（ISO 时间戳）。
- `src/cli.mjs`：仅有 `add`、`list` 两个子命令，无统计相关代码。
- `src/web/server.mjs` + `src/web/public/index.html`：网页只有一个只读列表页，
  `GET /api/notes` 返回全部笔记 JSON，无统计接口、无路由分发（唯一页面）。
- `docs/testing.md` + `package.json`：验证基建 = `npm test`（`node test/run-tests.mjs`，
  退出码 0 为过）；网页改动约定人工用 `npm run web` 看，仓库明确没有截图对比/视觉回归工具。
- `test/run-tests.mjs`：现有测试直接对真实 `data/notes.jsonl` 断言条数与字段完整性，
  不是隔离的单元测试框架，但可以在同一脚本里追加断言。
- 未发现 CI 配置文件（无 `.github/workflows` 等）。
- 对照物分类判定（Fact，按 SKILL.md 第 1 步规则得出，不占轮次）：网页统计页是新增用户
  可见界面 → 需要界面 mock；CLI `stats` 是纯新增命令，不改变 `add`/`list` 现有可观察行为，
  没有「今昔差异」可对照 → 不需要行为对照表。整体判定为「界面向」，跳过行为对照表。

## 第 2 步：批量问清歧义（第 1 轮，也是唯一一轮）

Agent 先给出推荐候选（按 SKILL.md 要求，提问前先亮候选）：

> **候选 Goal**：用户可以在网页统计页看到每个分类的笔记数量和「近 7 天新增」总数，CLI
> 也能看到同样的简版文本，两边数字一致。
> **候选 In**：按分类计数、近 7 天新增计数、网页统计页、CLI `stats` 命令。
> **候选 Out**：标签统计、导出文件、图表库、历史趋势图。
> **候选 AC 方向**：分类计数准确性、近 7 天计数准确性、网页展示、CLI 展示、两端一致性、
> 不破坏现有行为。

随后一次性抛出以下 3 个独立歧义（未使用 `AskUserQuestion` 结构化工具，因为本次以文本
方式模拟访谈；改用编号文本一次列全，问题数 ≤ 4，符合退化规则）：

**Q1. 统计结果的展示入口**
- 已知证据：现有网页只有一个只读列表页；CLI 只有 `add`/`list`。
- 选项：
  a) 只做网页统计页
  b) 只做 CLI 简版文本
  c)（推荐）网页统计页为主 + CLI 也出一份简版文本，两边数字必须一致
  d) 其他
- 真实代价：c 比 a/b 多一份实现和一致性校验，但两个使用场景（临时终端里瞄一眼 / 网页
  仔细看）都能覆盖。

> **用户回答（按画像）**：网页为主，做一个统计页；CLI 也顺手出一份简版文本（比如
> `notes stats` 命令），两边数字必须一致。→ 选 c。

**Q2. 「最近一周新增」的时间窗口口径**
- 已知证据：`created` 是 ISO 时间戳，精确到毫秒；仓库里没有「自然周」相关的既有约定。
- 选项：
  a)（推荐）滚动 7×24 小时：以当前时刻为终点，往前推 7 天
  b) 自然周：本周一 0 点到现在
  c) 用户自定义天数
- 真实代价：a 实现简单、语义direct（「最近一周」= 过去 7 天），b 需要处理时区/周起始日
  的额外约定，c 需要额外一个可配置项（画像明确说不需要额外配置）。

> **用户回答（按画像）**：画像未覆盖这个细节 → 选推荐项 a（滚动 7×24 小时）。

**Q3. 统计维度边界确认**
- 已知证据：请求原文只提到「按分类」和「最近一周新增」，没提标签、导出、图表。
- 选项：
  a)（推荐）只做分类计数 + 近 7 天新增总数，不做标签统计、不做导出、不引入图表库
  b) 额外加标签统计
  c) 额外加导出文件功能
- 真实代价：b/c 都会扩大 Scope、增加实现和验证成本，且请求原文没有提出这类需求。

> **用户回答（按画像）**：不做的：不需要按标签统计、不需要导出文件、不需要引入任何
> 图表库。→ 明确选 a，且是显式排除而非沉默接受推荐项。

### 本轮后的维度自评（SKILL.md 第 2 步「什么时候停」）

- Intent：已定——重度笔记用户想知道精力分布在哪些分类、近期投入了多少。
- Outcome：已定——网页统计页 + CLI `stats`，分类计数与近 7 天新增数，两端一致。
- Boundary：已定——In/Out 均已写明（不做标签/导出/图表库）。
- Constraints：已定——不引入图表库、CLI 与网页必须同口径。
- Context：已定——仓库现状（数据结构、现有页面、现有测试基建）已查清。

两条停止判据同时成立：五个维度都不在「未定」；且收口审计通过——继续追问只会改变
措辞，不会改变执行。→ 结束提问，进入第 3 步。未出现需要追加第二轮的新增歧义。
