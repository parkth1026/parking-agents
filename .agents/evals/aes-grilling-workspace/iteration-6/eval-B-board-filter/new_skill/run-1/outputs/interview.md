# 访谈：团队看板支持按负责人筛选任务

## 查到的事实

- 前端是原生 HTML/CSS/JS，无框架、无路由库、无 URL 参数处理代码。`public/app.js` 只是把 `/api/tasks` 的结果逐条渲染成 `<li class="card">`，卡片文案固定格式 `${task.title} — ${task.assignee}`。（`public/app.js:1-11`）
- 看板结构是三个按 `data-status` 分组的 `<section>`（todo/doing/done），顶部只有一个 `<header class="topbar">`，目前只放标题，没有任何控件。（`public/index.html:9-14`）
- 任务数据当前写死在后端 `src/server.mjs` 的 `TASKS` 数组里，`assignee` 是纯字符串，当前只有三个取值：`ayan`（2 条）、`bo`（1 条）、`chen`（1 条），没有空 assignee 的情况。`/api/tasks` 原样返回整份数组，不接受任何查询参数。（`src/server.mjs:5-10, 14-19`）
- 测试基建：`npm test` 跑 `test/run-tests.mjs`，用 Node 内置 `node:assert` 写断言，退出码 0 为过；`docs/testing.md` 明确写着页面改动目前只能本地 `npm start` 后人工在浏览器验证，仓库没有截图对比或视觉回归工具。`package.json` 里也没有装任何浏览器自动化测试依赖（如 Playwright/Puppeteer/jsdom）。（`docs/testing.md:3-4`，`package.json`）
- 判定对照物类型：本次请求是在现有看板上新增一处用户可见的筛选控件，属于「新增或改动用户可见界面」→ 出界面 mock；默认（不筛选）状态下的现有行为不发生变化，不存在「今昔行为差异」需要对照，因此不出行为对照表，只出 mock。

## 对照物迭代

判定：本次落在「新增或改动用户可见界面」，出 mock；不改变任何既有可观察行为（未筛选时现状不变），不出行为对照表。

- v1（草稿，未落盘，暂存于临时目录）：筛选下拉框放在标题右侧、紧挨标题；没有"清除筛选"按钮；筛选结果为 0 条时对应列直接留空白，没有任何文案。展示给用户后，得到三条意见：
  1. 筛选控件应该放顶部工具栏右侧，不要挨着标题；
  2. 要有一个"清除筛选"按钮，一键回到全部任务；
  3. 筛选后一张卡片都没有时，要显示空态文案"没有匹配的任务"。
- v2（确认版，`mock.html`）：把筛选控件连同新增的"清除筛选"按钮一起挪到 `.topbar` 最右侧（`justify-content: space-between` 使标题在左、控件组在右）；新增"清除筛选"按钮，仅在有筛选时可见；三列渲染逻辑改为筛选结果为空时插入 `<p class="empty-state">没有匹配的任务</p>` 而不是留空 `<ul>`；另外在 mock 页面下方加了一段静态的"空态示例"区块，方便不用手改地址栏也能直接看到空态长什么样。用户看过 v2 后确认通过，未再提新意见。

不变清单（mock 里同步保留、未改动的部分）：

- 顶部标题文案与位置（"团队看板"仍在左侧）；
- 三列布局（待办/进行中/已完成）与列内卡片的堆叠方式；
- 卡片文案格式 `${title} — ${assignee}`，不新增头像、不改字体；
- 未筛选（初始进入或清除筛选后）时的默认展示：与当前线上行为一致，显示全部任务。

视觉细节（颜色、字体）用户明确不要求与 mock 逐像素还原，只要求结构和交互按确认版来。此约定已写入 `work-item.md` 的 AC-001 Verify 说明（"不要求像素级还原，只要求结构与选项一致"），未额外写入「强约束」，因为它是验收判定口径而不是不可变的现有行为。
