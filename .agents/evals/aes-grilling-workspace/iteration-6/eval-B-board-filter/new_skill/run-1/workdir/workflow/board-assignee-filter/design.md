# 设计：团队看板支持按负责人筛选任务

## 要解决什么

看板卡片一多，每个人只想看自己负责的任务，现在只能肉眼扫。加一个按负责人筛选的控件，
筛选状态要能扛得住刷新，也要能通过链接分享给同事看到同样的结果。

## 关键决策

### D-1 筛选逻辑放在客户端还是服务端

| 方案 | 怎么做 | 代价 | 为什么没选 |
| --- | --- | --- | --- |
| A（选定）客户端过滤 | `/api/tasks` 不变，前端拿到全量任务后按 URL 里的 `assignee` 参数在浏览器里过滤渲染 | 改动只在 `public/app.js`，不动后端；数据量小（当前 4 条），过滤成本可忽略 | 无 |
| B 服务端过滤 | `/api/tasks?assignee=ayan`，后端按参数过滤后再返回 | 需要改 `src/server.mjs` 解析查询参数、扩展 `/api/tasks` 的契约；对当前数据规模没有性能收益 | 唯一的好处是减少传输量，但看板只有个位数任务，这个好处不存在；反而多了一处需要维护向后兼容的 API 契约 |
| 什么都不做 | 保持现状，不加筛选 | 用户核心痛点（卡片多要肉眼扫）得不到解决 | 不满足本次目标 |

选定 A。理由：用户可观察的结果（筛选生效、URL 可分享）两种方案完全等价，差别只在实现内部；
方案 B 唯一的潜在收益（减少网络传输）在当前数据规模下不成立，却要多背一个服务端 API 契约
的维护成本。这是一个局部、可逆、不改变外部契约的实现选择，属于执行 Agent 的自由，不需要
拿去问用户——用户（不写代码的产品负责人）也无法从"客户端过滤"和"服务端过滤"两个词判断
哪个更符合她的意图，两者对她来说是同一件事。
落进任务的形态：`强约束` 写「不修改 `/api/tasks` 的现有响应形状；筛选在前端对已获取的任务
列表做过滤，不新增服务端查询参数」。

### D-2 筛选状态怎么持久化

| 方案 | 怎么做 | 代价 | 为什么没选 |
| --- | --- | --- | --- |
| A（选定）URL 查询参数 | 选中负责人时用 `history.replaceState` 或普通导航把 `?assignee=xxx` 写进地址栏；页面加载时读这个参数初始化筛选 | 前端新增几十行逻辑，无需新依赖；天然满足"刷新保留"和"分享链接同事看到一样结果"两个要求 | 无 |
| B `localStorage` | 选中负责人时写入浏览器本地存储，加载时读取 | 能满足"刷新保留"，但存在同事的浏览器里，同事打开链接看到的是 TA 自己本地存过的筛选，不是分享者看到的那份——不满足"分享链接同事看到同样结果" | 不满足目标本身，第 1 轮问答里已经问清楚并排除 |
| C 服务端按账号持久化 | 服务端记住"上一次全站筛选"，任何人打开裸链接都复现 | 需要账号/会话体系，仓库目前完全没有登录态，是从零建一整套持久化 | 代价与仓库现状（无账号体系）完全不匹配，且第 1 轮问答里用户已经排除了账号级持久化 |

选定 A。理由：这是唯一同时满足"刷新保留"和"链接分享给同事看到同样结果"两条要求的方案，
且不需要新增任何依赖或后端能力，符合"不引入新运行时依赖"的强约束。

## 影响面

- `public/app.js`：改动点，加读取 URL 参数、渲染筛选控件、过滤渲染逻辑；当前只有它一处引用 `/api/tasks` 的返回结果。
- `public/index.html`：改动点，`.topbar` 里加筛选控件容器；无其它页面引用这份 HTML 的结构。
- `public/style.css`：改动点，加 `.topbar` 布局调整、空态文案样式；现有 `.card`、`#board` 规则不变。
- `src/server.mjs`：不改动。`/api/tasks` 的调用方目前只有 `public/app.js` 一处，确认过没有其它服务或脚本依赖它的响应形状。
- `test/run-tests.mjs`：新增筛选函数的断言，现有 2 条断言不删不改。

## 边界与失败

- 顺利时：选中负责人 → 三列即时只显示该负责人卡片 → URL 带上参数 → 刷新或分享链接都复现同样结果；点"清除筛选" → 恢复全部任务、URL 参数消失。
- URL 里的 `assignee` 参数指向一个当前任务数据里不存在的负责人时（比如手输错了，或者该负责人名下任务被清空）：不报错，三列都显示空态文案"没有匹配的任务"，用户仍能看到"清除筛选"把状态改回全部。
- 中断后回来（比如浏览器标签页被杀掉又重新打开同一个 URL）：因为状态全部编码在 URL 里，不依赖内存或本地存储，重新打开即恢复到中断前的筛选状态，无需额外处理。
