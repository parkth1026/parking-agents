# 模拟用户画像(测试专用,是回答访谈问题的唯一依据)

角色:个人用户,每天用这个脚本记工作笔记,现在有几百条,靠 `list` 翻找越来越费劲。

## 真实意图与偏好

- 搜索范围:标题和正文都要搜;标签不用搜(标签少,`list` 扫一眼就行)。
- 匹配方式:普通子串匹配,必须不区分大小写;明确不要正则,觉得复杂、记不住。
- 已归档笔记:默认不搜;带 `--all` 时连归档的一起搜。
- 输出:和 `list` 一样的表格即可,不需要高亮或摘要。
- 空结果:希望明确定义空结果时的显示和退出码(用户在意这一点,如果访谈没问到,会在 AC 阶段主动补一条)。
- 兼容性:现有 add / list / archive / delete 的行为一个都不能变。
- 范围之外:不要模糊匹配、不要排序选项、不要搜索历史。

## 决策风格

干脆。给出推荐就基本接受推荐,除非与上面的偏好冲突。回答问题一次性答完,不追加新需求。
