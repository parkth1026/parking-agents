# 问清楚要做什么，以及怎么算做完

一个任务只锁两个点：要做什么，以及怎么算做完。中间怎么实现，交给执行 Agent 自己
发挥。这两个点定偏了，中间做得再好也是错的，所以全程用提问达成。

本技能是编排器：它决定下一步进哪个阶段、卡住时退回哪里，**自己不产出任何文件**。
每个阶段的产物长什么样，写在产出它的那个子技能里。

## 三个阶段

| 阶段 | 技能 | 锁什么 |
| --- | --- | --- |
| `1-interview` | `aes-interview` | 锁需求：查清事实，批量问清歧义 |
| `2-prototype` | `aes-prototype` | 锁对照物：扫影响面，出用户能逐处质疑的具体物 |
| `3-contract` | `aes-goal-contract` | 锁验收：对齐验收条件，落盘契约，校验交接 |

提问方法论三个阶段共用，在 [asking.md](references/asking.md)。

## issue 目录

所有过程产物与最终契约都落在同一个 issue 目录下，一个入口看全貌：

```bash
node <skill-dir>/scripts/session.mjs init <date>-<任务词组>
```

它幂等：目录已存在就读出当前阶段供续跑，不覆盖任何内容。返回 issue 目录绝对路径，
后续所有命令都以它为参数。

`manifest.json` 是这个目录的状态与入口。**它只由 `session.mjs` 写**，任何技能、任何
subagent 都不许用 Edit/Write 直接改它。

## 怎么流转

1. 从用户请求派生 slug，跑 `init`，拿到 issue 目录与当前阶段。
2. 续跑时读 `manifest.json` 的 `stage` 与 `next_action`，从那里接上，不从头再来。
3. 进入该阶段的子技能，告诉它三件事：issue 目录绝对路径、当前阶段、上游产物的路径。
4. 子技能收尾时会写回阶段状态。读一次 manifest，决定下一步。

### 每个阶段必须交出什么

只看存在性与结构，不看质量——质量由产出它的子技能负责。结构由
`session.mjs stage ... done` 当场强制校验，缺节、缺文件、不合 schema 都报不出 done：

- `aes-interview` 交出 `1-interview/context.md` 与 `1-interview/rounds.jsonl`，
  且五个自评维度没有一个停在「未定」。
- `aes-prototype` 交出 `2-prototype/impact-surface.md`，以及它据此判定需要的那几份
  确认版对照物。没有可观察差异是一种结论，不是一种跳过。
- `aes-goal-contract` 交出 `3-contract/contract.md`，且 `finalize` 退出码为 0。它一条命令
  跑完结构校验、`[A]` 档冒烟和交接可执行性闸门，只看这一个码，不逐项复核。

### 门禁

前一阶段的状态不是 `done` 或 `skipped` 时，不得进入下一阶段。手上没有产物就往下走，
后面每一步都是在猜。

`done` 不是自报的：`session.mjs` 收到 done 时跑该阶段的结构闸门，不过就拒收；
`skipped` 只有 2-prototype 能用（差异极小且用户文字确认过），必须带 `--reason`
且七面扫描已落盘，`finalize` 拿 reason 跟契约「残留风险」对账——访谈和契约没有
「跳过」，走不下去用 `needs_reinterview` 打回。闸门挡结构不挡质量——问得好不好、
对照物像不像，仍由自评与用户确认负责。

### 回退

子技能报 `needs_reinterview` 时，它同时会给出待澄清项。重新进入 `aes-interview` 把
这些问清楚，再从中断处继续往下。**不要让子技能就地把歧义糊过去**——对照物阶段撞出
新歧义是它的价值所在，不是它的失败。

回退不是倒退：重新提出的问题会带着「是哪份草稿撞出来的」一起落盘。

## 终态报告

三阶段走完后报告：契约路径、目标一句话、范围、验收条件条数、校验结果，以及精确
阻塞项或可复制的启动指令。启动指令由 `aes-goal-contract` 现场生成。有阻塞项时不
启动实现。

同时交出决策档案：`finalize` 通过后跑
`node <skill-dir>/scripts/export-dossier.mjs --issue-dir <issue>`，把导出路径和
`dossier_digest` 一并报告。档案由任务原文、全部轮次、候选优劣势与契约重投影而成，
离线可读——它和契约同级，是访谈的交付物，不是 Web 载体的附属品：纯对话访谈一样
产出，与 `$workflow-interview-web` 共用同一投影实现。

`finalize` 列出的非 `[A]` 档验收条件要一并报给用户，点名是哪几条。它们在长时程执行
里没有任何东西能反驳「我做完了」，用户得知道交接之后哪部分要自己看。这不是阻塞项，
是交接面的一部分——不说，用户会以为整份契约都能自动判定。

跨 issue 的全局视图不落盘，要看时现扫：

```bash
node <skill-dir>/scripts/session.mjs list
```

## 简单不是跳过访谈的理由

多简单的需求都留下这份契约、访谈记录和设计取舍，设计取舍可以只有五句话。简单
需求带着没验证的假设开工，返工代价和复杂需求一样。

| 听到这句 | 怎么回 |
| --- | --- |
| 需求我说清楚了，别再问了 | 那就不问了，我把你说的写成记录，你看一眼对不对 |
| 你问得太啰嗦了，像走仪式 | 有把握的我直接定，列成一行一条你扫一遍；只有真两难的才占你一个问题 |
| 方案我定了，不用列备选 | 记下你定的那个，另一栏写「为什么没选别的」，一句话就够 |
| 上一轮已经分析过了 | 上一轮在聊天记录里，下一个人看不到。落成文件 |
| 就这么点事，直接排计划 | 计划的每一步都要指回设计里的某条决定，没有设计计划无处生根 |
| 验收标准你看着定就行 | 定偏了要执行完才发现。你只要答「什么情况下你会说这没做对」 |

用户说「别问了直接干」时照办，但把因此没问的东西记成一句残留风险落盘：当场用
`session.mjs stage ... --residual-risk "<一句>"` 记进 manifest，`aes-goal-contract`
到时候会把它写进契约，`finalize` 会对账。只说给用户听不落盘，交接的时候就没了。

本技能不实现任务里的目标。
