# 最佳实践调研（Best-Practice Research）

回答"当前外部最佳实践是什么"：只读、有边界、官方/上游证据优先，产出带引用与置信档位的结论后移交并停止。本技能是调研 wrapper：只路由证据收集与综合，不是新的研究权威，也不替代专职选型决策。

## 默认终态：只读

默认只读终态。收集证据，产出带引用的建议与交接说明，然后停止。不写文件、不改配置、不跑有副作用的命令——即使问题有明确的实现含义。需要实现时停在「交接」节，等用户显式切换到规划或执行工作流再继续。

## 何时激活 / 不要激活

- 激活：用户要最佳实践、推荐做法、官方口径、标准、版本敏感的上游行为；或某工作流在规划/执行前需要当前外部证据。
- 不要激活：答案纯在仓库内（走只读代码检索）；主要问题是选型/升级/替换/对比（移交依赖选型决策）；只差按既定需求实现（走执行工作流）；稳定本地约定即可回答、无需外部查证。

## 证据路由

1. **本地先行**：本地用法、约束、版本、配置、集成点会影响答案时，先用只读检索查清仓库现状。
2. **外部证据**：当前性或版本敏感性影响正确性时，收集官方/上游文档、release notes、changelog、标准原文。
3. **选型分界**：问题变成"要不要采用/替换/升级/对比依赖"时移交依赖选型决策，不在此裁决。
4. 带显式的证据、不确定性与交接约束回到调用方。

## 来源质量规则（细则见 [references/source-quality.md](references/source-quality.md)）

- **官方阶梯**：官方文档 / 上游源码 / release notes / 标准 > maintainer 指南 > 三方摘要（仅作补充，不先于官方）。
- **fetch-not-snippet**：material claim 必须来自实际打开过的页面；搜索摘要不得作为唯一证据。
- **就近引用**：material claim 的来源 URL 紧跟结论标注，不只堆在文末。
- **registry 口径**：包发布日期以 registry 的 time 字段为准（如 npm `time`）；GitHub Release `published_at` 仅作参考（可能是重新发布动作）。
- **时效（AS_OF）**：研究类来源 >3 年、快讯类 >6 个月 → 置信降一档并标注核对日期。
- **收敛门**：写进「直接建议」的关键结论需 ≥2 个独立域名支撑；达不到就显式标「单一来源，未收敛」。
- **置信三档**：高 = 官方或多源印证；中 = 单一可靠来源；低 = 未核实 / 过期 / 仅社区声量。
- **逐字摘录**：关键 API 签名、默认值、官方原句逐字引用并给 URL；禁止凭记忆重构。
- **最小证据集**：取能支撑决策的最小证据量；不因广度本身多抓。

## 工作流

1. 分类问题：概念最佳实践 / 实现指引 / 迁移与版本 / 标准合规 / 本地+外部混合。
2. 本地事实：本地用法或约束影响答案时，先只读检索（棕地事实）。
3. 外部证据：按来源质量规则收集；material claim 打开原文核对。
4. 综合：按输出契约给建议、证据、置信档位、冲突与缺口、交接。
5. 证据足以支撑调用方即停；不足以收敛时，报告确切缺口与所需移交，不继续磨措辞。

**停止预算**：同一子问题最多 3 次检索仍无官方来源 → 停止检索，声明不确定性并按现有证据收敛。

## 输出契约（完整模板与示例见 [references/report-template.md](references/report-template.md)）

报告用用户提问的语言书写。节结构：

```md
## 最佳实践调研：<问题>

### 直接建议
<结论 + 置信档位（高/中/低）；单一来源须标「未收敛」>

### 证据使用
<官方/上游来源与补充来源分列；material claim 就近标 [来源](URL)>

### 版本 / 日期上下文
<版本、日期、发布渠道、AS_OF 核对日期>

### 冲突与缺口
<矛盾证据并陈；过时来源点名标记；用户假设的流行来源若已过时，标为过时证据；查不到的如实写>

### 仓库本地上下文
<本地检索事实，无则写「不需要」>

### 边界 / 非目标
<本次调研不裁决什么>

### 交接
<移交给规划或执行工作流的含义；本技能到此为止>
```

## 停止规则

- 建议已可复用且有出处 → 停。
- 问题升级为选型对比、大架构或实现 → 上交。
- 剩余工作只是打磨措辞、不会改变建议 → 停。
- 本技能永不实现：交付建议与交接后即停，不改仓库状态。仅在用户显式切换到交接中点名的工作流后才继续。

## 引用真实性（scripts/verify-refs.mjs）

交付前可对报告跑 `node scripts/verify-refs.mjs <报告路径>` 核对全部 URL 可达性：`unreachable` 的引用按幻觉处理——补出处或删除，二选一。脚本只读网络，不改仓库。bot 拦截（403/429）判 `ambiguous`，人工复核，不算失败。

## 交接

交付后移交：规划类交给规划工作流，实现类交给执行工作流。本技能到交付为止；除非用户显式切换工作流，否则不继续执行移交后的内容。
