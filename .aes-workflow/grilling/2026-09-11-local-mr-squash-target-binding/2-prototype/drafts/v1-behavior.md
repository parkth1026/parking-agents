## 变化行

| # | 输入 / 前置 | 现在的行为（初铸版） | 改后的行为 |
| --- | --- | --- | --- |
| 1 | 点名调用，「把 X 合到 dev」但当前检出在源分支/别处 | prose 隐含「检出在目标」，agent 可能不切或方向跑反 | 第 1 步显式硬前置：当前检出即目标、源≠当前检出、全程在目标检出执行，不在就先切 |
| 2 | 双 worktree：源分支被附属 worktree 检出，收口 | prose 推荐「彼处 `git merge <target>`」→ 产生 merge commit，源 tip≠HEAD 恒成立，门禁第 4 项**永远红**（2026-09-11 实测） | 彼处 `git reset --hard <target>`：源引用前滚到 HEAD，门禁全绿（实测唯一常规全绿路径）；彼处树净是硬前置（脏则不 reset、停下问） |
| 3 | 在源 worktree 里跑门禁（「帮我看看合完没」） | 四项同义反复全绿（合并前实测 exit 0 假绿） | 用法错拒绝：exit 1 + 「当前检出就是源分支——门禁必须在目标分支的检出上运行」，不输出四项检查 |
| 4 | 第 4 项 FAIL 提示文案 | 「在其 worktree 里 git merge（树净且 tip 未前进）」 | 「在其 worktree 里 git reset --hard <target>（彼处树净且 tip 未前进）」；删除路径注明「源被 worktree 检出时先拆该 worktree」 |
| 5 | 正文措辞 | 「合入主干」 | 「合入目标分支（dev/main 等长命分支）」 |

## 边界值行

| # | 输入 / 前置 | 行为 |
| --- | --- | --- |
| B1 | squash 后源分支又前进步 | 门禁第 3 项变红——漂移被机械捕获（不变） |
| B2 | 彼处 worktree 树脏 | 不执行 reset --hard（会丢未提交改动），停下问 |
| B3 | 源分支已推送到远端 | 移动引用（branch -f / reset --hard 均同）与远端分叉、再推即改写已推送历史——撞永不红线，prose 要求停下问 |
| B4 | detached HEAD 上跑门禁 | 当前分支名为 HEAD ≠ source，四项照常（行为不变） |
| B5 | 门禁 FAIL 但想先报告 | 不许称完成；--keep 只跳第 4 项且必须显形（不变） |
