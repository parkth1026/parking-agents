1. 调用方式

在 VS Code Copilot Chat 中输入：

/rust-workflow-init

可选参数：项目路径（默认为当前工作区根目录）

/rust-workflow-init D:\projects\my-rust-app

Skill 会自动读取目标项目的 Cargo.toml，提取项目名称、workspace 成员和 edition 版本，然后生成所有配置文件。

3. 每个文件详解

1 CLAUDE.md Claude Code

作用：Claude Code / Claude CLI 在每次会话启动时自动读取此文件，作为项目上下文。告诉 AI 构建命令、代码规范和测试规则。

动态内容（从 Cargo.toml 读取）

  • 标题使用 [package].name 或项目目录名
  • 构建命令中的 <crate> 替换为实际 crate 名
  • Workspace 项目会列出所有成员 crate 及简要说明

核心规则

  • #[expect()] 代替 #[allow()] — 来自 Ruff AGENTS.md，让 lint 抑制在规则移除后自动报错
  • 禁止 unwrap()/panic!() — 来自 uv AGENTS.md，生产代码必须优雅处理错误
  • cargo nextest run 代替 cargo test — 来自 Deno CLAUDE.md，并行测试更快
  • 测试命名 test_<function>_<scenario>_<expected> — 业界共识，可读性优先
2 AGENTS.md GitHub Copilot

作用：GitHub Copilot Agent（VS Code 中的 Agent 模式）在会话中读取此文件。与 CLAUDE.md 相同的规则集，但使用英文——遵循 GitHub 生态的惯例。

与 CLAUDE.md 的区别

维度CLAUDE.mdAGENTS.md
读取者Claude Code / Claude CLIGitHub Copilot Agent
语言中文英文
格式惯例自由格式GitHub 约定格式
核心规则相同
3 .vscode/settings.json 深度合并

合并策略：读取已有文件 → 深度合并（已有值优先） → 写回。不会覆盖用户已有设置。

配置项详解

键值为什么
rust-analyzer.check.command "clippy" 保存时运行 clippy 而非 check，提前发现 lint 问题
rust-analyzer.cargo.targetDir true RA 使用独立 target 目录，避免与 CLI cargo build 互相 invalidate 缓存。实测可带来 ~13× 增量编译加速
rust-analyzer.check.extraArgs ["--all-targets"] 检查所有 target（含 tests/benches），不漏检
editor.formatOnSave true 保存自动 rustfmt，保证代码风格一致
4 rustfmt.toml

作用：配置 rustfmt 格式化行为。

edition = "2021"          # 自动匹配项目 Cargo.toml 中的 edition
max_width = 100           # 行宽上限
use_field_init_shorthand = true  # Point { x, y } 而非 Point { x: x, y: y }
use_try_shorthand = true         # expr? 而非 try!(expr)

edition 字段会根据 Cargo.toml 中的实际 edition 自动设置（2021 或 2024）。

5 Cargo.toml workspace lints 合并

合并策略：读取已有 [workspace.lints.clippy]（或 [lints.clippy]），仅添加缺失的键，不覆盖已有值。

配置的 lint 规则

Lint级别含义
pedanticwarn (priority -1)启用 pedantic lint 组，但优先级低于具体规则
unwrap_usedwarn禁止 .unwrap()，强制显式错误处理
expect_usedwarn提醒审查 .expect() 调用
panicwarn禁止生产代码中的 panic!()

Workspace 项目：各 crate 的 Cargo.toml 添加 [lints] workspace = true 继承根配置。

6 .githooks/pre-commit

三步门禁：每次 git commit 前自动运行。

  1. cargo fmt --all -- --check — 格式检查（不通过则拒绝提交）
  2. cargo clippy --workspace --all-targets -- -D warnings — Lint 检查
  3. cargo nextest run --workspace — 全量测试

跨平台：使用 #!/bin/sh 兼容 Unix 和 Git Bash（Windows）。Windows 上跳过 chmod。

配置方式：git config core.hooksPath .githooks（团队级，可提交到仓库）。

7 bacon.toml 可选

作用：配置 bacon 文件监视器，保存文件时自动运行 check/clippy/test。

定义三个 job：check（默认）、clippy、test。仅在用户明确需要时创建。

4. 前置条件

必须

  • Rust toolchain — rustup + cargo
  • rustfmt 组件 — Skill 会自动检查，缺失时运行 rustup component add rustfmt
  • cargo-nextest — Skill 会自动检查，缺失时运行 cargo install cargo-nextest --locked
  • Git — 用于配置 pre-commit hook

可选

  • bacon — 文件监视器 (cargo install bacon)
  • VS Code + rust-analyzer 扩展

5. 执行流程

1
检查环境 — 确认 Cargo.toml 存在；检查 cargo-nextest、rustfmt 是否安装，缺失则自动安装
2
读取项目信息 — 解析 Cargo.toml：项目名称、edition、workspace members
3
扫描已有配置 — 检查 CLAUDE.md、AGENTS.md、settings.json、rustfmt.toml 是否已存在
4
创建/合并文件 — 生成 CLAUDE.md + AGENTS.md（填入实际 crate 名），深度合并 settings.json 和 Cargo.toml lints
5
配置 Git — 创建 .githooks/pre-commit，运行 git config core.hooksPath .githooks
6
报告 — 列出所有创建/修改的文件及每个文件的核心作用

6. 规则来源

本 Skill 的规则提炼自三个顶级 Rust 开源项目的 AI coding 指南：

项目文件主要贡献规则链接
Deno CLAUDE.md cargo nextest、单 crate 测试命令格式、测试命名规范 GitHub
Ruff AGENTS.md #[expect()] 代替 #[allow()]、避免缩写变量名、最窄可见性 GitHub
uv AGENTS.md 禁止 unwrap/panic、Result + ? 错误处理、clippy pedantic GitHub

设计理念：这些项目是目前 Rust 生态中对 AI 辅助开发支持最成熟的项目。它们的规则经过大规模代码库的实战验证，覆盖了从编码规范到测试策略的完整链路。本 Skill 将这些最佳实践打包为一键初始化，让任何 Rust 项目都能立即获得同等水平的 AI 编码指南。
