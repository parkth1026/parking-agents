# ADR-0003：story 收口四条件硬门禁

- 日期：2026-08-29
- 状态：已接受（2026-08-29 用户裁决）
- 关联：parkth1026/parking-agents#147（map）、#153（裁决票，本 ADR 主决议源）、#155（回退分层与 finalize 挂点）；调研底座 #150、#151
- 筛选判据自评：三条全中——收口语义是验收链的根基，宣布过的 story 做完无法事后收紧；「为什么对话里说信得过不算数、为什么 automated 不许自报」是无上下文时的惊讶点；人核成本、漂移重判成本 vs 可判定的业务终态是真实权衡。

## Context

- interview 家族已有「一条 [A] 都没有 = 完成判定全靠自陈 = 没有终止条件，要停一下」的洞察，但其人工面只「报给用户」，没有回写面（#151 报告：aes 有而 WI 没有的是人工面回写协议）。
- aes-workflow 给了可借鉴的协议：人工核对三态 `[ ]`/`[x]`/`[!]` + 两阶段放行矩阵，原文「人核对通过只有一个来源：文件里的那个 [x]」；以及指针漂移模型——「任务还在飞的时候上游一改下游就漂，那是干活的常态……要收口了才必须全部对上，finish-check 在那一刻一次查干净」（#151 报告引 protocol.md:295）。
- board 侧对账点已现成但粒度错位：v3 三维 verdict 是 Task 级、v4 acceptance 是 job 级、Goal Contract 是 story 级——story 级收口需要 story 级锚点，最自然挂点是「acceptance 全绿 + contractDigest 未变」（#150 报告 §3 M3+M4）；contractDigest 已实现「AC 内容变更使旧证据失效」。

## Decision

**story 做完的判定 = 四条件硬门禁，全过才宣布，门禁由新技能执行（#153 决议③）：**

1. **全票 close**：story map 名下执行票全部到达终态。
2. **acceptance 全绿**：automated 档须有证据支撑、**不自报**——board 仓须 board runtime/GATE 证据；无 board 仓（含 GitLab）退为执行票关票评论挂「可复现命令 + 退出码 + 产物指针」（CONTEXT.md「可辩护」判据），收口脚本核验（2026-08-29 裁决分级，spec ⑤.2）。
3. **contractDigest 未变**：story 契约承载 digest（#155）；变了 → 指针漂移对账（在飞不爆红、收口一次重判），收口重判。
4. **非 [A] 档全 [x]**：story 契约文件中非 [A] 档（live/manual）AC 在收口前必须由人勾选 `[x]`，**唯一勾选落点 = story 契约文件**（contractDigest 锚定物本体，2026-08-29 裁决，spec ⑤.3）——**勾选是「人核对通过」的唯一来源**，用户在对话里说信得过不是勾，agent 也不能替他勾；未勾全则门禁拒收（#153 决议②，采纳 #151 人工面回写协议）。

配套：票 close 快照（dossier 随票投影，#156）是条件 ③ 对账的固定参照物；回退分层（票内问清 → story 级 withdraw + `Reopens:` 新票 → 执行中指针漂移）保证门禁严格而不僵化（#155 决议）；四条件全过 = ready、用户确认 = handed_off（独立状态对，不进门禁；2026-08-29 裁决，spec ⑤.6）。

## Consequences

- 正：「story done」有了与人核对闭合的可判定语义，业务终态不自陈；automated 证据锚在 board registry 事实（非推断）上；漂移不在执行期爆红，长链条多票不会被上游变更反复打断；人工面从「报给用户」升级为可回写、可对账。
- 负：收口成本真实存在——非 [A] 档必须等人勾，未勾全即拒收（收口会被人的节奏卡住）；无 board 仓的 automated 证据退为关票评论证据块，防线从 registry 事实移到评论核验 + 审计时间线（2026-08-29 裁决分级，spec ⑤.2）；digest 变更触发整段重判可能返工。
- 难逆转性：四条件一旦作为收口语义发布，弱化任何一条都会立即产生「过去宣布做完的 story 按新标准不成立」的追溯问题；本 ADR 约束 #159 spec ⑤ 节。
