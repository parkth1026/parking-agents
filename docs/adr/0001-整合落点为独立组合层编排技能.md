# ADR-0001：整合落点为独立组合层编排技能（workflow-story-map）

- 日期：2026-08-29
- 状态：已接受（2026-08-29 用户裁决）
- 关联：parkth1026/parking-agents#147（map）、#152（裁决票）、#157（命名与发布）；调研底座 #148/#149/#150/#151
- 筛选判据自评（难逆转 / 无上下文会惊讶 / 真实权衡）：三条全中——落点决定整个技能的架构定位与维护档结构；「为什么不升级 interview 家族、为什么不动 wayfinder」是无上下文时最自然的疑问；新增一档维护 map 是真实成本。

## Context

map #147 要求把 interview 家族（grilling 方法论、三阶段门禁、Goal Contract、决策档案）、wayfinder（分布式拆单、临时知识库、fog-frontier-claim）、aes-worktree-board（星图、三维 verdict）与 aes-workflow engineering 的路由门禁思想整合成 story 级全链条工作流，且**落点不预设**——升级 interview 家族 / 独立新技能 / 强化 wayfinder 三个候选由图上 grilling 票裁决（#147 已定边界③）。

四份调研的关键事实：

- interview 家族的 charter 锁两点、不实现任务目标；上下文爆炸的根因是「唤醒绑定」把阶段内全部轮次钉进单一会话谱系，而拆解层缺失使 story 级任务只有「塞进单 issue（上下文爆）」或「人工拆票（失去 grilling 与全局掌控）」两个坏选项（#148 报告 2.3/2.4）。
- wayfinder 双变体分歧不在语义在执行者（tracker 平台 + agent 自律 vs 本地工具 + 机器闸门），协议语义（map/票/fog/frontier/claim）两版一致且可整体继承（#149 报告）。
- board 的星图数据面、三维 verdict、GATE-acceptance 对 Goal Contract 的对账点已现成（#150 报告）。
- 本仓唯一「不产出文件、只做编排」的先例是 workflow-interview（SKILL.md:11-12）。

## Decision

**落点＝独立新编排技能（组合层），命名 `workflow-story-map`，category=engineering（#157）。**

- 新技能只拥有「story → 拆解 → 派发 → 收口对账」的路由与门禁，自己是编排器、不产出业务文件。
- GitHub Issues 为拆解层真源（map/票/fog/frontier 语法继承 wayfinder）；interview 家族**被组合**为每票/每 story 的契约真源（10 组能力零搬运）；board **被组合**为执行层；Goal Contract + contractDigest 做规划侧 × 执行侧的桥。
- 拆解输出与 Goal Contract 同型，A4–A7 验收链免改造复用。
- **wayfinder 本体＝并存分工**：探索性规划（路线未知、纯决策）继续用 `$wayfinder`，story 级交付用新工作流；两工具共享同一套 map/票语法，星图同渲、语法同源不分裂。
- 否决①升级 interview 家族：家族 charter「锁两点、不实现任务目标」要撑破，本地目录与 GitHub 票两真源域难缝合。否决③强化 wayfinder：fork 上游脱离本仓真源体系、planning-only charter 要反转。

## Consequences

- 正：grilling 高效性零损失（家族原样被调用）；上下文爆炸根治靠切割谱系而非压缩上下文；board/家族零改造被组合；wayfinder 不动，探索与交付两条路径并存且同源。
- 负：维护成本 +1（新技能一档维护 map，#100–#109 序列新增不改既有）；组合层的路由叙事要靠 description 分层单向链原则防膨胀（#157 决议④）；实现期需顺带修复 workflow-interview 零信息 description 债。
- 难逆转性：票、门禁、档案全部挂在新技能名下后迁移代价极高；本 ADR 是其余三条 ADR（0002–0004）的前置。
