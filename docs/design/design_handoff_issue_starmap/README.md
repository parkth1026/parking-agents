# Handoff: AES 需求星图（Issue 知识图谱 · Obsidian 式星空图）

## Overview

一个面向"AI 工程系统（多 worker 自动开发）"场景的 Issue 知识图谱界面。项目的 issue 及其依赖关系以 Obsidian 关联图 / 星空图的形式呈现在一整张画布上。

两个核心产品诉求（一切设计决策都服务于它们）：

1. **Issue 状态与 issue 间的依赖关系必须一眼看清** —— 状态用颜色和形态编码，依赖用连线编码；
2. **每个 worker 走到哪里了必须随时可知** —— worker 是画布上"常显"的信标（beacon），永远不会被淡出到不可辨认，另有右上角 Workers 停靠面板兜底。

## About the Design Files

本包中的 HTML 文件是**用 HTML 制作的设计参考稿**（prototype），展示目标外观与行为，**不是可直接搬运的生产代码**。任务是：在目标代码库的既有技术栈（React / Vue / Svelte / 原生等）中，用其既有模式和库**重新实现**该设计；若尚无既有环境，请选择最合适的框架实现。

- `需求星图 7a.dc.html` — 主设计稿（含 demoHover 开关可预览悬停态）。文件内 `class Component` 的 `renderVals()` 中包含全部节点/边的示例数据、半径公式、颜色逻辑，可直接作为实现参考。
- `support.js` — 设计稿的运行时，仅供本地打开预览用，与实现无关。

**High-fidelity（高保真）**。颜色、字体、字号、留白、圆角、阴影均为最终值，请按像素还原（数据为示例数据）。

## 节点状态规格（核心）

**星等 = 依赖连接数**：节点半径由度数（无向边数）决定。

```
r(可开工 frontier) = 8 + 1.4 × degree
r(进行中 claimed)  = 9 + 1.4 × degree
r(被阻塞 blocked)  = 5 + 1.1 × degree
r(已完成 resolved) = 3.5 + 0.8 × degree
背景小星（无 issue 语义的已完成远景）r = 1.6 ~ 3.5
```

| 状态                         | 视觉                                      | 精确值                                                                                                                                                       |
| ---------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 可开工 (frontier)            | 橙色实心圆 + 双层光晕                     | 填充 `#C15F3C`；内环 r+4.5 描边 `rgba(193,95,60,0.35)` 1.1px；外晕 r+10 填充 `rgba(193,95,60,0.07)`                                                          |
| 进行中 (claimed)             | 紫色实心圆 + 三层信标光环 + worker 名牌旗 | 填充 `#7C6BAE`；环 r+4.5 `rgba(124,107,174,0.45)`、r+9 `rgba(124,107,174,0.20)`、外晕 r+15 填充 `rgba(124,107,174,0.06)`。实现时外环应做 2s 缓慢呼吸脉冲动画 |
| 被阻塞 (blocked)             | 空心虚线圆                                | 填充同底色 `#FAF9F5`，描边 `#A39C8D` 1.4px，dasharray `3 3`                                                                                                  |
| 已完成 (resolved)            | 小实心暗点                                | 填充 `#B7AF9F`，不透明度 ×0.95；仅显示 `#id` 小标签                                                                                                          |
| 背景星                       | 更小更淡的点                              | 填充 `#DAD4C5`                                                                                                                                               |
| ⚠ 回归警示（完成后又出问题） | 已完成点外加琥珀虚线环                    | 环 r+4 描边 `#B08838` 1.1px dasharray `2 3`，副标「⚠ 回归有波动」10px `#B08838`                                                                              |

### 节点标签（重点节点常显）

- 可开工/进行中/被阻塞：常显。id (IBM Plex Mono 11.5px；橙 `#A94F2F` / 紫 `#6A5A9E` / 灰 `#8D867A`) + 标题 (12px `#6B675C`，可开工加粗 500)。位置：节点正下方 `y + r + 6`，水平居中。
- 已完成：仅 `#id`，10.5px mono `#B0A897`。
- 背景星：无标签。

### Worker 名牌旗（信标，核心需求 2）

钉在 worker 所在节点正上方（`y - r - 6`，翻转向上），名牌下有 1×9px 垂线连到节点。**任何淡出/过滤状态下永不完全消失**（最低不透明度 0.5）。

- 运行中：白字 `#FFFFFF`，紫底 `#7C6BAE`，边框 `#6A5A9E`，文案如 `dev5 ▶ 2h14m`（11px mono 600）
- 等待人工确认：深琥珀字 `#8A6A1F`，米黄底 `#F6EDD8`，边框 `#D9C48F`，文案如 `dev1 ✋ 等待确认`
- 阴影 `0 2px 8px rgba(31,30,27,0.10)`，圆角 6，padding 4×9

## 边（依赖关系）规格

边为**轻微弯曲的二次贝塞尔曲线**（控制点在中点垂直偏移 `±0.09 × 边长`，相邻边交替方向），永远绘制在节点下层。

| 类型                         | 样式                                 |
| ---------------------------- | ------------------------------------ |
| 普通依赖边                   | `#DFD8C7`，1.1px，实线，不透明度 0.9 |
| 指向被阻塞节点的边（阻塞链） | `#CE9A83`，1.15px，虚线 `5 4`        |
| 背景星连线                   | `#E7E1D2`，1px，不透明度 0.55        |

## Interactions & Behavior

1. **悬停高亮邻居**（设计稿 `demoHover` 开关演示了 #45 的悬停态）：
   - 悬停节点及其一跳邻居保持不透明度 1；相关边加粗至 1.4px 并加深（普通边 `#B9AF97`，阻塞边 `#C15F3C`）；
   - 其余节点/标签淡至 0.15，其余边淡至 0.1，背景星淡至 0.3；
   - **例外：进行中节点（有 worker）最低只淡至 0.5**，名牌旗保持不透明度 1；
   - 过渡 150ms ease-out；鼠标移出后恢复。
2. **点击节点 → 右侧详情面板**：白卡 340px 宽，right:22/top:22，圆角 12，阴影 `0 8px 28px rgba(31,30,27,0.10)`。内容：id + 状态胶囊、标题（Source Serif 4 19px 600）、键值行（状态/分支/来路，键 52px 宽 `#9A948E`）、「完成后解锁」灰底块（`#F5F3EB`，内含虚线边框 chip 列出将解锁的 issue）、两个按钮（主按钮橙底 `#C15F3C` 白字「查看运行日志」，次按钮描边「打开 PR」）。点击空白处或 × 关闭。
3. **滚轮缩放 / 拖拽平移**：缩放范围建议 25%–400%，以鼠标位置为中心；右下控件同步显示百分比；平移用画布拖拽。缩放到 <60% 时可隐藏"已完成"节点的标签降噪。
4. **按状态过滤高亮**：图例行可点击，激活后该状态节点保持不透明度 1，其余淡出（同悬停淡出值）；worker 名牌旗仍常显。再点取消。
5. **搜索定位**：匹配 issue id / 标题 / worker 名；选中结果后画布平滑飞行（pan+zoom，~450ms ease-in-out）至该节点并短暂高亮（描边闪烁 2 次）。
6. **Workers 面板 ⌖ 按钮**：点击后同"搜索定位"飞行至该 worker 所在节点。
7. **布局为静态力导向**：用力导向算法（如 d3-force：link + manyBody + collide）计算一次，收敛后**冻结**，不做持续物理晃动。数据更新时增量重算并用 ~600ms 过渡动画移动节点。

## State Management

```
graph:      { nodes: [{id, title, status: 'frontier'|'claimed'|'blocked'|'resolved', warn?, worker?}], edges: [[a,b]] }
workers:    [{name, state: 'running'|'awaiting_confirm'|'idle', issueId?, elapsed?}]
hoveredId:  string | null
selectedId: string | null        // 驱动详情面板
filter:     status | null        // 图例点击
transform:  {x, y, k}            // 画布缩放平移
query:      string               // 搜索
```

数据来源：定期拉取 issue 列表与 worker 状态（设计稿顶部曾有「↻ Issues / ↻ 状态」的同步概念）；worker 的 elapsed 需前端计时刷新。
