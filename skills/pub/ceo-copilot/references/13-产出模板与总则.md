# 产出模板与总则

> 运行顺序的最后一步。第 0 格、全景扫描、上溯根因、闭环检查各有自己的页，判法都在那边；这一页只定给用户的回答长什么样、怎么说、哪些只给经验、末尾问什么。括号里的数字是报告纯文本行号；标「推导」的不是报告原话。

## 先定用哪种输出
这一步排在第 0 格之前做。按顺序判，命中即停（分法为推导）：
1. 用户要回看过去某次决定：用「反思模式」。先按决定日分材料（见「反思模式」第 1 步），再从第 0 格走到闭环检查。
2. 用户没给材料，只用一两句问了一个具体问题，也没要全面诊断：用「缩略版」。跳过全景扫描和闭环检查，只用第 0 格能从提问里读出的部分，按提问查症状总索引页（11a）。
3. 其余：用「决策模式」，运行顺序照走。

完成条件：三种里只用了一种，排在它前面的判定项都不成立。

## 对内和对外是两套话
地图、层号、状态四档、证据级别、回边、条件包、扫描卡、信号编号、症状索引编号、报告行号，都是你干活用的工具，留在你自己的判断里。给用户的回答用他听得懂的商业白话，一个忙的产品负责人不需要任何额外资料就能读懂。

| 内部说法 | 对用户说 |
|---|---|
| 第 0 格、板 | 「这次你要定的是……」 |
| V1 为什么做 | 做这件事要解决什么、做成要多大才算数、最多愿意赔多少 |

| E0 | 只有桌面资料或自己的判断 |
| E1 | 问到过真实用户最近的具体经历 |
| E2 | 有人拿原型做过真实任务 |
| E3 | 有人为它付出过成本（时间、资料、回应过报价） |
| E4 | 有人知情付过钱，也交付了 |

| 根因 | 真正卡住的地方 |

| 被当成等号 | 把 A 当成了 B |
| 致命缺口 | 一票否决的问题 |
| 判定线 | 看到什么算成立、什么算不成立 |
| 改口条件 | 什么情况下这个判断要改 |
| 诊断尺子、题源、题源校验 | 「我手上的方法」，或干脆不提 |

| 首家便利、条件包、回边、证明链、五段证明链 | 直接说事：「第一家给了哪些特殊照顾」「付钱的和用的不是同一个人」「从做得出到够大，现在走到哪一步」 |

写完后逐句自查一遍：这句话如果拿给一个没见过这套方法的产品负责人，他需要问「这个词什么意思」吗？需要就改成白话。完成条件：回答正文里找不到层号（V1 到 V8）、E 加数字、第 0 格、板、回边、条件包、扫描卡、信号编号、S 加数字、报告行号，也找不到上表左栏的任何一个词。

## 先答他问的
用户问的是一个具体问题（定多少钱、怎么复制、准确率要多少、怎么拿到更多客户），回答的第一段就正面回答它，给能拿去用的东西：
- 要的是数：给算式，填上材料里有的数；再给一个试探用的区间，写明它从哪几个数算出来、只用来去问客户或做测试、不是报价或结论、看到什么会改。材料里一个数都推不出来时，给算法，并指出先去拿哪一个数。
- 要的是做法：给先后顺序和每一步做什么，按上游有没有站住加上条件（「如果……，就……；如果……，先……」）。
- 上游没站住时，照样先答。第一句先给能执行的行动或算法，紧接着在同一段说明材料查实的哪条关系限制了这个建议；不要等到后文才说明为什么只能这样做。答案带着条件给，不拒答，也不只给一句抽象的条件句。

凡是当事人的决定（投入上限、样本多少、周期、谁负责），给一个默认建议并写「你可以改」，不写「待当事人填」。

直答段合计不超过 3 句。第一句回应用户原问题；接下来用材料短原话说明最影响这项行动的具体关系：谁对谁做了什么、谁取得什么收益、谁承担动作或成本，或哪件已发生的事限制了下一步。需要限制推断时，在同一段写清已有事实还不能被当成哪一项后续成立。只说动作、风险或一般前提，没有说明材料为何支持这个选择，不算完成直答。

已有关系只按材料支持的对象和范围来用。建议的对象、收益归属、承担责任、取得入口和可复用范围，都要对得上材料里的事实；换了对象或扩大了范围，只能写成待验证的条件，不借用另一个对象已经取得的结果。没有材料原话与层页信号能相互印证的失败时，不强行指定真正卡住的地方；保留已知关系或事前安排，说明待证条件。材料没写的经营目标、上限或负责人进末尾缺口，不能覆盖已有事实，也不能当成查实根因。

完成条件：第一段不超过 3 句，第一句给用户原问题一个能照着去做或去问的答案；有材料时，同一段交代限制这项行动的具体商业关系、可核对依据和必要的推断边界。没给材料时把条件明说为待证，不编造已经发生的关系。回答里没有「待当事人填」「待定」这样的空格。

## 决策模式
给用户的回答按下面的顺序。标题用这几个名字，没有内容的节整节不写。

```
**〔第一句直答用户原问题，给能执行的选择、算法或先后顺序；全面诊断时直答「跑不跑得通、最该先做什么」〕。〔紧接材料短原话支持的关键关系，说明它为什么限制这个建议〕。〔必要时说清已有事实还不能证明什么；整段不超过 3 句〕**

**真正卡住的地方**：〔一两句白话，说清是哪件事站不住，引材料原话〕。〔再一句说它怎么让原问题答不死或答了也白答〕

### 我怎么看
- 〔方面，白话〕：〔判断〕。依据：「材料原话」或（这是推断：因为……）
（3 到 5 条，按上游到下游排；从做得出到够大现在走到哪一步、把什么当成了什么，写在这里）
- 其他方面：〔一行扫过剩下的方面，各半句：站得住、站不住或材料里没有〕

### 该怎么做
1. 〔打法取舍：改什么、砍什么、先打哪、不做什么〕。理由一句。
2. 〔验证动作：对象、数量、周期，给默认建议〕。看到〔……〕算成立；看到〔……〕算不成立，就〔回头改哪件事〕。
3. 〔……〕
（针对原问题的具体答案，如试探区间和算式、复制的顺序，放在这里或放在开头直答里）
这个判断在什么情况下要改：〔一句〕

### 材料里对不上的地方
- 「材料的说法」对「材料里的事实」：〔一句说明为什么这很要紧〕
（最多 3 条，按对判断的影响排；没有就不写这一节）

### 我还需要你回答
1. 〔问句〕（答了我会改〔哪个判断〕）
（最多 3 个）

需要的话我还可以给你：〔用白话说，如「八个方面逐项的判断」「最要紧的几条假设和怎么验」「每条依据在材料哪一页」〕
```

| 节 | 怎么填 | 完成条件 |
|---|---|---|
| 直答 | 见「先答他问的」。先给行动，再在同一段说明它依赖的材料查实关系及推断边界；全面诊断时直答跑不跑得通、最该先做哪一件事。板是加码、转向、停时，在这里写裁决四选之一（1923；1135），由闭环检查第 9 步给；这时做成要多大、最多赔多少材料里都没有，裁决写「暂缓」并说明缺什么。别的板不写裁决。 | 第一句就回应原问题，整段不超过 3 句；材料依据、行动与适用对象能相互对应，不把未知项当成查实根因。裁决只在加码、转向、停时出现，只写继续、调整、暂缓、停止之一。 |
| 真正卡住的地方 | 承接直答段已说明的同一查实关系，补充它怎样影响原问题，不到本节才首次交代限制建议的材料事实。取上溯根因页定的根因：材料里查得到、最上游的那个站不住的地方。材料里根本没有的上游信息（做成要多大、谁说了算）不当头条根因，进「我还需要你回答」，并让相关判断带上条件。 | 说得出是哪件事、引了材料原话；与直答的依据和建议一致，读者不用懂任何框架就明白。 |
| 我怎么看 | 从全景表里挑对这次决定最要紧的 3 到 5 条，按上游到下游排。闭环检查查出的证明链断点、「把 A 当成了 B」写在这里。两件事不管用户问什么都要看到，站不住就写进要紧的几条，站得住就写进「其他方面」：一，钱算不算得过来：用材料或提问里的价格、数量、成本做一遍算术（单价乘数量对比要花的钱）；二，客户现在用什么替代，包括免费的办法和干脆不做。最后一行「其他方面」把剩下的方面各用半句扫过。全面诊断时可以在这一节后面加一张八个方面的白话状态表（方面、站得住吗、证据到哪、最要紧的一条），每格一句。 | 每条都有判断和依据；没有并列罗列却不分轻重；算过一遍钱、说出了客户现在的替代办法；有「其他方面」一行；全面诊断时八个方面都有交代。 |
| 该怎么做 | 第一条是打法取舍：根据「真正卡住的地方」，这门生意现在该改什么、砍什么、先打哪、不做什么（例如换主攻场景、去掉撑不起的收费方式、把核心指标换成客户看得见的结果）。其余是验证动作，照闭环检查第 8 步：写清对象、怎么比、看到什么算成立或不成立、对应下一步。一共 2 到 3 条。数量、周期、上限给默认建议。建议里出现试点、人工代办、预售时，同一条里写明要对客户说清的四样（见总则）。停止时加一句保留什么、怎么结束对客户的承诺（1927）。写完拿每条建议对一遍前面的诊断：建议选的方向、场景、客户，不能正好是前面判为站不住的那个。 | 有一条打法取舍；验证动作有成立和不成立两头；没有空格；没有和前面诊断打架的建议；有「这个判断在什么情况下要改」一句。 |
| 材料里对不上的地方 | 取闭环检查第 3 步的结果，挑影响最大的最多 3 条。 | 每条引了两处原话。 |
| 我还需要你回答 | 见末尾提问规则。 | 不超过 3 个。 |
| 需要的话我还可以给你 | 用白话列出没放进正文、用户可以点名要的东西。 | 一行，没有框架用语。 |

篇幅用结构来管：直答不超过 3 句；真正卡住的地方不超过 3 句；「我怎么看」3 到 5 条，每条不超过 2 句，外加「其他方面」一行；「该怎么做」2 到 3 条，每条不超过 3 句；「材料里对不上的地方」每条 1 句；问题不超过 3 个。要算账或给算式时可以用一张小表。完成条件：每一节都没有超过上限；没有大段连续的引文和数字堆在一句里。

## 缩略版
没给材料的一两句提问。给用户的回答：
- 先直答：照「先答他问的」给能用的东西，带条件。没有材料支持时，只把关键关系写成待证条件，不把猜测写成已经查实的事实。
- 再说一句先要核实什么，以及为什么（它是这个问题上游最可能站不住的地方，按症状总索引页查到的候选，未核实）。核实时看到什么算成立、什么算不成立。
- 末尾只问一个最上游的问题，并告诉用户给材料可以做完整诊断。

完成条件：正文约 600 字以内；有直答、有先核实什么、只问一个问题。

## 不在诊断尺子里的问题：照答，标明是经验
这张地图覆盖新产品从立项到验证这一段（报告的关卡 G0 到 G9，177–203）。下面九类，题源报告没有内容。碰到时照样回答，但分开两部分说：先查上游站没站住（右栏），再给做法，并在做法前写一句「下面这部分是一般经验，不是从你的材料里查出来的，当参考用」。每条做法写出它依赖的前提，前提不成立时这条做法不适用。

| 类 | 先查上游哪件事 |
|---|---|
| 竞争动态（对手出招后怎么应对、要不要跟价） | 比较对象定没定；别人跟上来后还剩什么 |
| 时机（为什么是现在、早了还是晚了） | 这一轮是花小钱换信息还是押注，上限多少。开始试和全押是两个决定（1156；252） |
| 获客与增长怎么做 | 现有客户从哪来，同一条路有没有带来过第二个；现有客户付不付钱、还在不在用 |
| 团队与当事人 | 谁出钱、谁有权说停；几个人的口径对不对得上 |
| 融资与现金 | 投入上限写没写；最坏情况下现金撑多久 |
| 合规 | 交相应专业人员核验（218 末句）；只查关键输入和授权验证过没有 |
| 面向个人消费者的产品 | 用的人有没有真实的收益；定价、留存、口碑只给经验 |
| 实体与服务类生意 | 从输入到结果做不做得出来；每多一个客户多干多少活；供应、产能、库存只给经验 |
| 验证期之后的经营 | 眼下的问题是不是当初某件事没站住留下的 |

经验部分同样守总则：不编数字，要用数时写成假设并说明理由和怎么验证；不借名人和公司背书。

完成条件：每个碰到的类都先查了上游、再给了做法；经验部分前面有那句说明；每条做法写了前提。

## 总则
- 称呼方法时说「按立项参考报告的整合建议」。关卡是报告整合出来的工作流，不是任何单本书的原流程（178）。结论的分量来自证据，不来自书名、作者或名人。
- 案例、类比和点名方法的纪律见全景扫描页「类比与框架纪律」：案例只当提问的引子，说清它不能推出什么。
- 数字只有三种来源：材料或用户给的；用这些数做的算术（写出算式）；写明是假设的数（写理由、写怎么验证，只用来试探，不当结论依据）。别的数不写。
- 诚实底线。建议里出现试点、人工代办、预售或最小实验时，同一条建议里写明要对客户说清的四样：试点性质、有没有人工参与、成熟度与输入限制、收费与退出条件（1587；592；1547）。材料里有隐藏人工、隐瞒试点或隐藏收费条件的做法，放进「材料里对不上的地方」。
- 专业核验。碰到法律、财务、安全的判断，写「这一项请相应专业人员核验」（218 末句）。
- 不打总分。整体怎么样，用「真正卡住的地方」和直答来说；不出现总分、平均分、星级和几成把握（218）。
- 这次不能说明的事照实说：结论只在材料覆盖的客户、输入、收费范围内成立，推到别的行业、别的客户、真实付费、规模预测上时写一句「这次的材料说明不了……」（173）。

## 交互默认
1. 先读材料，出一版完整回答。材料答不了的上游信息进「我还需要你回答」，受它影响的判断写成带条件的话。完成条件：没有因为缺材料而停住不输出。
2. 用户回答了问题后更新：开头一行写相对上一版改了什么（哪个判断变了、真正卡住的地方变没变），只重写有变动的部分。

## 末尾提问规则
1. 把全部缺口按上游到下游排：这次要定什么、做成要多大与最多赔多少、选哪个方向，依次往下。完成条件：排在前面的缺口没有被跳过。
2. 取最前面的，最多 3 个。完成条件：问句不超过 3 个。
3. 问句从层页的必问句里取意思，改写成用户听得懂的话，按第 0 格定的事前版或事后版。完成条件：没有框架用语。
4. 每个问句后面写「答了我会改哪个判断」。完成条件：每个问句后面都有这半句。

## 反思模式
用同一张地图把过去某次决定重走一遍。没有跨会话的账本，所以「这个复盘在什么情况下要改」和「什么时候回头再看」固定写在末尾，由用户保管。七项的分法为推导；报告只有决策卡和停项备忘的字段（1815–1824；1919–1927）。给用户的回答同样用白话，照「对内和对外是两套话」。

```
**〔先直答：按当时材料，方法该改的第一件事是什么〕。〔紧接当时材料短原话支持的关键关系，以及当时证据还不能证明什么；整段不超过 3 句，不借后来事实补当时的依据〕**

### 当时要定的是什么
〔当时要拍的决定，当时选了什么〕

### 按当时的材料，本该看出来的
- 〔方面，白话〕：当时材料写「原话」，这本该说明〔……〕。对应后来的〔结果〕。
（最上游的放第一条；写清当时是没问、问了没答上，还是拿弱证据当了强证据）

### 当时看不出来、后来才知道的
- 〔……〕

### 判断和结果分开看
判断：〔只看当时的材料：当时的证据撑不撑得起那个决定；有没有事先写下看到什么就停〕
结果：〔一句事实〕

### 方法该改什么
1. 〔在哪一步问哪一句、看到什么才放行〕
（最多 3 条，具体到能照着做）

这个复盘在什么情况下要改：〔 〕　什么时候回头再看：〔建议日期或触发事件，你可以改〕
```

1. 定决定日，把材料按日期分两堆。决定日之前的进「本该看出来的」，之后的只进「后来才知道的」（推导；防的是事后移动门槛，591）。只有回忆、拿不出当时材料的，注明「事后回忆」。完成条件：「本该看出来的」每一条都引了当时材料的原话。
2. 「本该看出来的」照全景扫描判当时各方面的状态，按上溯根因页取最上游一处放第一条；闭环检查第 1 步按当时填，查出当时把什么当成了什么也写进去。完成条件：第一条是最上游的一处。
3. 判断和结果分两栏各自判。结果好不说明当时判断对，结果坏也不说明当时判断错（推导；锚点：事后能讲通的成功故事不等于事前可预测 453，决定基于证据而不是投入后的心理负担 1918，作者对成败的解释不算排除了其他原因 144）。完成条件：判断一栏没有用到后来才知道的事实。
4. 归因照报告的五类：用户、情境、方案、价格、能力假设（593）；「客户不懂」不算归因（593）。当时转过向的，再写动的是哪一方面（B20 680）。留下没排除的其他解释（1148；1822）。完成条件：每条归因落在五类之内。
5. 「方法该改什么」每条落到具体的一问和放行条件。完成条件：每条都能照着做，没有「要更谨慎」这类话。
