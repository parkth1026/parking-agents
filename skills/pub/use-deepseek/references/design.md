# design: use-deepseek

## 意图与触发场景

用户在 ZCode 主会话里要让外部模型 DeepSeek 参与工作：交叉验证方案、外部评审报告或代码、请它调研或产出草稿，并要求多轮来回（追问、纠错），而不是一次性问答。触发语如「问问 DeepSeek」「让 DeepSeek 评审/分析」「和 DeepSeek 来回讨论」「用外部模型交叉验证」。产出形态：完成多轮协作后，把 DeepSeek 结论与主 agent 的独立验证证据带回主会话，全程转录落盘。

## 设计取舍

- 参照 `skills/pub/use-gpt-pro`（原 codex-use-gpt-pro，2026-10-07 改名并同批迁到 browser-use）的双代理协议，把宿主从 Codex 内置浏览器换到 ZCode browser-use：后者不支持文件上传，上下文投递从「ZIP 打包上传」改为「消息文本内联 + 分块标记（第 i/N 块）」。
- 不内置浏览器驱动脚本（scripts/ 为空）：node_repl 每个细胞必须以官方引导代码开头，元素定位必须来自现场快照——硬编码选择器的脚本在 UI 改版时静默失效，比文字协议更脆。低自由度护栏放在协议规则（分块标记、完成判定多信号、凭据红线），定位细节留给现场判断。
- UI 知识放 `references/deepseek-ui.md` 并声明「锚点非契约」：DeepSeek 前端会改版、账号语言不定，固化选择器必然过时；文档只回答「该找什么」。
- 生成完成判定用多信号（停止按钮消失/输入框恢复/长度稳定）而非固定延时：单信号与固定等待都会被思考模式的长生成或 UI 改版击穿。
- 每轮往返即时落盘 JSONL 转录：多轮对话超出上下文窗口后，转录是恢复现场与最终报告的唯一可靠凭据。

| 编号 | 条件 | 类型 |

| AC-1 | SKILL.md frontmatter 合规：name=use-deepseek、description 非空且 ≤1024 字符、无尖括号、全文无待办占位 | script |
| AC-2 | 正文含接入护栏：指涉 control-browser 通用协议、优先接管既有标签页（tabs.list/user.openTabs）、登录或验证码即停 | script |

| AC-4 | 正文含消息循环（发送/等待/读取/落盘）且指向 deepseek-ui.md 的完成判定，含「不催促、不重发」约束 | script |
| AC-5 | deepseek-ui.md 存在且声明以现场快照为准，含完成判定多信号 | script |
| AC-6 | design.md 验收表无待办占位 | script |
| AC-7 | 实机冒烟：找到或新建 chat.deepseek.com 会话，完成 ≥1 轮「发送→等待完成→读回全文→转录落盘」 | manual |
