# DeepSeek 网页端 UI 地图（chat.deepseek.com）

本文是「该找什么」的锚点提示，不是选择器契约。DeepSeek 前端会改版，账号界面语言可能是中文或英文——任何元素定位都以现场 `domSnapshot()` 的事实为准，本文只帮你省去「不知道页面上有什么」的摸索。首次接入、找不到元素、判定生成是否结束时读本文。

## 页面结构

- 左侧栏：新对话入口 + 历史会话列表（每项含标题，按时间排序）。窄屏下可能折叠，展开后可见。
- 主区：消息流。你发的消息与 DeepSeek 回复交替出现；回复以 Markdown 渲染（代码块、表格、可折叠的思考块）。
- 底部：输入区。多行文本框（textarea）+ 功能开关（如「深度思考」「联网搜索」）+ 发送按钮。

## 输入与发送

- 输入框是页面上最主要的 textarea（placeholder 通常含「发送消息」/「Message」字样）。
- 用 `fill()` 写入全文，然后点发送按钮——不要用 Enter 键发送：Enter 在部分状态下是换行，行为不稳定。
- 发送成功的判据：你发的文本回显在消息流里。没回显就重新观察按钮与输入框状态，不要连续补发。
- 功能开关（深度思考/联网搜索）**由用户手动管理，agent 一律不点击、不读取、不判断其状态**（实测状态读取与点击结果多次相反，现场提示文案也不可靠）。需要联网或深度思考时，请用户在发送前自行开启；发送前也不做确认。
- 一次只发一条消息；它生成期间不输入下一条。

## 生成完成判定（多信号，任一单信号都不可靠）

1. 「停止」按钮消失、发送按钮恢复可点；
2. 输入框恢复可输入状态；
3. 最新回复文本长度在间隔 ≥5 秒的两次采样中不再增长。

深度思考模式下回复前有较长的思考阶段（可折叠的「思考过程」块），整体耗时可到分钟级：耐心轮询，不催促、不点停止、不重发。判定「卡死」前至少观察 2 分钟无任何文本增长。

## 读取回复

- 目标是「最后一条 DeepSeek 回复」的消息容器：从快照按消息顺序定位——你的消息会回显刚发的文本，其后紧邻的回复块即目标。
- 长回复优先对该容器用 `innerText()` 取全文；快照可能截断长文本。
- 深度思考模式下区分「思考过程」折叠块与正式回答，转录时两者都记，分别标注。
- 回复底部有操作条（复制/重新生成等），读文本时不要点到它们。

## 会话管理

- 相互独立的任务各开一个新对话（防上下文污染）；同一任务的追问留在同一会话。
- 继续既有任务：从左侧会话列表按标题找回并点入。
- 页面刷新/断线后：重进会话列表找回原会话，从最后完成的位置继续，不要新开会话丢上下文。
- 把所用会话的标题（URL 里含会话 id 时一并记）写进转录与最终报告。

### 2026-09-28 冒烟（英文界面账号，ZCode IAB）

- 输入框 accessible name 为 `Message DeepSeek`（该账号界面语言是英文）；功能开关显示为 `DeepThink` / `Search`；新会话入口文本 `New chat`（快捷键 Ctrl+J）。
- 发送键：`role=button` 且类名含 `ds-button--primary`、`ds-button--filled`、`ds-button--circle`，输入栏最右的圆形主按钮（其左侧还有一个小的胶囊附件按钮）。**标准 Playwright `click()` 在该按钮上常因 actionability 抖动超时**（含 `force: true`）；对该唯一定位执行页面内点击 `locator.evaluate(el => el.click())` 可靠。
- 发送成功判据实测成立：输入框清空 + URL 变为 `/a/chat/s/<uuid>`，会话以自动生成标题出现在侧栏 Today 组（标题由 DeepSeek 从消息内容生成）。
- 回复默认带一行思考块（"Thought for N seconds" 折叠区），正式回答在其后；读取时按思考块与回答分段。
- 健康页面上 `domSnapshot()` 能看到消息文本；长回复仍优先 `innerText()`。
- **渲染面劣化坑**：接管来的或长期驻留的标签页，可能在一次发送后消息流不再进 DOM（`document.body.innerText` 只剩几十个字符、无任何消息文本节点，iframe/shadow root 均为空）且 `screenshot()` 表面准备超时。会话本身完好（服务端已建、标题已生成）。恢复：新开标签页直达会话 URL（`/a/chat/s/<id>`）即完整渲染，随后关闭劣化标签页。判别方法：读取回复时若 `innerText` 里找不到刚发出的消息文本，不要怀疑发送失败——先查 URL 与侧栏标题确认会话存在，再换新标签页。

### 2026-10-01 分享页（/share/<id>）读取路径

- 分享页是 JS 渲染：WebFetch / webReader 均拿不到正文；页面正文在 `ds-virtual-list` 虚拟列表里，程序化改 `scrollTop` 不触发重渲染（顶部采样反而为空），滚动采集不可行。
- 可靠路径：登录态下在页面内同源 `fetch('/api/v0/share/content?share_id=<id>', {credentials:'include'})`，返回完整 JSON（`data.biz_data.messages[]`，含 USER/ASSISTANT、fragments 分 THINK/RESPONSE/TOOL_*），本地解析即可全文转录；接口 URL 可从 `performance.getEntriesByType('resource')` 证据式找到，无需猜路径。
- 分享页 `screenshot()` 可能表面准备超时（与既有劣化坑同款），但不影响数据接口路径。
- `share/content` 接口实测无需登录（WebFetch 直接抓接口 URL 即返回 JSON），可先用 WebFetch 打接口做快速预览；但大对话（约 200KB）经 WebFetch 小模型转述疑似被截断（12 条只数出 8 条），精确全量转录仍以浏览器同源 fetch 落盘解析为准。

### 2026-09-28 用户裁定：开关由用户手动管理

- Agent 不点击、不读取、不判断 DeepThink/Search 开关状态（实测状态读取与点击结果多次相反，现场提示文案也不可靠）。需要联网或深度思考时，由用户在发送前手动开启。
- 若任务强依赖联网而回复里没有任何搜索痕迹（无 "Found/Searched N pages"、无可核实的实时信息），照常读回并在最终报告里标注，不自行补救、不重发。
