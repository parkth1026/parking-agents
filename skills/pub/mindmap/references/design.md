# design: markmap-mindmap

## 意图与触发场景

人和 agent 协作维护思维导图：人在 VS Code Markmap 插件里轻量预览、手改，agent 按统一规范生成和批量改写同一份 `*.mindmap.md`。没有这个技能时，每个会话会重新发明写法：节点忽长忽短，括号说明堆在分支上，`[[ ]]` 在预览里显示成原样括号。

触发模式：**语境触发**。用户会说「画个思维导图 / 脑图」「把这份文档整理成导图」「导图里 L2 拆成两支」「把刚才讨论的结论记进导图」「markmap」。drawio 流程图、架构图、时序图等不归本技能。

三类场景（用户 2026-10-17 选定）：从文档或 wiki 生成；批量重构；对话中边聊边记。

产出：一份通过 `scripts/lint.mjs` 的 `*.mindmap.md`，再加上一段变动说明。

## 设计取舍

- **正本只有 md，不生成 HTML、不用 markmap-cli**：用户已装 VS Code 插件，生成物会和正本漂移（用户 2026-10-17 裁定）。
- **数值规则交给脚本（低自由度），语义规则交给文字（高自由度）**：字数、深度、子节点数、缩进、`[[ ]]` 能机械判，进 lint；MECE、怎么分组、标不标状态需要理解内容，写进 rules.md 由 agent 判断。
- **分支 ≤12 字、叶子 ≤30 字，而不是 Buzan 的一线一词**：在 WDP6 架构图上实测，一线一词把首屏节点从 37 降到 16，但让「工具规训」这类叶子失去了含义；分支短、叶子成句，在保持首屏 15 个节点的同时把信息找了回来。
- **子节点只设上限 7，不设下限 3**：实测中下限在真实内容里有 10 处做不到，强行凑数只会制造假分组。
- **深度上限 6**：上限 5 和「一级分支 3–7 个」互相冲突，实测需要 6 层。
- **（注）≤20 字且只写判断依据或口径**：第一稿范例有 19 个节点带注，长文字只是换了个地方放。
- **节点不放 `[[ ]]`**：Markmap 不渲染 wiki 链接；溯源信息移到顶部注释。
- **改前必读最新版**：人可能刚在插件里手改过，凭记忆改会覆盖人的改动。

## 验收条件

| 编号 | 条件 | 类型 |
| --- | --- | --- |
| AC-1 | 产出的 `*.mindmap.md` 跑 `scripts/lint.mjs` 退出码 0 | script |
| AC-2 | 从文档生成时，顶部有 `<!-- 来源：… -->` 注释，节点内无 `[[ ]]` | script |
| AC-3 | 叶子节点保留原文的关键信息（判断、口径、约束），不是只剩关键词 | manual |
| AC-4 | 兄弟节点同类、不重叠；一级分支是不同的观察角度 | manual |
| AC-5 | 改已有导图前读取文件最新内容；改后在回复里列出新增 / 删除 / 移动的节点 | manual |
| AC-6 | 不生成 HTML，不调用 markmap-cli | script |
| AC-7 | lint 对 fixtures/bad.mindmap.md 检出全部 12 类违规，对 good 判 0 | script |
