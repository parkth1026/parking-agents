# 思维导图写法规范

正本是 `*.mindmap.md`，人用 VS Code Markmap 插件预览和手改，agent 直接改文本。`scripts/lint.mjs` 能检查的规则标了【lint】，其余靠判断。

## 0. 档位：A 结构型 / B 记录卡型

| 档 | 用途 | 判据 |
| --- | --- | --- |
| A 结构型 | 概念图、知识梳理 | 默认 |
| B 记录卡型 | 开发计划、看板、清单 | 机械判据【lint】：全文 ≥3 行实体卡行（`- …〔E#-S# …〕`）；或在 frontmatter 写 `cardMode: true` 显式声明 |

判定是机械的，不靠语义猜测。B 档文档里的**非卡分支**（发布门、横切原则等）仍按 A 档规则约束。同一文档混两种文体时，卡片区按 §9，叙事区按 §1-8。

## 1. 结构语法

- `#` 根节点，全文只有一个【lint】。
- `##` 一级分支；再往下一律用 `-` 列表，不用 `###`【lint】。
- 列表缩进 2 空格，不用 Tab【lint】。
- 一行一个节点，节点内不换行。

为什么：标题和列表混深了，人手改时层级容易错；固定成 `#`/`##`/列表三档，缩进就是层级。

## 2. 节点写法（A 档）

| 节点类型 | 写法 | 上限 |
| --- | --- | --- |
| 分支节点（有子节点） | 关键词或短语，只负责结构 | ≤12 字【lint】 |
| 叶子节点（无子节点） | 一句话把意思说清，可用「名词：说明」格式 | ≤30 字【lint】 |

计字口径：去掉魔法注释、（注）、状态标记、〔〕标签与 🔌，链接只算文字。

- 分支原来带的括号说明（用户、职责、定位、原则…）下沉为叶子，写成 `用户：业主 / 决策层`、`职责：数据 → 业务系统`。
- 不要为了短而把叶子压成一个词。「工具规训」读者看不懂，「工具规训：AI 只能调用批准的能力清单」才是信息。
- 写不进 30 字的，按分号/逗号切分拆成多个兄弟叶子，不要塞进（注）。

为什么：Buzan 的「一线一词」适合自己记忆，不适合给别人看。分支短保证结构清楚，叶子成句保证信息不丢。

## 3. 层级与分组

- 每个节点的子节点 ≤7【lint】（B 档 EPIC 下卡片数豁免——记录数 ≠ 认知组块），超了就再分一组。不设下限，2 个子节点是正常的。
- 深度 ≤6（`#` 算第 1 层）【lint】，超了就拆成独立的 `*.mindmap.md`，在原位置写一个叶子指向它。
- 兄弟节点同类、不重叠、合起来完整（MECE）：不要把「模块」和「风险」并列。
- 上层是下层的概括，只读到某一层也能明白下面在讲什么。
- 一级分支是看问题的不同角度（如 价值闭环 / 五层架构 / 横切支撑），不是把所有东西平铺。

## 4. 标记词表

| 标记 | 含义 | 适用 |
| --- | --- | --- |
| `✅已定` | 已决策，有依据 | 仅 A 档 |
| `🧪探索` | 在验证中，不进承诺 | 仅 A 档 |
| `❓待定` | 还没决定 | 仅 A 档 |
| `🔌` | 类型标记：上下游接口直接相关 | A/B 档通用 |

原则：**类型（不随时间过期）才进导图；状态（会过期）归数据正本**。B 档不用 ✅🧪❓ 状态标记——状态与进展由外部表格承载。🔌 只标接口直接相关的卡片，词表封闭，不新造标记。只标关键项，不要每个节点都标。

## 5. （注）

格式 `（注：…）`，≤20 字【lint】，只写**判断依据或口径**，例如 `❓待定（注：T2 国产实测后定）`。普通解释写成叶子，不进（注）。

为什么：（注）不计入节点字数，放开用就成了塞长文字的后门。

## 6. 元信息与溯源

- 来源、关联 wiki、状态词表、规范摘要都写在文件顶部的 HTML 注释里，不占一级分支【lint】。
- 节点里不放 `[[ ]]`【lint】：Markmap 不认 wiki 链接，会原样显示括号。需要溯源时把 wiki 页名列进顶部 `<!-- 关联 wiki：… -->`。
- 从文档生成时必须写 `<!-- 来源：路径 版本/日期 -->`。

## 7. Markmap 语法

frontmatter：

```yaml
---
title: 标题
cardMode: true        # 仅 B 档需要
markmap:
  colorFreezeLevel: 2      # 第 2 层起子分支沿用祖先颜色，一级分支各一色
  initialExpandLevel: 3    # A 档默认 3；B 档用 2（首屏只出 EPIC 索引）
  maxWidth: 320            # 节点最大宽度，超出换行显示
---
```

魔法注释写在节点行尾：

- `<!-- markmap: fold -->`：只折叠该节点。细节分支用它，让首屏只剩骨架。
- `<!-- markmap: foldAll -->`：折叠该节点和全部后代。

首屏控制：A 档首屏节点（展开层内、未被折叠的）约 20 个；B 档给每个 EPIC 标题行加 fold、`initialExpandLevel: 2`，首屏只出 EPIC 索引，点开看卡。14 寸屏上长句卡片折行后 44 卡就是文字墙——渐进披露靠折叠，不靠放宽口径。

## 8. 对照示例（A 档）

差：

```markdown
## L2 生产侧（开发者 / FDE / 业务专家）
- 业务 Agent（数据 → 业务系统）
  - 骨架组装（挑预置模板 → 填资产 → 绑数据源）
```

好：

```markdown
- L2 生产侧
  - 用户：开发者 / FDE / 业务专家
  - 业务 Agent <!-- markmap: fold -->
    - 职责：数据 → 业务系统
    - 骨架组装：挑预置模板 → 填资产 → 绑数据源
```

完整范例见 `fixtures/good.mindmap.md`；B 档范例见 §9。

## 9. B 档：记录卡模式

一张卡 = 实体行 + 固定字段。EPIC 标题行加 fold。

```markdown
## E2 场景重建AGENT <!-- markmap: fold -->

- Story：单场景重建速度与面积关系衡量，确保能给用户时间的预估与承诺 〔E2-S06 · 彭博/陈文婕/景雅虹/曾标 · W3 公测〕
  - 用户：等待结果的客户
  - 原因：产品说明书明文承诺数小时级，时长 SLA 需要有人负责兑现
  - 验收
    - 速度-面积关系模型成文，任意场景可给出时间预估
    - 厂房级端到端（上传→可下载）≤ 数小时
```

规则（豁免是交易：字数豁免换来结构强校验）：

- **实体行**：`Story：完整句` ≤50 字【lint】（英文组件名计入）；〔〕标签与 🔌 不计。
- **行内标签**：〔ID · 负责人 · 目标版本〕，全角括号+间隔号，可扫描可 grep【lint】。
- **字段行封闭词表**：`用户：` / `原因：` / `验收`【lint】。用户/原因 ≤45 字【lint】。
- **验收写法（双形态）**：**阅读视图** `验收：完整句` ≤90 字【lint】——条件与因果保留在句内，适合逐卡阅读；**清单视图** 拆 `验收` 分支 + checklist 子叶，每叶 ≤30 字【lint】——适合逐条勾选。同一份文档选一种为主；超 90 字必须拆清单。
- **字段行归属**：用户/原因/验收必须直接挂在实体行下（缩进恰好一层）【lint】——顶格或错层的字段行是结构事故，一票警告。
- **ID 主权**：〔E#-S#〕全局唯一【lint】、前缀与所在 EPIC 编号一致【lint】。表格删列后，mindmap 编号是人机沟通与表格关联的唯一锚——改内容不改编号；新增卡片从所属 EPIC 顺延编号。
- **易变数据归表格**：排期、进展、状态不进导图（排期行已废除，正本在表格「交付安排与复验」列）。行内标签只留 ID·负责人·目标版本。
- **生命周期**：阶段完成的卡片折叠进「已归档」分支，不删。

## 10. 双正本同步（B 档）

mindmap=工作视图，结构化正本在外部表格（如飞书多维表格）：

- **改前先拉**：动卡片区前拉表格最新版对齐字段（ID↔行、用户/原因/验收↔说明列、负责人/迭代/版本↔列），防止覆盖他人改动。
- **字段级 master**：卡片内容字段以表格「说明」列为准；EPIC 分组、发布门等叙事分支以 mindmap 为准；编号主权在 mindmap。
- **漂移兜底**：lint 结构校验（编号唯一、前缀一致、字段词表、缩进归属）负责拦结构性漂移；内容漂移靠「改前先拉」纪律。
