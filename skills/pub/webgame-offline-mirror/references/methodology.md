# 方法论：三层抓取 + 后端本地化 + 三零终验

任何单层抓取都有系统性盲区。三层各自独立命中过其他层永远找不到的文件，缺一不可。

## 第 0 层：侦察（决定后面所有参数）

按 engine-playbooks.md 的指纹表识别引擎/构建系统，同时确认：

1. **sourcemap 探测**：抓 entry JS，试 `<entry>.map`、chunk 名 + `.map`。命中 → 先恢复源码再谈镜像（完全不同的任务）；未命中 → 产物镜像路线。
2. **service worker**：HTML/JS 里搜 `serviceWorker`。有 SW 的站点资源经 SW 缓存，抓取面不同（可能要读 SW 的 precache 清单——那是现成的完整文件列表，金矿）。
3. **资源 base resolver**：游戏资源 URL 常由一个 `base + path` 函数拼接（Vite 系常叫资产函数）。从 bundle 里找到它（搜 `.png`/`.glb` 字面量附近的函数），确认 base 前缀与版本参数（`?v=`）——**不确认 base 直接拼 URL 会全 404**。
4. **后端面**：搜独立 API 域、`/api/`、`fetch(`。游戏有无后端决定第 4 层工作量。

## 第 1 层：静态引用闭包

`scripts/mirror.mjs --origin <url> --out <dir>` 从入口递归抓字面量引用直到收敛，然后 `scripts/audit-closure.mjs` 审计「被引用但缺失」。收敛判据：audit 报零真实缺失（少量探测性 404 属正常）。

## 第 2 层：家族全枚举

对「运行时拼接」的 URL（模板串 `${id}.png`），静态闭包无能为力。三个策略按优先级：

1. **注册表抽取（首选）**：数据驱动的家族（图标、标记、皮肤）几乎总在 bundle 里有注册表/枚举对象。找到它，抽全集，一次收口。**不要打地鼠**——每局游戏随机暴露几个新名字，永远抓不完。
2. **id 空间枚举**：命名是数字序列的（`cries/1.ogg`…`cries/1025.ogg`），按数据文件给出的全集生成 URL，404 淘汰。
3. **词候选探测**：名字来自有限词表的（模型名、曲目名），从 bundle 提取全部单词字面量（`[a-z][a-z0-9-]{2,28}`）作候选，404 淘汰。候选量控制在一到三千，并发 8-10，带退避。

产出写入 urls 文件（`--urls-file`）重跑 mirror。收敛判据：连续一轮无新增命中。

## 第 3 层：运行时录制回灌

无头浏览器真跑游戏，录全部网络请求，missing 回灌 urls 文件。这层专治前两层的结构性盲区（数据驱动命名、深层菜单才加载的资源）。要点：

- 交互脚本外置 JSON（verify-offline.mjs 的 flow 格式），按钮匹配用多语言正则。
- 引导/弹窗/选关是最大障碍：新档首启常有赛季弹窗、新手引导、选人确认，逐个关掉才能进正局。
- 「进入对局」的判定用「主菜单按钮消失」，不要用「发了某请求」假设。
- 真站点录制一轮 + 本地镜像录制一轮：前者发现真实资源用法，后者验证镜像完整性。

## 第 4 层：后端本地化

见 backend-mock.md。核心：录制真实流量做形状蓝本，patch 客户端 base 指向本地，本地服务按录制形状应答，进度落库。

## 第 5 层：三零终验

`verify-offline.mjs --block-external`：网络层阻断一切外部请求，全流程（登录→主菜单→对局→结算→刷新）。三零 = 零 404 / 零外网请求 / 零 console 错误。截图留证。**「看起来能跑」不算数**——不屏蔽外网时，缺的文件会被线上静默补上，验证就是假的。

## 交付物清单

镜像目录 + 本地服务（含 mock 后端）+ 三零报告 + 截图 + README（运行方式/更新流程/已知边界）。更新流程：重跑 mirror → audit → patch → verify；build id 变化时更新参数。
