# 后端本地化模式

多数联网网页游戏有一个 API 后端（账号/存档/配置）。离线运行必须本地替代它。**形状不猜、只录**。

## 流程

### 1. 分析客户端（读压缩代码，不运行）

- 找 API base 字面量：搜独立域名、`api.`、`https://` 在 fetch 附近的常量。几乎总有单一 base 常量拼 `base + path`——这决定了 patch 只改一处。
- 枚举全部端点：搜 `this.req(`/`fetch(` 的第一个参数字面量；注意模板串端点（`` `/runs/${id}/finish` ``）按模式归并。
- 读请求封装的超时/重试/**离线降级**分支：降级逻辑（本地队列重试、离线对局不保存）决定 mock 的最低实现面——有的游戏只要闸门接口通，其余全有兜底；有的没有降级，全链路都要 mock。
- 找启动闸门：启动时第一个阻塞后续的状态接口。它不通，游戏卡死在重试屏。

### 2. 录制真实流量（fixtures 蓝本）

无头浏览器开**真实站点**，录制后端域名下所有请求/响应（方法、路径、请求体、响应体、状态码）。驱动力求覆盖：游客注册 → 主菜单 → 各功能页 → 开一局 → 结束结算。录制自己拥有或已授权的服务；一次性游客账号即可。
产出到 fixtures 文件，同时是将来后端形状变化时的对照基线。

### 3. patch 客户端 base

把 bundle 里的 `https://api.example.com` 替换为同源相对路径 `/api`（客户端是 `base + path` 字符串拼接，相对路径可用；若客户端对 base 做 `new URL(base)` 解析则不能用相对路径，改绝对 `http://127.0.0.1:PORT/api`）。原始文件备份 `.orig`，patch 脚本幂等可重跑。

### 4. 本地实现（推荐形态）

单进程 node 服务同时承担静态镜像 + `/api` mock（同源免 CORS）。按复杂度分级：

- **最低**：闸门接口按录制形状应答（注意把时效字段推到远未来——赛季结束时间、维护标志）。
- **标准**：认证/存档链路（游客、注册/登录、profile 读写、对局上报），进度持久化。凭据 scrypt 加盐哈希，写入用事务（SQLite：Node 内置 `node:sqlite`，零原生依赖）。多会话并存（sessions 表）。
- **惰性**：多人/社交端点（战队、好友、邮件、聊天）返回空数据或 204——离线没有多人。宁可惰性不可假成功：未实现的端点不要返回形状不对的 200，会让客户端走进未知分支。

### 5. 回归

注册→登出→登录→进度持久化→断外网全流程，逐条对照录制形状。客户端对 mock 的每个响应都要像对真实后端一样消费——UI 不炸才算形状对。

## 判断点：什么时候放弃 mock

核心玩法逻辑在服务端的（MMO 战斗结算、反作弊强校验、服务端权威状态机），录制形状也还原不了行为。识别特征：客户端只发操作、不收结果；或状态同步走 WebSocket 双向流。这类目标在动手前就告诉用户「离线镜像对该游戏不可行，只能做资产镜像」。
