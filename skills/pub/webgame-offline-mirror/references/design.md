# design: webgame-offline-mirror

## 意图与触发场景

把一个线上网页游戏（或重前端的网页应用）完整恢复成本地**离线可运行**副本：资产、前端、必要的后端替代全部本地化，运行时零外网请求。产出：镜像目录 + 本地服务/后端 + 三零验证报告 + 更新手册。

触发模式：语境触发。用户会说：「源码丢了，把 X 游戏/网站下载到本地离线跑」「把 X 镜像下来，断网也能玩」「完整保存这个网页游戏」。

**使用边界（硬约束）**：仅用于自己拥有、或有明确授权的目标。技能不判断授权，由调用者负责；对无授权目标的请求应拒绝并说明。

不适用：只需存单个页面（浏览器另存为即可）；需要窃取登录态的内容；客户端-服务器强耦合的 MMO（核心玩法在服务端，mock 无法还原）。

## 设计取舍

1. **三层抓取缺一不可**：静态引用闭包抓「字面量引用」；家族枚举抓「运行时拼接 URL」；运行时录制抓「数据驱动命名」。实测每层都独立抓出过其他层永远找不到的文件——这是本技能最核心的教训。不选单层方案（如纯 wget/HTTrack）因为对动态资源有系统性盲区。
2. **脚本固化机械操作，方法论留给 agent**：抓取器/审计器/验证器为低自由度脚本（参数化、零站点逻辑）；「识别哪个家族、怎么枚举、引擎是哪个」是高自由度判断，写 references。
3. **后端不猜、只录**：mock 响应形状以真实流量录制为准（fixtures）；客户端离线降级逻辑必须读压缩代码确认，不假设「断了应该也能玩」。
4. **终验必须屏蔽外网**：网络层阻断一切外部请求后全流程跑通，三零判定（零 404 / 零外网 / 零报错）。「看起来能跑」不算数。
5. **交付含更新手册**：build id、hash 模式等参数全部外置，线上更新后重跑管线即可同步。

## 验收条件
| 编号 | 条件 | 类型 |
| --- | --- | --- |
| AC-1 | 给定 fixture 站点（哈希命名资产 + 嵌套引用 + 无引号 CSS url()），`mirror.mjs` 单轮抓取后 `audit-closure.mjs` 报零缺失 | script |
| AC-2 | `verify-offline.mjs --block-external` 对本地 fixture 产出三零判定（零缺失/零外网/零报错） | script |
| AC-3 | 坑清单（pitfalls.md）覆盖五个通用类目：引用位移、无引号 url()、资源 base 前缀、请求无超时、后端启动闸门 | manual |
| AC-4 | 引擎手册覆盖 ≥6 种引擎的指纹与资产模式 | manual |
| AC-5 | `run-tests.mjs` 全过（无网络依赖，回归门） | script |
