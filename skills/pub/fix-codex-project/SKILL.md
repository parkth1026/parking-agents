# fix-codex-project

恢复本机仍保存的项目组织关系到当前账号，保留原件和目标账号新增记录。默认交付当前项目内的一次性脚本包，让用户退出 Codex 后执行一次。生成成功与恢复成功分开报告，最终以原项目分组重新可用为准。

## 只读定位

解析实际 `CODEX_HOME`；未设置时用当前用户的 `.codex`。检查环境覆盖、目录联接、实际桌面端版本及进程，避免读取一个目录却修改另一个目录。

```powershell
python '<skill-dir>\scripts\projects.py' inspect --home '<codex-home>'
```

脚本输出匿名账号前缀、项目数、工作目录数、会话关联数、路径存在情况及 SQLite 摘要，不打印会话正文、完整账号 ID 或认证信息。

区分项目文件夹、项目元数据、会话正文、会话归属四种证据。`inactive` 是状态 JSON 的字段，不是磁盘目录。创建者字段存在不代表会话列表按账号过滤。需要解释结构或版本行为时读 [references/storage.md](references/storage.md)，并核对已安装版本或官方说明。

## 在当前项目生成脚本包

只问原因时保持只读。要求修复时，确认当前项目绝对路径，直接生成脚本包，不再次请求生成许可。项目路径决定产物位置，恢复范围仍是当前账号的本地项目集合。

```powershell
node '<skill-dir>\scripts\prepare.mjs' --project '<当前项目绝对路径>' --home '<codex-home>' --source '<完整来源标识>'
```

默认输出 `<当前项目>\outputs\codex-project-repair-<时间戳>\`。宿主指定其他交付目录时用 `--out '<全新目录>'`，保持在当前项目内、技能扫描根之外。目录已存在则拒绝覆盖。可用 `--python '<已验证的 Python 路径>'` 指定已有解释器。

来源唯一且确有项目记录时可省略 `--source`。多个来源时比较项目名称、路径和待恢复字段；内容一致时明确记录等价依据再选一个，内容不同且无法判断才询问，不按记录最多判断旧账号。目标身份不明确或结构异常时先解决再生成。

生成器只读账号状态，输出 `run-repair.cmd`、`run-once.mjs`、`projects.py`、`plan.json`、`config.json`、`README.txt`。计划绑定 Home、当前身份、原始来源内容指纹；本地恢复自动排除来源的远程会话归属与其关联字段，原始 inactive 和目标已有远程记录保留。未知归属类型仍拒绝处理。

完成标准：脚本包存在、计划来源和目标明确，当前账号文件未修改。最终回复链接 `run-repair.cmd`，状态写 `PREPARED_NOT_APPLIED`；不要把生成、等待或备份标成恢复成功。私人计划与后续备份只保存在本机，不打进通用技能包。

## 用户退出后执行一次

交代固定顺序：双击 `run-repair.cmd`，彻底退出 Codex，保持关闭，等脚本提示成功再手动打开。也可先退出再双击脚本。默认只交付入口，不启动后台等待程序；用户明确要求自动等待时才启动这个入口，并如实报告正在等待。

桌面端退出时可能把内存旧状态写回磁盘，运行中直接写文件不能保证重启后保留。脚本不关闭、结束或启动任何应用，不操作凭据；用户退出后连续 5 秒未检测到桌面进程，才进行一次恢复。最长等待 30 分钟，进程检测失败则拒绝写入。等待期间重开会重置计时，备份期间重开则失败退出，保持原有写入前检查。

每个脚本包以独占创建的 `run-once.claim.json` 标记一次执行。并发双击、再次执行、超时、失败或进程中断后均不能重用；解决原因后生成新包，不删除标记重跑，也不循环覆盖状态。生成阶段不注册计划任务、不安装驻留程序。

执行结果写 `result.json`：只有后端完成备份、写入、校验并返回凭据后才是 `RESTORED_ON_DISK`。失败是 `FAILED`，保留错误与已有备份；中断时没有成功回执就按未完成处理。文件成功后才提示重新打开应用。

脚本重新核对身份与来源，创建独立 JSON 和 SQLite 一致性备份，然后只合并白名单字段。对象递归合并、列表保留目标顺序补缺项；冲突保留目标值。保留整个 `inactive`、身份与其他配置。迁移映射只导入当前 Home 的本地主机记录。写入采用原子替换，两文件任一写入或校验失败时恢复已改文件并报告失败。

执行期间以 Home 下临时 `.fix-codex-project.lock` 阻止本工具并发恢复，退出时释放。残留锁须核对记录的 PID 与运行状态，不直接删除。锁不能约束其他工具；恢复窗口应保持其他写入者静止，指纹变化就停止，不循环覆盖。两文件独立原子替换不等于跨文件事务，断电或持续磁盘故障后应按独立备份重新检查，不承诺无条件自动恢复。

仅修改 `.codex-global-state.json` 及其 `.bak`；SQLite 和会话正文只读。备份目录须新建且位于技能扫描根之外。来源不存在时不能凭空重建；数据库 `project_id` 为空也不能证明会话无归属，旧关联可能在 JSON。

## 用户重新打开后验收

用户重新打开后，重新 `inspect`，确认项目及归属仍处于当前身份，比较恢复凭据的计数和冲突数。检查真实界面至少一个原项目及其已知会话；工具禁止操作目标应用时让用户检查界面，并保留 `NOT_RUN`。一次性脚本本身不把尚未执行的重启持久化、界面分组、会话续用标为成功。

分层报告 `PASS`、`FAIL` 或 `NOT_RUN`：备份、文件合并、重启后持久化、界面分组、原会话续用。明确两个 JSON 的绝对路径、备份位置及数据库未被脚本修改。应用启动后的数据库自行更新若未审计则单独说明。

这是一次恢复当前账号，不改变按账号选择状态的逻辑。不承诺再次切换自动共享；永久同步需要另行设计并验证双向合并与 A → B → A。

## 撤销本次恢复

先退出应用，再使用脚本包的 `backup` 目录：

```powershell
python '<脚本包>\projects.py' rollback --home '<codex-home>' --backup-dir '<脚本包>\backup'
```

只回滚本次改动的 JSON，不覆盖 SQLite。当前文件须匹配写后指纹；若重启或新增内容已改变文件，拒绝整份覆盖，分析差异并保留新记录后再撤销。回滚中途失败时补偿恢复到回滚前；持续磁盘错误导致补偿失败时保留备份并报告实际状态。
