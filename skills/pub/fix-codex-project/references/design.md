# 设计依据

## 意图与触发场景

采用语境触发并保留自动发现：恢复桌面端换账号后消失的本地项目与会话分组，或显式调用 fix-codex-project。仅诊断的请求不授权恢复。排除云端共享和永久同步。

## 设计取舍

以来源指纹和目标身份锁定计划，执行时合并最新状态，保留目标新增记录。采用白名单，数据库一致性备份但不修改；避免把旧 JSON 关联盲目迁入新表。进程管理交给具有现场证据的 agent，不固定 PID、用户目录或账号。

## 验收条件

| 编号 | 可验证条件 |
|---|---|
| AC-1 | inspect/plan 不修改输入；多来源、无目标身份、异常结构均拒绝模糊计划 |
| AC-2 | 目标或来源变化后拒绝恢复，应用仍运行时拒绝写入 |
| AC-3 | JSON 备份指纹一致，SQLite 备份 quick_check 为 ok，备份目录拒绝复用 |
| AC-4 | 保留目标冲突与新增、来源原件、无关配置，恢复项目及关联 |
| AC-5 | 数据库与正文不写入；中途失败恢复已改 JSON |
| AC-6 | 回滚恢复 JSON 原件，指纹变化时拒绝覆盖新数据 |
| AC-7 | 文件恢复不替代界面、会话续用或永久共享验收 |
