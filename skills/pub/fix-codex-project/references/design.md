# 设计依据

## 意图与触发场景

采用语境触发并保留自动发现：恢复桌面端换账号后消失的本地项目与会话分组，或显式调用 fix-codex-project。仅诊断的请求不授权恢复。排除云端共享和永久同步。

## 设计取舍

以来源指纹和目标身份锁定计划，执行时合并最新状态，保留目标新增记录。采用白名单，数据库一致性备份但不修改；避免把旧 JSON 关联盲目迁入新表。

默认在当前项目生成一次性脚本包：Node 内置模块负责生成、等待与回执，复用已有 Python 标准库后端进行 SQLite 一致性备份。Windows 批处理只作为生成的双击入口，不在技能内维护机器专用脚本。生成时记录实际解释器路径，不固定用户目录、账号或 PID。

不主动退出或重启应用。用户彻底退出且连续 5 秒检测不到桌面进程后，后端执行一次；用户看到成功提示才打开应用。独占执行标记贯穿成功、失败和中断，失败后需生成新包，避免复用旧备份或重复覆盖。进程在备份期间重开仍由后端拒绝，不以反复尝试绕过检查。当前项目只决定产物目录，不限制账号级恢复为单个项目。

## 验收条件

| 编号 | 可验证条件 |
|---|---|
| AC-1 | inspect/plan 不修改输入；多来源、无目标身份、异常结构均拒绝模糊计划 |
| AC-2 | 目标或来源变化后拒绝恢复，应用仍运行时拒绝写入 |
| AC-3 | JSON 备份指纹一致，SQLite 备份 quick_check 为 ok，备份目录拒绝复用 |
| AC-4 | 保留目标冲突与新增、来源原件、无关配置，恢复项目及关联 |
| AC-5 | 数据库与正文不写入；中途失败恢复已改 JSON |
| AC-6 | 回滚恢复 JSON 原件，指纹变化时拒绝覆盖新数据 |
| AC-7 | 文件恢复不替代界面、会话续用或永久共享验收 |
| AC-8 | prepare 仅生成当前项目内的独立包，不修改 Home；拒绝覆盖已有目录、向技能扫描根写入私人产物 |
| AC-9 | 连续退出 5 秒才执行，重开重置计时；超时或检测失败不调用恢复后端 |
| AC-10 | 同一包成功、失败或中断后不可再执行；并发启动只有一个获得执行标记 |
| AC-11 | 备份期间应用重开则失败且不重试，不误报文件成功；结果中未验收层始终 NOT_RUN |
| AC-12 | 本地计划排除来源的远程归属及关联字段，保留来源存档和目标已有远程记录，未知结构拒绝 |
| AC-13 | 拷出的独立包可调用真实恢复后端，不因后端位置变化误把项目目录当作技能扫描根 |
