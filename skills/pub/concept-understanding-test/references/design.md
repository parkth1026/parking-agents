# design: concept-understanding-test

## 意图与触发场景

用户要测「某模型对某概念是原生理解还是靠检索」时使用。输出结论是**理解程度百分比**。典型说法：「测一下模型懂不懂奥卡姆剃刀」「这个概念它原生会多少」。

触发模式：**名字触发**（模式二，description 只写名字中英双语）。本技能是刻意调用的测量工具；误触发（用户只是聊到某概念）会产生昂贵副作用（双 subagent + 联网核实）。升级路径：若日后发现总要以整句意图唤醒，改语境式并重跑触发评测。

期望产出：理解程度百分比 + 分级 + 三分类明细 + 子分（原理/出处）+ 两臂信源与校准注记。

## 设计取舍

| 决定 | 自由度 | 为什么没选别的 |
| --- | --- | --- |
| 双跑对比：闭卷臂 vs 带搜索臂，以带搜索答案为参照 | 文字锁死 | 用户定形的核心机制；参照系自带（搜索核实后的答案），无需出题人预写判定依据，判分可复现、跨模型可比 |
| 输出=理解程度百分比（一致/(一致+偏差+缺失)） | 文字锁死 | 用户明确要百分比结论；纯计数公式消除评分者主观 |
| 考题=概念题+应用题两道自然问法 | 文字锁死 | 用户给定形态（「X 是什么」+「对<对象>用 X 你会怎么做」）；应用题防只会背定义不会干活 |
| 题面禁写评分维度提示 | 文字锁死 | 提示=引导性提示，测的是展开能力不是原生理解（第二轮实测打回教训） |
| 臂 A tool_uses=0、臂 B tool_uses>0 且含来源，双向硬判据 | 文字锁死 | 单向计数不构成对照；无来源的 B 只是第二份闭卷，参照无效 |
| 搜索通道降级（WebSearch→Exa→WebFetch 直抓）且全尽即作废 | 文字锁死 | 降级返回的同模型复述不得冒充参照（Hamilton 1852 实测教训）；无检索的 B 会把测量变成同先验自比 |
| 子分（原理类/出处类）分列 | 文字 | 出处要点会稀释原理得分；子分把「懂不懂原理」与「记不记得出处」分开回答，机制仍是纯对比 |
| 判分/出题全文字，不写 scripts | 高自由度 | 要点提取与三分类是模型工作；唯一确定性检查（文档完整性）放 run-tests.mjs |

## 验收条件

| 编号 | 条件 | 类型 |
| --- | --- | --- |
| AC-1 | 考题为两道自然形态（概念题+应用题），题面无任何评分维度/结构/格式提示 | manual |
| AC-2 | 臂 A tool_uses=0（非零作废）；臂 B tool_uses>0 且答案含来源链接（否则参照无效重跑）；搜索通道全部耗尽时本次测量作废，不以无搜索答案冒充 | manual |
| AC-3 | 判分按固定公式（一致÷(一致+偏差+缺失)×100%），三分类逐条成表，含原理/出处子分 | manual |
| AC-4 | 报告含百分比、分级、明细表、子分、A 校准注记、B 信源清单 | manual |
| AC-5 | run-tests.mjs 全绿：frontmatter 合法（name=目录名、description 为名字式中英双语）、必需章节齐全、无 TODO 占位残留 | script |
