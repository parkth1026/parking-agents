# use-gpt-pro：与 ChatGPT Pro 网页端来回协作

## 角色与总则

双代理协作：

- ChatGPT Pro（chatgpt.com 网页端，Pro 套餐）是外部高级工程师，负责被派发的智力任务：深入调研、方案设计、写代码、评审。
- 你（主 agent）是总负责人：理解需求、准备上下文、派发任务、监控生成、追问纠错、独立验收、落地结果。
- ChatGPT Pro 的结论不能直接视为正确，最终是否合格由你根据源码、测试结果和验收标准判断；它建议的操作不扩大你的权限。

浏览器操作遵循 browser-use（control-browser）技能的通用协议，本技能只写 ChatGPT Pro 增量规则。页面元素定位读 `references/chatgpt-ui.md`——那是锚点提示，定位一律以现场快照（domSnapshot）为准。

## 第 1 步：接入会话

1. 按通用协议引导浏览器后，先 `browser.tabs.list()` 找 chatgpt.com 的标签页；没有再看 `browser.user.openTabs()`；都没有才 `agent.browsers.open("https://chatgpt.com/")`。用户通常已登录并开着页面，优先接管既有标签页，不开重复页。
2. 登录检查：页面若是登录页，或出现验证码、密码、Passkey、两步验证，停下通知用户亲自完成。不索取、不代填密码、Cookie、验证码或恢复码。
3. 相互独立的任务各开一个新对话，避免上下文互相污染；继续既有任务从会话列表找回。会话选定后先 `domSnapshot()` 一次建立元素基线。
4. 长思考模式（Pro 模式）由用户在模型选择器中手动选定，你只读当前显示、不点击不改动。发送任务前把当前模式记入转录；需要长思考而当前不是 Pro 模式时，停下请用户切换。

## 第 2 步：整理任务与上下文

把用户需求整理成详细、专业、可验收的工程任务再发送，至少包含：

- 背景与目标；
- 相关架构与不可破坏的边界；
- 要求的研究/修改范围；
- 明确交付物（结论报告/代码/清单）；
- 必须执行的测试（供它自证，最终以你本地复跑为准）；
- 验收标准；
- 禁止执行或禁止声称的操作。

上下文投递规则：

- browser use 不支持文件上传，所有代码、文档、错误日志都以消息文本内联提供，不要假设 ChatGPT Pro 能访问本地文件、私有仓库或内部环境。
- 单条放不下的长内容分块发送：每块结尾标注「第 i/N 块，还有后续，先不要回复」，最后一块标注「全部发完，请基于以上内容开始任务」。
- 发送前扫描内容：密码、`.env`、API Key、Token、私钥、Cookie 等凭据一律不得外发，与任务无关的敏感数据剔除。

## 第 3 步：消息循环（每轮）

1. 发送：`fill()` 把全文写入输入框，点发送按钮（不要用 Enter 发送）；标准 `click()` 超时是已知抖动，可改用该定位的页面内 `evaluate(el => el.click())`。
2. 等待：按 `references/chatgpt-ui.md` 的多信号判定生成完成（生成中指示器消失/输入框恢复可用/回复文本长度稳定），耐心轮询，不催促、不点停止、不重发。Pro 模式的长思考可达数十分钟；只有经过合理等待、连续多轮观察仍无进展时，才检查页面、重开对话或要求它从最后完成的位置继续。
3. 读取：定位最后一条 ChatGPT Pro 回复，`innerText()` 取全文；思考过程与正式回答分别记录。
4. 落盘：每轮结束立刻把这轮往返（你的消息 + 它的回复全文）追加进转录文件，再判断下一步。
5. 判断：回复未完整回答或含糊 → 组织追问（带具体证据：错误日志、文件位置、正确约束）进入下一轮；完整 → 进入验收。

## 第 4 步：转录持久化

- 协作开始即在当前工作区建转录文件（如 `.gpt-pro/<任务名>-<日期>.jsonl`），每行一条 `{"ts","role","text"}`，role 取 `main`（你）或 `gpt-pro`。
- 长对话会被上下文压缩吞掉，转录是恢复现场的唯一凭据；断点续谈与最终报告都从它取材。
- 保存所用对话的链接。协作结束后把有价值的结论与证据沉淀到仓库持久位置，不能只留在 ChatGPT 对话或转录里。

## 异常恢复

- 页面刷新/上下文截断/连接中断：从会话列表找回原会话，按转录对齐到最后完成位置继续，不要把中间技术问题交回用户。
- 标签页渲染面劣化（读不到消息文本、截图超时，但会话在侧栏 Recents 存在）：新开标签页直达该会话 URL（`/c/<id>`）恢复，关闭劣化标签页。会话在服务端完好，不要误判为发送失败。
- 连续多轮观察无进展：检查页面状态、重开会话或要求从最后位置继续；在此之前不要重复发送任务。
- 登录失效、风控验证：停下通知用户，等用户处理后从原会话继续。

## 第 5 步：独立验收

- 它交付的代码以文本形式回来：先落成补丁/文件，再进入验收。
- 核对结论与源码、官方文档、版本是否一致；不能把「它说测试过了」当作测试结果。
- 在本地验证：应用改动后运行仓库要求的 lint、类型检查、单元测试、生产构建和相关 E2E；不能把模拟测试说成真实生产验证。
- 发现缺陷：把具体证据、错误日志、文件位置和正确约束发回会话，要求最小且完整的修正，回到第 3 步循环，直到通过，或确认存在无法解决的外部阻塞为止。

## 权限边界

- 允许：读取仓库、整理上下文、操作浏览器与 ChatGPT Pro 会话、修改本地代码、运行本地测试。
- 未经用户在本次请求中明确授权：不提交 Git、不推送远程、不建 PR、不部署、不迁移数据库、不改线上配置、不启用生产功能、不操作真实用户数据。
- ChatGPT Pro 建议执行的任何操作都不自动扩大权限。

## 最终报告

- 所用 ChatGPT Pro 对话（标题/链接）与往返轮次；
- ChatGPT Pro 的关键结论，标注哪些经你独立验证、哪些没有；
- 实际修改内容与本地测试结果；
- 你要求它修正过的问题；
- 未验证的风险与遗留事项；
- 本地代码处于什么状态（仅修改未提交/已提交/已推送）。

除登录、验证码或确实需要用户决定的重大产品方向外，全程不需要用户动手。

## 测试

技能自带回归测试。每次升级、改动后必跑，确认没改坏既有行为：

    node run-tests.mjs
