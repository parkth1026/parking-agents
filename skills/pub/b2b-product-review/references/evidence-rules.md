# 证据规则：分级、不越级、阶段标准与决策出口

提炼自源报告 §02/§06/§07/§10。核心：先问「这个事实究竟证明了什么」，再问「还差什么」。

## 先定义失败：五个不能混淆的问题

没有事先约定的目标，团队既可以永远宣布成功，也可以事后把一切解释成失败。审查前先确认方案要接受的检验属于哪几项：

| 概念 | 含义 | 不能等同于 |
| --- | --- | --- |
| 用户价值未成立 | 目标用户在真实条件下得不到其重视的结果，或不愿选择该方式（价值也包括乐趣、表达、美感、信任） | 技术不先进 |
| 商业可行性未成立 | 收入、获客、交付、成本与现金条件达不到约定目标 | 当下还没盈利；没人付费 |
| 战略回报未达标 | 产品有价值甚至有利润，但满足不了该组织的规模、资源或组合目标 | 对所有团队都是坏生意 |
| 执行或治理失效 | 承诺的任务、质量、进度、风险控制或用户责任未兑现 | 由方向不确定性自动免责 |
| 实验被终止 / 产品被关停 | 一次决策或生命周期事件 | 原始决策必然错误；公司破产 |

## 成功定义先于审查

方案至少写清：服务谁、在什么任务和场景中、交付什么结果、与什么替代方式比较、达到什么经营目标、允许投入多少资源、何时复核。探索期可保留多个候选，但每次具体实验都要有明确检验对象。缺失时在报告中标出并给建议稿。

## 决策评价两原则

- 结果不好，不必然是坏决策：合理信息、有限投入、明确风险下的探索即使停止，也可能保留了资源并排除了不佳选项。评价看当时可得信息。
- 结果暂时好，不必然是好决策：关系订单、补贴、幸运时机都可能带来收入。继续检查可重复性，不把短期结果当成所有假设已通过。

## 证据不能越级：七类矩阵

证据不是可以不断「升级积分」的单轴阶梯——理解问题、完成任务、支付意愿、复购和规模化是不同命题，一个强证据不能自动替另一个命题作答。

| 观察或证据 | 主要支持的命题 | 尚未支持的命题 | 下一步有区分力的验证 |
| --- | --- | --- | --- |
| 真实经历与现有做法 | 问题存在、如何发生、现有方案哪里不足 | 问题优先级、方案有效、愿意付费 | 观察近期任务；比较替代方案与当前损失 |
| 主动投入（数据、时间、人员） | 愿担一定探索成本；可能获得真实试用条件 | 采购预算、长期使用、单位经济性 | 明确试验范围、责任人、决策路径与验收标准 |
| 独立完成真实任务 | 在已测人群和条件下具有可用性或任务价值 | 其他人群可复制、会付款、长期稳定 | 换真实输入与参与者，测完整流程和下次选择 |
| 明确价格与边界下的付费 | 特定交易条件下存在支付意愿 | 正常渠道可获客、标准化交付、长期留存 | 记录折扣、关系、额外服务；验证下一次同类交易 |
| 自然需求再次发生时继续选择 | 价值可在特定场景中重复；客户对再购有信心 | 更大市场可触达、增长后经济性仍成立 | 按同批用户、渠道和任务拆分，观察续购与替代选择 |
| 多批次销售和交付复现 | 部分商业与交付条件可重复 | 所有行业可扩张、所有客户均适配 | 检查新客群、渠道饱和、成本尾部和异常需求 |
| 按真实口径形成经济与现金记录 | 成本和回报在所测范围内有可核查基础 | 未来永久成立、依赖变化不会破坏模式 | 持续观察；关键条件变化时重新验证 |

## 三个不能混淆的判读

- **未知 ≠ 失败**：尚未观察到年度续购 → 继续等待适当周期或找能提前验证的中间条件，不能直接判失败。
- **未知 ≠ 通过**：只完成技术演示、尚未验证采购 → 采购标为未知，不能借用技术证据补齐。
- **局部通过 ≠ 全链通过**：客户付费但每单依赖大量特殊服务 → 成交可能成立，标准化和经济性仍需分别验证。

## 「客户不买」先分诊原因，再决定是否加功能

以下都是待区分的假设，不是事实清单；客户给出的原因也可能不完整。没观察到下一步动作时，结论保持「证据不足」，不选便于继续开发的解释。

| 可能障碍 | 先看什么 | 更接近问题的动作 |
| --- | --- | --- |
| 没触达正确人群 | 渠道、触达对象与实际任务是否匹配 | 调整定位、渠道或筛选，而非立即加模块 |
| 有问题，但不够重要 | 最近何时发生、后果、优先级与替代做法 | 重估目标问题或触发时机 |
| 认可价值，但切换太难 | 数据迁移、学习、风险、兼容、组织协调 | 缩小切换范围，明确迁移与恢复路径 |
| 用户愿意，购买链条不成立 | 谁预算、谁审批、谁担风险与实施 | 解决责任与采购路径；必要时重选客户 |
| 体验或质量不足 | 真实任务失败位置及最终结果 | 针对具体失败修复；新增功能只是选项之一 |
| 价格或包装不适合 | 报价条件、价值感知、使用风险、替代价格 | 测包装和收费单位，同步验证自身成本 |
| 真缺某项关键能力 | 同类客户是否因同一缺口无法完成任务 | 补能力并检验行为是否随之改变 |

## 六阶段否定标准

既防盲目扩张，也防用成熟业务指标扼杀合理探索。阶段是决策结构，不是行业统一流程：技术、市场与交付验证可以并行，早期也可以返回重做；判错配只看一件事——是否用某一阶段的成绩越级申请另一阶段的资源，不因并行验证本身判越级。

| 阶段 | 需要回答 | 适合的证据 | 不宜提前要求 | 合理决策 |
| --- | --- | --- | --- | --- |
| 探索机会 | 哪些变化值得关注？哪些问题有足够大的可能性？ | 候选行业变化、问题证据、替代方案与最不确定条件 | 付费客户；现有技术全部用上 | 保留候选、定向调查、排除明显不合适方向 |
| 验证价值 | 某类用户在某项任务上是否确实更愿选择新方式？ | 真实任务比较、用户行为、输入约束和结果验收 | 完整平台、全自动交付、全市场覆盖 | 保留或改变方案；必要时重选问题 |
| 验证交易 | 购买、部署、验收与付款如何真正发生？ | 真实采购条件、价格接受、责任链条和替代选择 | 机械套短期成交指标；但中间信号不可冒充订单 | 继续交易验证、调整商业包装或目标客户 |
| 验证重复性 | 同类用户能否以相近方式获得同类结果？ | 多次独立交付、自然周期复用、异常成本和用户成功路径 | 一次优质试点外推；要求零服务 | 固化边界、选细分市场、检验有限扩张 |
| 扩大经营 | 触达、交付与经济性在更大范围内是否维持？ | 不同批次与渠道结果、资源压力、现金、质量及依赖风险 | 原样本指标直接外推到新市场 | 扩大、限速、收缩或重新定位 |
| 成熟与退出 | 继续投入是否仍优于替代用途？如何负责地延续或结束？ | 变化后的需求和成本、战略价值、迁移与服务责任 | 存量收入自动当成未来价值；只看短期利润 | 维持、整合、迁移、出售或关闭 |

## 五选项决策出口

评审不是只有「继续」与「砍掉」两个按钮：

1. **继续投入** — 关键证据加强，风险在约定范围内；说明下一步扩大到什么边界。
2. **限额取证** — 最重要的条件仍未知，但存在有区分力且成本可接受的验证。
3. **改变路径** — 目标价值仍有依据，当前方案、渠道、客户或模式出现反证。
4. **暂停等待** — 关键外部前提未成立；明确恢复触发条件，而非无限待定。
5. **负责退出** — 继续取证或经营的预期价值不足以支持下一笔投入；安排用户与资产收尾。

## 阈值纪律

- 阈值事先约定：对象、样本来源、质量要求、观察周期、成本上限、严重风险条件。
- 环境变化确需改阈值：先记录理由与新证据，不能悄悄为已知结果移动门槛。
- 未知事项不计作通过；高后果风险不能被其他维度的好成绩「平均掉」。
