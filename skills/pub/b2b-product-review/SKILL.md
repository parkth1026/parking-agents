# B 端产品方案逆向审查

对一份 B 端产品方案（B2B / B2G、标品）做失败预演式审查，同时以成功产品的证据形态做正面对照。产出服务于下一个投入决策（继续 / 限额取证 / 改向 / 暂停 / 退出），不是为了列全风险清单，更不是给方案打分——审查的价值在于找出「一旦不成立就需要改路」的条件，让下一笔更大的投入建立在更可靠的依据上。

## 工作流

### Step 0 界定审查对象与阶段

- 确认本次审查对应**哪一个明确决策**（新功能、进新行业、扩团队、拓展渠道、结束产品）。一次只审一个决策；材料混杂多个决策时先向用户确认主决策，其余列为未覆盖。
- 确定方案所处阶段（六阶段之一）：探索机会 / 验证价值 / 验证交易 / 验证重复性 / 扩大经营 / 成熟与退出。阶段决定否定标准，定错阶段整个审查口径就会错。
- 检查「成功定义」是否事先约定（服务谁、任务场景、交付结果、对比替代、经营目标、投入上限、复核时点）。缺失是审查发现之一，在报告中标出并给建议稿供用户确认。

### Step 1 证据盘点：每个主张证明了什么

读 `references/evidence-rules.md` 的七类证据矩阵，把方案的关键主张逐条映射到证据类型：

- 标出「实际支持的命题」与「被用来支撑的命题」之间的越级之处（如把赞美/意向当需求证据、把技术演示当采购验证）。
- 三个判读铁律：未知 ≠ 失败；未知 ≠ 通过；局部通过 ≠ 全链通过。
- 为最支持方案的事实各提一个竞争性解释（关系订单、补贴、选择性样本等）。

### Step 2 逐层审查 18 类机制

读 `references/mechanisms.md`，按 A→F 六层逐条核对，每条输出：

- 状态四值之一：`未知 / 证据不足`、`初步支持`、`出现反证`、`本阶段不适用`（附理由）。
- 一句依据，引用方案原文或既有证据；找不到依据就保持未知，**不编造、不把「方案没写」当「方案错了」**。
- 命中预警的条目，先过该条「反面提醒」确认不是机械套用，再定状态（例如早期人工交付本身不是失败证据）。

### Step 3 适配：阶段、产品类型与正例对照

- 用 `references/evidence-rules.md` 的六阶段表检查两个方向的错配：是否用上一阶段的成绩越级申请下一阶段的资源；是否用成熟期指标（如日活、短期成交）扼杀探索期方案。
- 按方案的产品类型读 `references/context-adjustments.md` 调整证据口径（B2B 采购链、消费自然复用、AI 任务验收等）。方案含 AI 能力时必查四种口径偷换。
- **正例对照**（B 端方案必做）：读 `references/positive-signals.md`——判定方案主张的成立层级（生意 / 产品 / 自助）与证据实际支持的层级；逐项过八课决策关口，通不过的关口即候选关键假设；方案引用成功案例时用案例卡核对其「不能照搬」边界（如免费入口≠无销售成本、平台业务规模≠公司收入）。正例学的是证据形态，不是收入数字与计价方式。政企（B2G）客户的额外边界见 `references/context-adjustments.md`。

### Step 4 聚焦：选出最能改变决策的假设

从 18 条中挑 2-3 个「一旦不成立就需要改路」的条件，不给全部风险平均篇幅。每个假设写清：

- 竞争性解释
- 有区分力的验证（真实输入、对照、观察周期）
- 通过 / 反证 / 停止条件
- 负责人与下一次决策日期（方案里有则引用，无则标待定）

验证设计可参考 `references/evidence-rules.md` 矩阵的「下一步有区分力的验证」列与「客户不买」分诊表；「客户不买」先分诊原因，加功能从来不是默认答案。

### Step 5 决策建议

五选一：继续投入 / 限额取证 / 改变路径 / 暂停等待 / 负责退出（定义见 `references/evidence-rules.md`）。附理由与资源边界。核心判断依据：**证据是否在变强，投入是否在持续升级**——最需要警惕的不是某次实验没成功，而是证据没变强投入却升级、结果没改善解释却更完整。

### Step 6 产出报告

严格按 `references/report-format.md` 的模板与词表输出。

## 铁律

- 这不是打分器：状态统计不是健康分数，「初步支持」不等于问题永久解决；18 类机制无统计权重，不能相加成失败概率。
- 未知事项不计作通过；高后果风险（安全、数据、现金、信任）单独点名，不能被其他维度的好成绩平均掉。
- 每条命中先过反面提醒——本技能最大的失败模式就是变成「逢方案必风险」的挑刺清单。
- 正例对照学证据形态不学结果数字：案例的「不能照搬」与「可迁移经验」同权重；成立层级判定只用三层词表（生意 / 产品 / 自助）。
- 审查自身的证据也适用不越级：结论的每句话都要能指回方案原文或用户提供的证据。
