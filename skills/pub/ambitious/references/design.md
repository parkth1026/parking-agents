# design: ambitious

## 意图与触发场景

把用户随手写下的普通任务，改写成更有野心的版本——高度（目标背后的目标）、深度（顶尖从业者的做法）、广度（借其他领域的方法）——先输出方案、等用户确认再执行。源自 Felix Rieseberg 的「deeper version」四问（顶尖从业者会做哪些没被要求的工作 / 从哪些最原始的材料入手 / 具体用什么方法和工具 / 除了当事人还有什么能证明结果正确），扩成「三步野心 + 执行规则」的命令型技能。

- 触发模式：**手动专用**（双开关：SKILL.md `disable-model-invocation: true` + openai.yaml `allow_implicit_invocation: false`）。唯一入口是用户显式输入 `/ambitious <任务>`；不自动触发、不因语境招揽——任务改写是用户的主观决策，被模型自动套用等于劫持正常任务。
- 期望产出：一屏以内的方案，固定五项（改写后的任务 / 要用的方法和工具 / 野心目标 / 外部验证 / 需要用户提供的），结尾问用户按方案执行还是调整；确认后才动手，执行中每阶段跑外部验证。

## 设计取舍

- 纯 prompt、零脚本：全部价值在指令文本本身，没有可复用例程，不设 scripts/assets。
- 手动专用而非语境触发：会「把任务变大」的技能不能自作主张触发，双开关硬关。
- 先出方案等确认：野心放大必须留在用户手里，方案即确认界面。
- 「不扩大任务范围」「禁止角色扮演」写死在执行规则：前者防 deeper 滑成 bigger，后者防组队步骤滑向口吻模仿。
- 自由度全高（文字指令）：无脆弱操作需要护栏，判据交给验收条件而不是固定参数。
- 触发评测豁免：双开关硬关后无自动触发面，`trigger-evals.json`/`trigger-benchmark.json` 不适用（见 `docs/agents/skill-release.md` 手动专用例外）。

## 验收条件
| 编号 | 条件 | 类型 |
| --- | --- | --- |
| AC-1 | 手动专用：双开关全关（SKILL.md `disable-model-invocation: true` + openai.yaml `allow_implicit_invocation: false`），仅 `/ambitious` 显式调用 | script |
| AC-2 | 先出方案等确认：方案含五项（改写后的任务/要用的方法和工具/野心目标/外部验证/需要用户提供的），一屏以内，结尾询问是否执行 | manual |
| AC-3 | 方案里的方法与工具写具体名字（可指名的技术名词、命令、库），不出现「专业地」类空泛形容 | manual |
| AC-4 | 外部验证是执行者自己可运行的检查（测试/命令/基准/比对），不是主观判断 | manual |
| AC-5 | 任务抬升有判据：结果有人接着跟进→可抬一层；一次性小任务→保持原层级；抬升后目标能在当前环境验证，不空泛 | manual |
| AC-6 | 不扩大范围：交付更深/更高的版本，不添加用户未要求的无关功能 | manual |
