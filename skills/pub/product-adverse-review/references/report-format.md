# 审查报告模板

按此结构输出，词表固定；各节内容按方案实际填写，没有依据的字段保持「未知 / 待补」，不编造。

```markdown
# 产品方案逆向审查：<方案名>

> 审查对象：<文件名或方案描述> · 审查日期：<日期>
> 本次审查对应的决策：<新功能 / 进新行业 / 扩团队 / 渠道扩展 / 关停 / …，一次只审一个>
> 所处阶段：<探索机会 / 验证价值 / 验证交易 / 验证重复性 / 扩大经营 / 成熟与退出>

## 1. 成功定义核查

方案是否写清：服务谁 / 任务场景 / 交付结果 / 对比替代 / 经营目标 / 投入上限 / 复核时点。
逐项标注「已约定 / 缺失」；整体缺失时给出建议稿（供确认，不替代团队约定）。

## 2. 证据盘点：每个主张证明了什么

| 方案关键主张 | 现有证据类型 | 实际支持的命题 | 被用来支撑的命题（越级之处） |
| --- | --- | --- | --- |
| … | 真实经历 / 主动投入 / 独立完成任务 / 明确付费 / 复购 / 多批次复现 / 经济记录 | … | … |

对最支持方案的事实，各给一个竞争性解释。

## 3. 18 机制审查

每层一小节，逐条输出；只展开有实质内容的条目，其余可并行列出但不得省略编号与状态。

### A 方向与问题
| # | 机制 | 状态 | 依据（引用方案原文或证据；无则写「方案未提及」） | 反面提醒核对 |
| 01 | 先保住方案再找需求 | 未知 / 证据不足 | … | 不适用（未命中预警）/ 已核对，非机械套用 |

（B 证据与学习、C 采用与价值、D 商业与分发、E 交付与信任、F 组织与适应 同构）

**汇总**：初步支持 N · 出现反证 N · 未知 N · 本阶段不适用 N
（这是证据状态统计，不是健康分数；「初步支持」只对应当前证据，不等于问题永久解决。）

## 4. 最可能改变决策的假设（2-3 个）

按「一旦不成立就需要改路」排序，不给全部风险平均篇幅。

### 假设 1：<陈述>
- 竞争性解释：…
- 有区分力的验证：<真实输入、对照、观察周期>
- 通过条件 / 反证条件 / 停止条件：…
- 负责人与下一次决策日期：<方案里有则引用，无则标待定>

## 5. 决策建议

**建议：<继续投入 / 限额取证 / 改变路径 / 暂停等待 / 负责退出>（五选一）**

- 理由：…
- 资源边界：<下一笔投入的上限与绑定条件>
- 若选择「暂停等待」或「限额取证」：恢复触发条件 / 取证范围与决策日期

## 6. 本次审查未覆盖与证据不足

- 方案未提供而无法核查的信息
- 需要内部数据（交易记录、成本、决策日志）才能补上的判断
- 保持「未知」而非猜测的事项
```

## 输出纪律

- 状态只用四值：`未知 / 证据不足`、`初步支持`、`出现反证`、`本阶段不适用`（后两者和「不适用」都必须附依据或理由）。
- 决策建议只用五值：`继续投入`、`限额取证`、`改变路径`、`暂停等待`、`负责退出`。
- 依据引用方案原文时给出处（节名或引文）；审查报告不得把「方案没写」当成「方案错了」。
- 不引用无出处的通用失败率或行业定论（如「这类项目九成失败」）作判据；其他市场（尤其国外数字产品案例）或行业的实验与案例数据只能作待本地验证的类比，不能直接支撑本方案的状态判定。
- 本审查基于方案材料与用户提供的证据，不是系统调研或内部审计；结论也不构成对未来环境的保证——关键依赖、竞争或制度环境变化后应重开决策（见机制 18）。
- 高后果风险单独点名，不并入汇总计数了事。
