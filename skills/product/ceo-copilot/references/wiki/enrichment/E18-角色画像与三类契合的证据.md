# 角色画像与三类契合的证据

以报告 B18 的观点为范围。以下是选定原书段落的原创摘要；没有宣称通读或完整收录全书。所引原文选段随技能分发。页码均指指定 raw 版本的页锚点，不默认等于纸书页码。

## 报告观点的补全与校准

| 报告条目 | 原书核对后的解释与条件 |
|---|---|
| B18.theory.01 · 客户画像侧 | 客户画像分别记录任务、痛点和收益；B2B 交易中的推荐者、经济买方、决策者与使用者可能需要不同画像。[^s1][^s2] |
| B18.theory.02 · 价值图侧 | 价值图描述提供什么、缓解何种痛点与创造何种收益。应与客户画像对应，不能先将全部现有功能塞入。[^s3] |
| B18.theory.03 · 优先级与取舍 | 聚焦重要且尚未充分解决的痛点，以及真正有差异的收益。作者明确客户不会期待一个产品解决全部问题。[^s1] |
| B18.theory.04 · 三类契合 | 问题—方案契合包含对重要任务的证据及相应设计，但尚不证明客户在意该价值主张；产品—市场契合需实际价值与牵引，商业模式契合需可盈利和可扩张。[^s1] |
| B18.theory.05 · 嵌入商业模式 | 一个组织由不同角色组成。组织整体价值主张不能代替各角色的任务、收益和否决因素。[^s1] |

## 方法提示

以下为编者结合原书与报告整理的应用步骤，不冒充作者逐字流程。方法依据：[^s1][^s2][^s3]

1. 为影响采用与购买的角色分别写画像，先放事实。
2. 对任务、痛点和收益排序，再选择要解决的子集。
3. 将功能连接到痛点缓解或收益创造，为每条连接标出证据。
4. 分别检查三类契合，说明已支持到哪一层、下一层缺什么。

**预期产出：**针对当前决定的选择或验证方案；逐项说明事实、假设、观察结果和改变决定的条件。此产出格式是编者建议。

## 适用条件与误用边界

适用于价值主张设计和证据核对。原文 OCR 存在噪声；无法读出的图形与表格对应关系保留未知。

书中作者的机制解释与案例结果不能证明当前业务成立。应用时先核对角色、任务、资源、采购及交付条件。

原书用家庭说明：付款、影响、决定和使用可能由不同成员承担，因此消费品也可能需要多个角色画像。[^s1]

**迁移限制：**这是书中说明性示例，未给出某品牌销量或效果；不能包装为历史成功案例。
