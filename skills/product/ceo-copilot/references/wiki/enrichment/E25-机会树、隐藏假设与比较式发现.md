# 机会树、隐藏假设与比较式发现

以报告 B25 的观点为范围。以下是选定原书段落的原创摘要；没有宣称通读或完整收录全书。所引原文选段随技能分发。页码均指指定 raw 版本的页锚点，不默认等于纸书页码。

## 报告观点的补全与校准

| 报告条目 | 原书核对后的解释与条件 |
|---|---|
| B25.theory.01 · 持续接触用户 | 持续发现由实际建设产品的团队持续接触客户并做学习活动。持续频率不等于持续获取有效证据。[^s3] |
| B25.theory.02 · 结果—机会—方案—假设测试 | 结果、机会、方案和假设保持不同层次。方案产生作用以及机会推动结果的连接，也都是需要检验的假设。[^s1][^s4] |
| B25.theory.03 · 产品三人组 | 产品三人组应形成共同理解。故事地图先对齐每个参与者取得价值的步骤，再逐步识别假设。[^s1] |
| B25.theory.04 · 故事型访谈与可视化 | 故事型访谈保留具体情境，再将学习可视化。团队不能用自己熟悉的软件流程替代用户完整经历。[^s2][^s4] |
| B25.theory.05 · 比较而非单点论证 | 比较多个方案，再测试其最危险假设，通常比完整开发多个方案更适合早期学习。五类假设还包括可用性与伦理，不应只保留三类商业假设。[^s1] |

## 方法提示

以下为编者结合原书与报告整理的应用步骤，不冒充作者逐字流程。方法依据：[^s1][^s2][^s3][^s4]

1. 确定可影响的产品结果，按具体故事整理机会。
2. 对同一机会保留多个方案，先比较而非为单一方案辩护。
3. 画各参与者获得价值的步骤，逐步列需求、可用性、可行性、经营与伦理假设。
4. 沿机会树反推结果关系，再按重要性与证据缺口优先测试，更新树和下一步选择。

**预期产出：**针对当前决定的选择或验证方案；逐项说明事实、假设、观察结果和改变决定的条件。此产出格式是编者建议。

## 适用条件与误用边界

适用于持续产品发现。不要把作者的流媒体教学示例当成 Netflix 内部真实实验；次数与节奏需适应团队实际条件。

书中作者的机制解释与案例结果不能证明当前业务成立。应用时先核对角色、任务、资源、采购及交付条件。

## 代表案例与逻辑

### 1. 流媒体中的直播体育教学示例

“想看体育”不直接等于“加地方频道会提高续费”。原书拆出节目覆盖、观看意愿、额外观看时长、续费关系与版权成本等独立假设。[^s1]

**迁移限制：**这是作者构造的推演，不是已验证的经营结果；它说明需要检验方案到机会、机会到结果的连接。

### 2. 家庭找电影的访谈示例

故事包含电视被孩子占用、账号推荐偏向儿童、搜索电影不顺等情境；这些信息比笼统问是否喜欢流媒体更能定位机会。[^s2]

**迁移限制：**原书使用想象的访谈场景说明方法，不能冒充实地用户记录。



### 五类隐藏假设怎样落到步骤

| 类型 | 原书要检查的问题 |
|---|---|
| 需求吸引力 | 用户是否想做、愿意做，并信任你 |
| 经营可行性 | 方案能否创造足够业务价值，收入与维护成本如何对应 |
| 实现可行性 | 技术、组织、法务及安全约束是否允许实现 |
| 可用性 | 用户能否找到、理解并完成所需动作 |
| 伦理 | 数据和使用方式是否可能造成伤害，如何降低伤害 |

这些类别来自原书；它们帮助发现遗漏，不要求每次回答逐类列状态。[^s1]

编者应用：对每个用户步骤写必要行为，再沿“方案→机会→产品结果→经营结果”检查每条推理。例如增加体育节目是否带来额外观看、额外观看是否提高续费、增量收入能否覆盖内容成本，应分别取证。
