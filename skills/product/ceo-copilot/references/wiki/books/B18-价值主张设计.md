# 价值主张设计

## 核心主张与适用问题

价值主张画布把客户侧的任务、痛点与收益，同产品侧的产品/服务、痛点缓解和收益创造相对照。所谓契合是逐步建立的假设：先理解客户，再比较产品选择，最后以市场反应检验，不是填写完成即成立。

适用问题：哪些任务、痛点或预期收益对具体客户最重要？现有能力如何改变结果，客户是否确认这种改善值得采用或购买？

## 诊断层 v1–v8

V1 限定要改善的业务结果；V2 选定具体客户群；V3 描述任务情境、痛点和收益；V4 验证产品是否能产生目标改善；V5 检查客户价值是否连接到预算和支付；V6 将渠道、关系和采用负担纳入；V7 检验价值交付是否可重复；V8 判断优势与经济性是否能维持。本页直接支持 V2–V5；其他层不能由画布本身推出。

## 报告覆盖与缺口

报告概述了价值主张画布和三类契合，并提示将客户侧与产品侧连接。状态为主干概述、执行深度待补：客户研究、原型、测试和迭代没有展开成完整操作流程，章节与案例也未完整核对。

## 本技能如何用

将 B 的经营任务与 C 的终端任务分别建立客户剖面，避免把购买者的效率目标当作使用者的结果。把每个痛点/收益连接到可观察的行为或结果，再比较最小产品选择和简单替代。用 [[K06-价值主张画布]] 记录匹配假设，用 [[K05-JTBD任务与进展]] 补具体情境，并通过 [[K07-事实访谈]] 核对行为事实。

## 误用边界

客户访谈中的喜好不等于购买；团队写出的痛点不是客户事实。不要把所有任务和收益都列为同等重要，也不要把产品功能直接改写成客户收益。契合需要行为、使用结果和商业证据支撑。

## 锁定报告逐项知识

以下摘要以报告已有正文为范围，保留原书仍未收录的缺口。

### B18.theory.01 客户画像侧

客户画像先分别记录任务、痛点、收益，避免将自家功能混入客户事实。

### B18.theory.02 价值图侧

价值图将产品服务、缓解痛点与创造收益逐一对应客户侧。

### B18.theory.03 优先级与取舍

选择最重要的任务和痛点，不同时承诺满足所有问题。

### B18.theory.04 三类契合

问题解法、产品市场和商业模式契合对应不同证明层次。

### B18.theory.05 嵌入商业模式

价值画布放大商业模式的客户与价值部分，不能覆盖全模式。

### B18.action.01 给 B 与 C 各画一张

B 与 C 各建画布，管理端上线方便不能证明 C 理解、选对或降低不确定性。

### B18.action.02 每条连接加证据

每条能力到结果的联系单独留证，例如准备耗时和决策正确是不同因果链。

### B18.action.03 把弱相关功能删掉

无重要任务和证据对应的能力不因现成可做而纳入首版。

### B18.action.04 区分重要与愿意迁移

同时检查信任、迁移成本、数据和责任，严重痛点也可能难以采用。
