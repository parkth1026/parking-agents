# 转换与证据规则

## 输入分支

| 输入 | 处理 |
|---|---|
| 已符合契约的 JSON | 校验后直接构建；保留原字段 |
| 能力矩阵 Markdown / CSV / XLSX / DOCX | 提取，确定性映射表头，再核对全部条目 |
| 叙述 Markdown / Word / TXT | 读取正文；Agent 提取能力、状态、限制与出处；记录所有候选归宿 |
| XLSX 公式、合并单元格、隐藏工作表 | 保留原结构和警告；状态证据核实后采用，不自动补值 |
| XLS / PDF / 图片扫描件 | 通过宿主文件工具或相应 skill 读取；保留原来源与转换链；读取失败则报告 |
| 多材料 | 先列版本与来源；按同一能力身份对齐；冲突双方保留待定 |

支持不同输入形态不等于所有输入都能确定状态。以源材料为准，不用外部常识替缺失分类。

## 三档语义

“已具备”采用源材料对当前技术能力的明确判断。它不自动表示产品化、泛化、性能目标或生产交付。

“确定能做到”采用源材料或用户对技术可行性的明确判断。仅写“计划”“在研”“将上线”不够；记录为待定。

“可能做到”采用明确探索/可能性判断。未知、未提及、当前不具备和范围外不是同义词。

确定性脚本只处理有限的同义词，映射写入转换报告。其他词由 Agent 根据明示语义与上下文判读；有歧义就待定，不提升状态。

## 粒度与摘要

每个点描述一个能验收的能力结果。保留完整名称与原始证据，主图用最短动宾说明。

将“模型、算法、框架、工作流工具名”转换为能力结果时，必须能从源中找到实际输入与产出。若只有技术名，保留原名称并标明能力边界待确认。

将原文的否定、部分支持、输入限制、内部使用、未产品化、未实测或泛化未证保留在限制摘要。例：“内部台账解析通过，尚未接外部系统”可写为“解析业务台账 / 仅内部验证”。不能写成“企业业务自动化”。

保持判断强度。“不能承诺泛化”表示尚不能作出承诺，不等于“不能泛化”。“未验证”也不等于“不支持”。摘要既不能扩大肯定，也不能扩大否定。

上级能力和子能力分级不一致时保留冲突；不要按最成熟子项确定父级状态。同一能力合并时保留所有 sourceRefs。多来源自报不提升证据等级。

## 缺失与失败

材料不可读：记录读取失败与原因。状态不明：pending。当前不具备、放弃、范围外：excluded 并保留原话。关联资源无法读取：记录未读取，限制结论范围。

存在已明确能力时可生成工作稿，在图内 note 呈现待定数量；交付报告列出全部待定项。全部分类未知时只交付提取记录、待定清单和可填写数据结构；不生成伪造三档能力。
