# 设计与验收

## 意图与触发场景

触发模式：语境触发。用户提供文档或表格，要求转换为三档能力雷达、标准 JSON 或可双击查看的能力图谱。普通文档摘要和定量评分雷达不在范围内。

## 设计取舍

采用原始材料→提取记录→标准能力数据→独立 HTML 的单向流程。确定性脚本处理文件读取、结构校验和模板构建。Agent 处理叙述材料、能力粒度和限制摘要。记录没有足够依据的能力，不用三档分类掩盖未知。

模板在卡片上直接显示能力短说明和摘要；三档状态由圈层和卡片边框颜色表示。内嵌 JSON 支持双击离线打开。页面保留手动导入、编辑及保存最新 HTML 的入口。每次运行复制模板，保留模板本身。

使用 Node 内置模块。浏览器验证使用环境已有 Playwright，路径通过参数提供。分发包不包含用户材料、工作站绝对路径或评测工作区。

## 验收条件

| 编号 | 条件 |
|---|---|
| AC-1 | 读取 Markdown、CSV/TSV、TXT、JSON、XLSX、DOCX；保留来源 hash 和定位信息；无法读取时明确失败 |
| AC-2 | 规整表格可确定性转换；状态缺失、冲突、不具备与范围外分别记录；不把它们归入可能做到 |
| AC-3 | 标准数据通过统一契约校验；浏览器和 CLI 使用同一校验函数 |
| AC-4 | 构建产生标准 JSON 与内嵌数据的独立 HTML；新页面双击可见能力短说明，无外网依赖 |
| AC-5 | 完整名称、证据与限制保留；主图使用人工核对的最短说明与限制摘要 |
| AC-6 | 原始材料、已有输出及模板均不被覆盖；源码内容作为数据处理 |
| AC-7 | 自带回归测试覆盖多种输入、异常输入、状态映射、来源定位与模板构建 |
| AC-8 | 独立执行能力提取任务；验收结果绑定具体产物，不用结构校验代替转换质量 |
