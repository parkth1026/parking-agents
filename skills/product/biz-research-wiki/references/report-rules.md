# 调研报告与证据规则

## 先写有用的调研结果

报告首先回答原始问题。公司、产品和来源是分析对象，不是强制 Wiki 页面类型。
报告可独立阅读；章节按问题组织，不要求 wikilink、200 行上限或最低出链数。
同批对象使用一致的问题和比较口径。仅在确有独立主题时拆文件。

报告至少包含：问题与范围、截至日期、结论、逐项回答、依据、反证或冲突、未知与下一步验证。
页首结论不超过 5 句。事实附来源，判断附依据，不能把营销表述改写成客观结论。

## 事实、判断与未知

- 一句尽量只说一个事实。事实句后带相对来源链接与发布日；没有发布日时写抓取日。
- 普通 Markdown 链接指向 raw 来源文件。给出章节名或原文短摘录，便于核对；引用遵守版权限制。
- 写事实前，确认支持该事实的原文已归档。抓取时看到但未保存的内容不能只凭记忆引用；补存新摘录或降为待验证。
- 原文摘录与研究者整理备注分别标记。整理备注是派生文本，不是独立来源，不能单独用于证明事实。
- 只有局部摘录时，将否定表述限定为“本批材料未取得”。不要把摘录未出现推成整个网站不存在。
- 判断以“判断：”开头，写依据与适用条件。商业优势、付费动机和市场空间尤其需要区分事实与判断。
- 缺项写“查不到：具体项；查过的来源或检索范围”。公开渠道未找到，不等于不存在。
- 数字保留原数、币种、单位、时间和统计范围。计算结果标为计算，列输入与公式。冲突数字并列，不取平均。
- 价格、人数、收入和客户数注明截至日期。演示不是客户验收，潜在订单上限不是收入，厂商客户名单不是付款证明。

## 来源等级与独立性

每份来源在 manifest 使用以下固定枚举；报告使用对应中文说明。

| source_tier | 说明 |
| --- | --- |
| customer_or_regulator | 客户方或监管：客户公告、采购成交、工商与监管记录 |
| independent_media | 独立媒体：有独立采访或核实的具名报道 |
| attributed_restatement | 转述公告或利益相关方：新闻稿转载、投资方、律所等 |
| vendor_claim | 厂商自述：官网、新闻稿、厂商案例、供稿软文 |
| estimate | 数据站估算：方法不透明的收入、人数估算或目录转录 |

等级不能代替逐项判断。产品功能与官方定价可依据厂商官方材料；客户收益和实际付费需匹配相应证据。
不同机构仍可能依赖同一原始公告。用 origin 标记可识别的原始证据链 URL；未知时填 null 并说明。
关键事实缺少独立佐证时标“单一来源”。厂商自述占主要依据时，在结论前说明。

## 公司必答问题

1. 卖什么，卖给谁，谁付款。
2. 付款方为什么付钱；哪部分有客户证据，哪部分只是推断。
3. 怎么卖，怎么收费；渠道、计价方式和公开价格。
4. 多大；客户数、收入、员工数分别写口径，有哪个写哪个。
5. 靠什么站住；区分已证明的能力与待验证的竞争优势。
6. 近 3 年有日期的动作；融资、发布、改价、收购、转型和退出。

## 产品必答问题

1. 解决谁的什么问题。
2. 交付什么；形态与核心功能。
3. 怎么收费，多少钱。
4. 具名客户与案例；区分厂商案例与客户方确认。
5. 替代品是什么，差异证据是什么。
6. 近期变化；改版、改价和下线。

按主题增加共同问题。每道题保留未回答的子项，不用整节“查不到”掩盖已知内容。

## 主题报告

综合对象结果，回答主题问题，说明哪些判断可支持决策，哪些仍需验证。
横向对照至少覆盖对象、付款方/场景、收费与公开价格、付费证据、规模口径、主要未知。
每个事实格保留来源或链接到对象报告的具体章节。不强制每格 25 字，不把未找到价格写成免费或无。
跨对象结论列比较对象、比较条件和反例。不要据候选清单推断行业全貌。
