# 商业调研入库

把一句主题变成一批核实过的公司页、产品页，写进同一个行业知识库。库是给以后的 AI 用的：它先读 `index.md`，再只读要用的页。

知识库在 `wikis/industry/`，结构与校验用 `karpathy-llm-wiki` 技能，先读它的 SKILL.md。页面怎么写见 [page-rules.md](references/page-rules.md)。

## 四步

### 1. 定范围，出清单，等用户说开始

1. 从主题 Prompt 里读出：调研哪个行业或场景、付款方是谁、用户特别想知道什么。读不出的用最窄的理解，并写明。
2. 用少量检索（不超过 10 次 WebSearch）列出候选对象。先读 `wikis/industry/wiki/index.md`，库里已有的对象标「已有，更新」。
3. 把清单给用户：每个对象一行（名字、公司还是产品、为什么在范围内、新建还是更新），加本主题的自由节提纲与用量预估。
4. 用户说开始之前不批量调研。用户在 Prompt 里直接给了清单时，跳过第 2 项，仍然回显一次清单。

### 2. 批量调研

一个对象派一个调研代理，并行。给每个代理：对象名、主题 Prompt 原文、必答题、自由节提纲、page-rules.md。

调研代理的规则：

- 必须联网。只用 WebSearch 与 WebFetch。请求里不放邮箱、姓名等个人信息；站点要求自报联系方式的换来源。不用浏览器。
- 每个用到的网页存一份 raw 进 `wikis/industry/raw/articles/`。WebFetch 拿不到网页原样，存的是它的转出稿：尽量全文，不要自己压成摘要。文件头写 `url:`、`fetched:`、`note: WebFetch 转出稿`。存了就不改。
- 去查了但没拿到内容的网址（403、付费墙、空页），记在运行记录的「查过没拿到」里，不建来源页。
- 页面文字由代理读原文后写。不得用脚本拼页面。
- 查不到就写「查不到」，并写查过哪里。不编，不拿厂商自述当第三方事实。
- 结束时报：WebSearch 次数、WebFetch 次数、用时、token（平台不给就写未记录）。

### 3. 反思实锤

每张页另派一个没参与调研的核实代理，只做一遍，不循环：

1. 逐句拿页面对 raw。raw 是转出稿，照它核。对不上的句子删掉，或改成「待验证」。
2. 页首结论和每个数字，再找一个独立来源（不同机构、不是转载同一稿）。找到的补进来源；找不到的在句末标「单一来源」。两个来源说法不同时并列写，不取舍。
3. 把改了什么记在页面所在运行记录里：删了几句、标了几句、补了几个来源。

核实代理发现整页主要靠厂商自述时，照实在页首写一句「本页主要依据厂商自述」，照样入库。

### 4. 入库

1. 按 `karpathy-llm-wiki` 的 ingest 流程写页、更新 `index.md` 与 `log.md`。更新已有页时旧事实不删，新事实带新日期追加。
   `index.md` 的写法：按主题分组，每个主题下列综述页、公司页、产品页，一页一行带一句说明。全部来源页放在最后一节「## 来源页清单」里（校验器要求每页都在 index 里，所以不能移走）。查询时只读到这一节之前。
2. 本次调研末尾写一张主题综述页：这批对象放在一起能看出什么，链到每张页。综述页不设必答题，但必须有一张「横向对照表」，写法见 page-rules.md。往已有主题里加对象时，在这张表里加行，不重写。
3. 跑引擎校验器，改到 PASS。
4. 给用户一段话的结果：建了哪几页、更新了哪几页、每个对象的用量、哪些必答题答成了「查不到」。

## 运行记录

每次调研在 `wikis/industry/runs/<日期>-<主题短名>.md` 留一页：主题 Prompt 原文、对象清单、每个对象的用量、核实改动数、查过没拿到的网址。只留这一页，不建别的过程文件。

## 不做

不证明清单扫全了。不做盲扫、漏网率、隔离核查。不建验收报告。
