# 场景适配：产品类型、指标口径与 AI 产品

提炼自源报告 §08/§09。通用框架负责提问，具体场景决定证据口径与阈值——同样的「付费、留存、自动化」在不同业务中含义完全不同。

## 七类产品类型的审查侧重

| 产品类型 | 应优先检查 | 容易误判的地方 |
| --- | --- | --- |
| 企业级 B2B | 使用者—买单者—审批者—实施者关系，数据接入、验收、回款、续约和销售成本 | 少数大单不能自动证明标准化；长期采购不能简单视为没有需求。成立层级判定、八课关口与案例对照见 `positive-signals.md` |
| 自助消费与创作产品 | 触达、首次价值、自然复用、付费转化、体验与退出成本 | 乐趣、审美、表达与身份价值也是真实价值，不能只用省钱省时解释需求 |
| 开发者工具 / 开源生态 | 真实工作流中的采用、接入与迁移、维护负担、谁为哪一层能力付费 | 下载量和关注数不是生产采用；免费核心不必然无法商业化 |
| 多边平台 / 市场 | 供需双方是否同时获得价值、局部交易密度、履约、补贴去除后的表现 | 单边用户数不是网络效果；总交易额不等于平台收入或贡献 |
| 硬件 / 深科技 / 生产系统 | 技术里程碑、可靠性、制造与维护、关键供应、资金周期和实际部署条件 | 不能套消费应用的短期收入门槛，也不能只靠技术突破推定产业化成功 |
| 内部工具与平台 | 组织结果、真实使用、维护成本、替代工具、接入收益和跨团队责任 | 被强制使用不等于有价值；无外部收入也不等于没有回报 |
| AI 功能 / Agent | 任务验收、错误成本、权限、依赖、监督、重试与成本波动，外加所属业务类型的全部检查 | AI 是技术条件，不是豁免商业验证的类别；本地或云端部署本身都不保证价值或护城河 |

## B2G / 政企客户的额外边界

两份源报告的案例与调研均不含政企采购特有机制——本节是适用性判断，不是实证结论；政企方案照常走全部审查流程，另加：

- **框架部分适用、力度调整**：角色链更长（使用者、主管单位、财政、评审专家、集采平台），购买链更慢，试点结论向正式预算的外推更弱——机制 08（角色链）与 17（过早扩张 / 无限试点）的检查加强；但否定标准不因采购周期长而更苛刻（周期本身是行业常态，不是方案的失败信号）。
- **无来源支持的事项一律标「需专项验证」，不得当结论写**：预算年度与专项资金窗口、招投标 / 比选 / 单一来源的法定形态、等级保护与安全审查等合规前置、国产化替代要求、验收与决算流程——这些可能改变整条交付路径（机制 15），但本技能知识库没有证据基础去断言它们在本方案中的形态。
- **竞争性解释权重上调**：政企首批订单中「关系 / 政策窗口」的竞争性解释权重高于 B2B（机制 04/05）；首单标杆 ≠ 可复制采购路径（机制 13/17），重复性证据要求更严。

## 指标口径：防「看起来增长」

每次决策只挑少量能区分关键假设的结果指标，再配必要的质量、成本和风险护栏；不要求监控全部指标。

| 指标 | 应怎样定义 | 主要误用 |
| --- | --- | --- |
| 合格触达 | 被真实触达且符合目标条件的对象；明确去重、渠道及时间 | 曝光、所有线索与目标客户混在一起 |
| 首次价值达成 | 符合条件的新用户中，指定时间内完成可验收任务的比例 | 注册、登录、点击或生成一个结果自动等于达成价值 |
| 完整任务结果 | 从输入准备到交付验收的耗时、成本、质量及失败后果 | 只测最精彩的子步骤；对照任务和质量要求不一致 |
| 自然周期复用 | 再次出现同类需求、且有观察条件的用户中重新选择产品的比例 | 可靠识别需求机会才能这样算，否则报告可观测的重复使用及其局限 |
| 留存 / 续购 | 按首次进入时间、渠道、客群与任务分组定义特定周期的继续使用或购买 | 套通用日活或固定留存阈值；订阅未取消不总等于持续有价值 |
| 交易转化 | 符合明确条件的商机中，进入约定采购节点或实际成交的比例 | 授权试点、意向、合同、验收、开票与回款不分开记录 |
| 单位贡献 | 净收入减去清晰定义的直接变动成本，口径一致 | 冒充营业利润；获客、固定团队和会计分摊不另行说明 |
| 获客成本与回收 | 按可归因新客批次计算获客投入，再观察贡献回收 | 混合口径与边际口径不分；小样本假装精确；漏销售人工 |
| 交付复用 | 同类客户核心流程的共享程度及配置、定制、人工的实际投入 | 总交付速度改善自动证明自助；后台人工不如实记录 |
| 风险与恢复 | 按严重程度记录错误漏出、异常频率、恢复时间和补救责任 | 平均成功率代替高后果事件检查；零次事故证明零风险 |
| 现金需求 | 按真实回款与支出时间观察净流出、预收、账期、库存和合同义务 | 利润、收入和现金混为一谈；增长情景不重算资金占用 |

## 收入 ≠ 盈利 ≠ 现金

- 单位贡献为负、或虽为正但覆盖不了获客与固定投入，都可能是「账面增长、实际恶化」；库存和回款可使企业在账面增长时面临现金压力。
- 分开检查：单位贡献、固定费用、获客投入、回收周期、现金需求；用悲观/基准/较好三情景，不用单点估计。
- 可以暂不赚钱，但需要可验证的改善机制、资源边界和目标口径——规模越大亏损越大的模式不会仅因增长自动修复。
- 项目收入不能按软件毛利预测；人工短期属固定成本时，贡献口径与完全成本口径分开列示，不重复扣除。

## AI 产品：四种口径偷换

| 容易混淆 | 审查方式 |
| --- | --- |
| 「多试几次总有一次成功」 ≠ 「能稳定交付」 | 明确重试次数、成功判定和用户能否承受等待；所有尝试与人工挑选计入成本 |
| 「代理说已完成」 ≠ 「任务结果已发生」 | 检查真实文件、记录、环境状态或可验收成果，不只看回答文本 |
| 「模型分数提高」 ≠ 「产品价值提高」 | 固定一组真实任务，比较质量、时延、成本、核验和恢复；再观察采用与付款 |
| 「人工生产步骤消失」 ≠ 「全流程无需人工」 | 分别披露采集、输入整理、监督、结果验收、售后和异常处理；不偷换产品边界 |

## 机会成本与退出责任

- 「还能做」与「值得继续投入」是两道题：把维持、收缩、迁移、出售或关闭与其他投资用途比较，记录可迁移资产和用户承诺。
- 继续投入的理由如果只剩历史投入和少数忠实用户，是预警；战略已改但考核没改，是预警。
- 战略价值也需要命名、责任人和可检查的结果；退出质量（数据迁移、余额、服务责任）是产品责任的一部分。
