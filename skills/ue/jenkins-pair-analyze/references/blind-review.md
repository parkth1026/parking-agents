# 盲评流程（评分信度测量）

对当前 rawDir 全量知识文件生成**去分副本**，由未参与原评分的人（或 agent）独立按四维打分，
与原分对照计算信度指标。用途：补「评分信度无测量」的缺口，为 scoring.md 的校准触发条件
（一致率 < 0.8）提供信号源。首次基线落在
`docs/reports/scoring-audit-2026-08-16/blind-review/`；复用时按本流程在新审计目录重新现场生成，
**不设常驻脚本**（一次性任务不值得维护面）。

## 生成盲评包（现场生成）

落点：`docs/reports/<审计目录>/blind-review/`（gitignore 已忽略，不入库）。用一次性 node 代码
生成四件东西：

1. `set/BR-{NN}.md` —— 每份知识文件一份去分副本：
   - 文件名换成编号（剥离文件名暗示，编号随机洗牌防按名猜测）；
   - frontmatter 删除 `score:` 与 `result:` 两行（`result` 含 `failure:score=N` 会泄露）；
   - 正文原样保留（正文不含分值）。
2. `key.md` —— 编号 ↔ 原文件名 ↔ 原分/原落档映射，**盲评完成前任何人不得打开**。
3. `scoring-sheet.md` —— 四维打分表，每文件一行（Info/Diff/Commit/Reuse + 总分 + 落档建议）。
4. `procedure.md` —— 操作流程（本文档针对当次包的操作化版本）。

## 盲评纪律

- 打分期间**不得回看原分**：不打开 `key.md`、不去 rawDir/wikiDir 看原文件、不查旧账本。
- 打分口径只用 [scoring.md](scoring.md) 的四维定义（含等效强归因链与 Commit 修复侧证据语义），
  不参考原文件落档结果。
- 操作者只填打分表；指标计算由执行 Agent 完成（不代填、不代算）。

## 指标口径（results.md）

- **逐文件 |Δ总分|** = |盲评总分 − 原总分|，全量列表。
- **一致率** = |Δ总分| ≤ 1 的文件数 / 总文件数。**< 0.8 触发 scoring.md 校准复审**。
- **四维差异表**：每维 |Δ| 的均值/最大值/分布，用于定位系统性偏差维度（某维普遍 ≥2 分
  偏差即系统性问题，需回改规则——那是新一轮契约，不在盲评当轮顺手改）。

## 结果落盘

`blind-review/results.md`：打分表（编号、盲评四维与总分、原四维与总分、|Δ|）、上述三项指标、
盲评人注记（哪些文件拿不准、为什么）。此文件是信度基线的第一手数据，后续校准复审引用它。
