各阶段详细说明
PHASE 0 配置加载 & 输入解析 始终执行

配置加载

  • 从 skill 目录读取 config.json
  • 解析路径：~/ → 展开为主目录；./ → 相对于 skill 目录；绝对路径直接使用
  • 用 Test-Path 验证所有路径，rawDir 不存在则自动创建
  • 创建临时目录 $env:TEMP/ue-error-solver

输入解析

  • 格式 1：完整 Jenkins URL → 直接提取 baseUrl / jobPath / buildNumber
  • 格式 2：任务名 + 编号 → 查询 Jenkins API 递归展平并模糊匹配
  • 多个匹配时列出供用户选择；无匹配时要求完整 URL
输入

config.json + 用户提供的 Jenkins 构建引用

输出

解析后的 baseUrl、jobPath、buildNumber；验证后的路径配置

PHASE 1 下载并解析构建日志 始终执行

关键步骤

  • 用 curl.exe 下载控制台日志，文件名含时间戳防冲突
  • 大日志 (>500KB) 内存保留全量，磁盘保存过滤版
  • 通过 API 检查构建结果 (result / timestamp / duration)
  • 提取所有错误类型：C/C++ 编译、Clang、链接器、UBT/UHT、Cook、Blueprint、基础设施
  • 捕获完整错误块（含 note: 行、实例化链、代码指示行）
  • 分类分组：识别主要错误，标注级联错误
  • 提取构建命令（UBT 调用 / RunUBT.bat / Build.bat）
输入

Jenkins consoleText API 端点

输出

分类后的错误列表、完整错误块、构建命令

PHASE 2 多源诊断 始终执行

诊断来源（顺序执行）

  • 2.1 源码上下文 — 映射错误路径到本地 git 仓库，读取 ±15 行上下文，查看 git log 最近修改
  • 2.2 知识库搜索 — 搜索 wiki concepts / entities + rawDir + jenkins-log-auto-learning 历史，按评分判定置信度
  • 2.3 Epic UE 助手 — 使用 Invoke-EpicAssistantQuery 发送完整错误块 + 源码上下文（多个独立错误分别查询，新会话）
  • 2.4 网络搜索 — 不常见错误码、第三方插件、引擎版本迁移问题的补充来源

强制检查清单

  • 进入 Phase 3 前必须填写 4 步骤状态表（已完成 / 已跳过 + 原因）
  • 不可仅凭模型直觉跳过有条件步骤
输入

Phase 1 提取的错误块 + 分类结果

输出

各来源诊断结果、KB 评分、检查清单

PHASE 3 呈现诊断 始终执行

输出模板（中文）

  • 诊断：ErrorCode — FileName
  • 错误信息：原始错误消息
  • 根因分析：综合所有来源的确定性分析
  • 置信度：高 / 中 / 低
  • 证据：知识库 / Epic 指引 / 源码上下文 / Web 搜索
  • 修复建议：具体步骤和代码改动
  • 参考资料：Epic 文档、KB 文件、Web 链接
  • 证据部分必须与 Phase 2 检查清单一致
  • 多个独立错误分别呈现
输入

Phase 2 检查清单 + 所有来源结果

输出

格式化的中文诊断报告

PHASE 4 修复代码 可选 — 仅用户要求

触发条件

  • 用户提示中包含 "fix" / "repair" / "修复" / "解决" / "solve" 等词

关键步骤

  • 在 gitRepos 中定位错误文件并应用代码更改
  • 回读修改后文件验证语法正确性
  • 使用 Phase 1 提取的构建命令本地重新编译
  • 编译失败时分析新错误类型，修订修复，最多重试 3 次
输入

Phase 3 的修复建议 + 本地源码

输出

修改后的代码文件 + 编译结果

PHASE 5 提交推送 可选 — 仅用户要求

触发条件

  • 用户明确要求 "commit" / "push" / "提交" / "推送"

安全规则

  • 始终先 git pull — 提交前拉取最新更改
  • 禁止 git push --force — 绝对禁止
  • 冲突或失败 → 通知用户并停止，不尝试破坏性变通

提交信息格式

  • fix({module}): {ErrorCode} - {brief description}
输入

Phase 4 修复后的文件

输出

git commit + push 结果

PHASE 6 知识积累 有条件 — Phase 4 成功后

触发条件

  • Phase 4 已执行 且 编译确认成功
  • 仅诊断（未修复）时不执行此阶段

关键步骤

  • 保存到 knowledgeBase.rawDir，文件名 {jobShort}-{buildNumber}-{ErrorCode}-{ShortDesc}.md
  • 检查 rawDir/details/ 中是否有重复，有则更新而非新建
  • 仅保存已验证修复 — 不保存推测性诊断

知识文件包含

  • Error Message / Root Cause / Fix / Evidence Sources / Epic Guidance / Prevention
输入

已验证的修复 + 全部诊断证据

输出

Markdown 知识文件（rawDir）

来源选择规则 (Phase 2)
步骤 来源 执行条件 跳过条件
2.1 源码上下文 始终执行 基础设施错误（OOM / 磁盘 / 网络无源码可读）
2.2 知识库搜索 始终执行 知识库目录不存在
2.3 Epic UE 助手 有条件 KB 评分 < 8 且为 UE 错误 KB 评分 ≥ 8（已有验证修复）；非 UE 错误（基础设施 / 第三方库）
2.4 网络搜索 有条件 KB < 8 且 Epic 未明确 KB 评分 ≥ 8；Epic 已提供明确修复方案；基础设施错误

知识库评分标准

1 – 4 分：仅关键词重叠
5 – 7 分：相同错误码 / 不同文件
8 – 10 分：完全匹配 + 修复段落
1 – 4 分
仅关键词重叠 → 继续查询 Epic
5 – 7 分
相同错误代码但不同文件路径，或修复不完整 → 继续查询 Epic
8 – 10 分
完全相同错误代码 + 相同文件路径 + 含修复段落 → 跳过 Epic (2.3)

诊断决策流

配置结构 (config.json)
jenkins.baseUrl
Jenkins 服务器 URL。示例：http://10.66.12.40
gitRepos
非浅克隆 git 仓库目录路径。用于读取源码上下文和应用修复。
knowledgeBase.wikiDir
精选 wiki 知识库路径（concepts + entities 子目录）。
knowledgeBase.rawDir
原始知识积累目录，新发现的已验证修复保存于此。

路径解析规则

~/...
波浪号展开为 $HOME
./...
相对于 skill 目录（config.json 所在位置）
D:/Git
绝对路径直接使用
临时目录：$env:TEMP/ue-error-solver — 存放下载的日志文件（带时间戳命名避免冲突）
环境变量：$env:JENKINS_USER / $env:JENKINS_TOKEN — Jenkins 认证（如已设置）
约束条件（12 条）
1
Jenkins 只读 — 绝不修改 Jenkins 配置或触发构建
2
禁止 force push — git push --force 绝对禁止
3
提交前 pull — git pull 必须在任何提交前成功
4
配置驱动路径 — 所有路径来自 config.json，不硬编码
5
UTF-8 without BOM — 所有输出文件，CRLF 换行
6
优雅降级 — Jenkins 不可达、Epic API 失败或知识库为空时继续使用可用来源并通知用户
7
仅保存已验证知识 — 编译确认修复有效后才保存到知识库
8
不静默提交 — 提交代码前始终通知用户
9
使用 curl.exe — HTTP 请求使用 curl.exe（非 Invoke-WebRequest），避免 Cloudflare 拦截
10
中文输出 — 诊断报告以中文撰写，技术术语保持英文
11
禁止纯模型诊断 — 每条诊断必须引用至少一个已执行来源的证据
12
认证假设已配置 — Jenkins 使用 env 变量；Git 凭据假设已在系统凭据管理器中配置
