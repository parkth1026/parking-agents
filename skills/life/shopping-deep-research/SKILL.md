# 硬证据选购调研

为高决策成本的实物商品做**循证式**选购调研。核心信念：排名只认一手销量与口碑数据；营销号"十大品牌"类榜单只能当线索，永远不能当结论。

**不适用**：低价标品（如纸巾）、纯比价搜券（用比价工具）、服务与虚拟商品。

## 流程总览

行业指标框架 → 指标化需求锁定（需求卡确认）→ 指标分级推硬约束 → 分级找证据 → 双口径排名 + 品牌画像 → 型号解码 → Top 5 综合推荐 → 留档

### 1. 行业指标框架（先调研后提问）

选购对象确定后、向用户提问前，先调研该品类的**核心指标体系**——国标/行标定义的测量项、头部评测机构的测试维度、行业报告的关键参数。每个入选指标回答三件事：

- **含义**：测的是什么（例：甲醛 CADR = 每小时输出的洁净空气量 m³/h）
- **影响**：决定哪方面体验、差多少能感知（例：CCM 决定滤芯寿命与长期持有成本）
- **读数**：好歹方向与量级感（例：坐姿桌面高 ≈ 身高 × 0.42；"对比度"1000:1 与 5000 万:1 不是同一量纲的比法）

指标分四档，后续问答、约束与推荐全部以此为分析框架，防止被参数表带偏本质：

| 档位 | 判据 | 后续用法 |
|---|---|---|
| 体验决定性 | 直接决定核心体验，有行业共识的硬门槛 | 一票否决候选 |
| 重要 | 同档位间明显拉开可感知差距 | 主要比较项 |
| 次要 | 对目标场景影响小 | 提及即可，不主导决策 |
| 营销虚指标 | 高数值无实义或量纲混用（如动态对比度、自封认证词） | 点破，不作任何依据 |

用户不一定知道这些指标——**报告必须含指标科普章节**（含义/影响/读数逐项讲清），这是用户校验推荐逻辑的共同语言；指标框架本身的信源按第 4 节分级标注。

### 2. 指标化的需求锁定（对话式收敛 + 需求卡确认）

一组问题 ≤5 问起步；关键信息仍有缺口就继续追问下一组，轮数不设硬上限。每轮末尾附「已锁定 / 仍待定」清单，待定项直接给分支结论，不空转确认。**场景问题用指标语言问**——把第 1 节的指标映射成用户答得了的场景问题（例：「玩 FPS/竞速吗？」→ 响应时间与刷新率升为重要档；「客厅白天看吗？」→ 亮度与防反光升档），不问抽象的「你有什么需求」。必问维度：

- **使用者**：谁用、几人用、身体参数（身高直接决定尺寸类硬约束）
- **场景与物理限制**：放置环境（墙面宽度、房间进深、电梯/房门尺寸）、使用组合（谁和谁同时用）
- **已有设备**：要配合的显示器/椅子/主机等（兼容性约束）
- **预算上限**：明确含不含配件
- **售后期望与品牌偏好**：保修年限/上门服务期望；有没有点名要避开的品牌
- **一票否决挖掘**：主动追问"有没有什么条件不满足就绝对不买"（例：家有小孩 → 最低高度/童锁；小房间 → 最大外形尺寸）

已有答案不重复问；不确定项标"待定"并给分支结论。

**需求卡回读**：访谈收敛后、进入调研前，输出一张需求卡（使用者/场景与物理限制/已有设备/预算/**指标重要性分级**/一票否决项/加分项/待定项）请用户确认或纠偏。用户不在线（自动化/评测）时不阻塞：需求卡照常落盘并标注"未经确认，按分支结论推进"。

### 3. 指标分级与硬约束推导

把第 1 节的指标框架与第 2 节的场景答案对齐——逐指标标定对本用户**重要/不重要**（用户确认或按分支结论），再把自然语言翻译成**可逐条核对的参数表**，区分两档：

- **一票否决项**：不满足直接淘汰，先筛后比（例：最低高度 ≤62cm、总宽 ≤193cm、承重 ≥100kg）
- **加分项**：满足更好，用于同档比较（例：USB 口、App 记忆、实木桌板）

尺寸类用通用人机公式推算（坐姿桌面高 ≈ 身高 × 0.42，站姿 ≈ × 0.62），标注为推算值。

### 4. 证据分级

| 级别 | 信源 | 用法 |
|---|---|---|
| A | 上市公司财报/招股书、国标行标文本、监管文书 | 可直接下结论 |
| B | 头部市场研究机构报告 | 可下结论，注明机构名 |
| C | 老牌独立评测媒体 | 作参考结论，注明可能的利益关联 |
| D | 电商榜单、门户/自媒体"Top N"榜 | **只当线索找 SKU，不进结论** |

企业自述（"销量第一""市占第一"）即使出现在 A 级信源里也要单独标"公司口径"。

### 5. 销量口径（一手数据）

- 用**平台在售 SKU 累计评论数**作销量代理：亲自抓在售清单页/榜单页，记录抓取日期
- 类目必须对齐：整桌 ≠ 桌面升降架，整机 ≠ 配件（品牌榜常混类目，弃用）
- 品牌榜存在缓存滞后与平台自营特权问题，只用于发现 SKU；排名一律用 SKU 评论数重算

### 6. 口碑口径

- 晒单关键词归纳：好评差评各在说什么，找重复出现的抱怨点
- 黑猫投诉/12315 类平台检索"品牌+型号"具体案例（可链接的才算数）
- 第三方横评的差评归纳，注明"非全量文本分析"

### 7. 双口径排名 + 品牌画像

- 排名**只**基于销量 + 口碑两个口径，每个结论旁明示证据强度
- 场景分开出榜（例：办公、电竞、家用是三张榜，不混排）
- 用户质疑排名时：承认证据不足的部分，降级或重查；不为原结论辩护
- 品牌榜旁附**品牌画像表**，补足排名口径覆盖不到的品牌级因素（逐项列，不进排名公式）：

| 画像因素 | 典型来源 | 口径标注 |
|---|---|---|
| 售后与保修 | 官网保修条款、售后政策（年限/上门/配件周期） | 官网口径标"公司口径" |
| 企业实力 | 财报/招股书营收与品类占比、自研产线 vs 代工 | A 级可直接引用 |
| 可靠性线索 | 投诉平台投诉量对销量比、评测机构故障率 | C 级，注明样本局限 |

- 画像只在同档品牌间作定性比较与推荐理由陈述，**不折算加权综合分**

### 8. 型号解码（胜出品牌）

- 先讲清该品牌命名规律（字母/数字/后缀含义），再列表
- **只列当前在售型号**，以一手抓到的在售 SKU（有评论数、有价格）为在售证据；评测里活跃但抓不到在售证据的旧款，明确标"未确认在售"
- 参数有出处冲突时并列写明，提醒以商品页为准

### 9. 结论与留档

- 输出顺序：需求卡（含指标分级与确认状态）→ **行业指标科普**（含义/影响/读数）→ 品牌榜（双口径排名 + 品牌画像表）→ **Top 5 型号综合推荐** → **下单前核对清单**（硬约束逐项 + "向客服确认"项）
- Top 5 综合推荐 = 硬约束匹配 + 双口径排名 + 品牌画像的**定性综合**（逐型号带依据链：哪条指标达标、什么口径的销量口碑、画像里什么因素加减分）；不做数值加权综合分，凑不满 5 个达标型号时如实少列并说明淘汰原因
- 报告存为 Markdown（主题+日期命名），放主题匹配的目录；跨会话要用的结论同步 memory
- 价格一律标注"检索日期口径，以商品页实时价为准"

## 红线

1. D 级信源不得作为排名依据
2. 参数宁可标"口径分歧"也不编数
3. 企业口径不得直接转为事实陈述
4. 推断必须写明是推断
5. 推荐型号必须满足本报告自设的一票否决线；确要破例列入时，明示违反了哪条线与理由
6. 品牌画像因素逐项标注证据级别与口径来源，不得合成加权综合分
