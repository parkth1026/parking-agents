# shopping-deep-research 设计文档

## 意图与触发场景

为高决策成本的实物商品（家具、家电、数码、工学设备等）做循证式选购调研：排名只认一手销量与口碑数据，营销号"十大品牌"类榜单只当 SKU 线索、不进结论。触发于用户的"帮我调研/对比/排行/选哪个"类请求。不适用：低价标品、纯比价搜券、服务与虚拟商品。

## 设计取舍

1. **评论数作销量代理**：真实销量数据不可得，平台在售 SKU 累计评论数是最可得的一手口径；代价是刷单噪声，用"记录抓取日期 + 类目对齐（整桌≠升降架）"缓解。
2. **访谈弹性轮数 + 需求卡确认**（iter-3 改）：一组 ≤5 问起步、未收敛继续追问、每轮末尾附「已锁定/仍待定」清单；收敛后输出需求卡（使用者/硬约束/一票否决/待定项）回读，用户确认或纠偏后才进调研。用户不在线（自动化/评测）时按"待定 + 分支结论"退化、需求卡标"未经确认"，不虚构答案。iter-1/2 原为"问答限两轮"，因与用户期望的"对话式慢慢锁定需求"冲突而改；无断言锁定轮数，AC-1 退化行为不变。
3. **D 级信源只当线索**：宁可结论慢，不要结论脏；企业自述单独标"公司口径"。
4. **纯指令技能、零脚本零依赖**：全流程是判断类工作，自由度全高，无 scripts/references 资产。
5. **品牌画像层，不做综合评分**（iter-3 新增）：品牌榜排名仍只认销量+口碑两个可量化一手口径；售后保修、企业实力（财报）、可靠性线索作为画像表附在榜旁、逐项标证据级。加权综合分必然引入主观权重=编数（违反红线 2/6），画像层方案使 AC-3 既有断言零改动。
6. **指标先行，而非需求先行**（iter-4 新增）：先调研品类核心指标体系（含义/影响/读数 + 体验决定性/重要/次要/营销虚指标四档）并科普，再用指标语言问场景问题、与用户锁定指标重要性，最后才进品牌与型号——用户不一定知道行业看什么参数，问题若不建立在指标语言上就会迷失本质。Top 5 综合推荐是硬约束匹配+双口径排名+画像的定性综合（带依据链），不做数值加权分。

## 验收条件

| 编号 | 验收条件 |
| --- | --- |
| AC-1 | 需求缺口处理：用户不在线或信息不全时，影响结论的未知项标"待定"并给分支结论，不虚构用户答案 |
| AC-2 | 硬约束落表：物理/人体/预算/场景约束转化为可逐条核对的参数（一票否决 vs 加分分档），推荐型号不违反一票否决约束 |
| AC-3 | 双口径证据：排名/推荐结论由销量（一手代理）+ 口碑证据支撑；电商/自媒体 Top N 榜单仅作 SKU 线索，不作排序依据 |
| AC-4 | 场景分榜：用户存在多个使用场景时，结论按场景分开给，不混排 |
| AC-5 | 在售证据：只推荐有在售证据的型号；抓不到在售证据的明确标"未确认在售" |
| AC-6 | 口径标注：价格、销量等时效数据标注检索日期或"以商品页实时价为准" |
| AC-7 | 结论可执行：最终落到面向用户约束的具体候选型号 + 可核对项（下单前核对清单或等价形式） |
| AC-8 | 诚实性：参数冲突标"口径分歧"、推算标"推断"，不编数；企业口径不转为事实陈述 |
| AC-9 | 品牌画像：品牌榜旁有品牌级因素（售后保修/企业实力/可靠性线索至少两类），逐项标注证据级或"公司口径"，不合成加权综合分 |
| AC-10 | 需求卡：进入调研前对需求做结构化汇总（含一票否决与待定项）回读确认；用户不在线时照常输出并标注"未经确认，按分支结论推进" |
| AC-11 | 行业指标框架：先调研品类核心指标（含义/影响/读数）作为分析框架呈现并科普，需求与推荐按指标重要性分档组织（含点破营销虚指标/次要指标），Top 5 综合推荐为定性综合且逐型号带依据链 |
