# workflow-interview 设计依据

## 意图与触发场景

- 触发模式：名字触发——用户点名技能名或明确要求该能力才触发；情境相近但未点名、未明确要求的请求不触发（2026-10-03 批量定案，与 description 同步收窄）。

三阶段需求缔约的编排器：访谈锁需求、原型锁对照物、契约锁验收，全程决定下一步进哪个
阶段、卡住时退回哪里。由用户或上游编排显式选择，不靠只言片语触发。自己不产出文件，
各阶段产物的定义都在产出它们的子技能里。

## 设计取舍

- **只锁「做什么 / 怎么算做完」**：中间怎么实现交给执行 Agent；这两个点定偏了，中间
  质量救不回来。
- **状态机单一真源**：`manifest.json` / `rounds.jsonl` 只由 `session.mjs` 写；`done`
  不是自报的，结构闸门当场强制，质量仍归自评与用户确认。
- **结构化问法属于家族（#146）**：`response` 字段（九种应答类型）是 `rounds.jsonl`
  的一等字段；`pct` 与 100±2 加和只在单选语义强制——多选的选项是候选集合不是概率，
  硬卡加和只会逼人编数字。schema 与 Web 载体发布协议同源，映射无需变形。
- **决策档案是核心逻辑（#146）**：`export-dossier.mjs` 从家族真源（任务原文、轮次、
  契约）重投影出 HTML 预览，来源文件按相对路径引用而不内嵌（2026-09-12 起）；投影库（`scripts/lib/dossier.mjs`）两载体共用一份实现，
  纯对话访谈产出与 Web 版同构的档案，Web 侧只多提交事件证据（ledger）。
- **简单不是跳过访谈的理由**：再简单的需求也留下问答、取舍与残留风险记录。
- **修订保留底本与已定上游**：吸收0e0dbda1的事实重验、契约留底和对抗复审机制；用共用规则和可选revise工具撤销陈旧Ready，只重开契约阶段。只清现行术语，不改历史；不自动迁仓、放宽验收或增加固定审查人数。

## 验收条件

交付范围由manifest.delivery登记。dossier、依赖检查和提交预览共用该清单。过程留存与Git范围分开；兼容旧任务读取，但旧任务必须先登记才能通过提交检查。登记、修订留底、档案导出和提交检查不执行产品或模型；finalize和verify按契约执行[A]命令。工具不操作Git索引或提交；提交入口独立做只读Git检查。

| 编号 | 验收条件 |
| --- | --- |
| AC-1 | 三阶段结构闸门缺件拒收 `done`；`skipped` 仅 2-prototype 可用且必须带 reason，`finalize` 与残留风险对账 |
| AC-2 | `rounds.jsonl` 行先过 schema 再追加；`ask` 行必带 `question`，单选语义 `pct` 加和 100±2 |
| AC-3 | 非单选结构化行（如 `multi_select`）无 `pct` 可落盘；`min`/`max` 别名写入时正规化为 `min_selections`/`max_selections`，冲突拒收 |
| AC-4 | 无 `web/` 目录时 `export-dossier.mjs` 仍能从 rounds/manifest/contract 导出自包含档案，含完整轨迹、候选优劣势、用户决定、契约原文与 digest，且不创建 `web/` |
| AC-5 | `finalize` 提示仓库外路径及非 `[A]` 档盲区，拒绝结构错误、命令无法运行、残留风险缺失和交接指令超长 |
| AC-6 | 正式清单拒绝缺件、内容漂移、未分类文件和未发布依赖；不删除原始历史，不自动操作Git |
| AC-7 | 登记后的dossier仅投影正式文件，保留Web原答并合并新增family修订；来源字节数与SHA正确，源档案和预览投影一致；包外预览拒绝覆盖 |
| AC-8 | init幂等维护公共ignore并保留自定义内容；提交检查验证真实Git效果、可恢复规则来源与跟踪范围，共享配置列入预览前提 |
| AC-9 | 上游重开或finalize失败撤销契约完成状态，仅关闭上游不能恢复无效Ready；revise先保存契约、manifest及指纹，按实际文件身份合并路径别名，保留全部登记SHA约束和历史，不操作Git索引 |
