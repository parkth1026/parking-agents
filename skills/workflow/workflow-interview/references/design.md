# workflow-interview 设计依据

本技能由用户或上游显式选择，交付目标与验收约定，不实现产品。
三个职责是调查理解、具体对照和契约交接；允许合并、交错和复用。

## 当前取舍

- 授权内由 Agent 选择方法，用户决定目标、限制和重大后果的接受范围。
- manifest 由 session.mjs 写，rounds 经 round 追加；状态一致性不等于语义确认。
- 过程文件和固定问法不作为质量代理。保留记录有效性、实际引用可访问性和校验版本绑定。
- pct 为可选历史字段，无强制偏好概率或加和阈值；九种 response 类型继续兼容。
- ready 表示宿主已声明授权与验收对齐，职责闭合且当前校验有效；finalize 只做机器校验。
- rebuild 只恢复有依据的记录，不扫描文件制造 confirmed。
- dossier 是可复用的投影能力，按需导出；两载体共享交付语义，分别维护投影适配。
- 旧任务已确认约束不自动降级，不批量迁移历史数据。下游 digest、SHA 和人验边界不变。

## 验证方向

验证无概率单选、可选过程材料、自由对照物载体、AC 缺号与多条验收。
同时验证无授权恢复不制造 ready、声明引用缺失仍拒、校验过期仍拒、
旧记录保真和 Web 持久提交及幂等消费不退化。
测试评估实际内容与行为，不把某一句问法、某个文件名或轮次数当成普遍质量。
