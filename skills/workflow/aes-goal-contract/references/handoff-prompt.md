# 启动指令模板

任务记录落盘并通过校验后，按执行 Agent 的类型二选一。两个变体都以落盘记录和其中引用的有效授权为依据，避免无助于交接的重复。

## 变体一：会话式执行 Agent

把下面这段发给执行 Agent。把 `<goal contract 路径>` 换成绝对路径，其余原样。

```text
按 <goal contract 路径> 执行。

这份任务记录是本次需求的唯一权威。先完整读它，它的「读什么」一节点名的文件也全部读，
那里有已经拍过板的取舍和用户确认版的对照物，绕开它们等于把定过的事重定一遍。

仓库里查得到的事实自己查，不要回来问我。

结合原始背景、目标、范围和确认的对照物，理解本次要做成的样子。
完成实现，用证据说明目标及全部已确认验收条件成立，并保持强约束。
Verify 全过不能覆盖已发现的目标偏差；也不要把通用 QA 惯例变成新目标。
围绕目标和实际影响选择验证，考虑准备、执行、诊断和维护的时间成本，复用有效证据。
已确认的验证要求和仓库门禁仍须履行；时间不足时如实报告，不能静默降低要求。
review 最终 diff，在不改变行为的前提下 simplify。

在目标与已有授权内，自行决定调查、实现和验证取舍。「自主边界」重点规定例外限制，
未列举的正常实现选择不因此失去授权。需要新的用户决定、授权或关键输入时再问。
已有明确要求继续有效，不能靠改变验收含义、隐藏失败或沿用失效证据制造通过。

全部验收条件满足之前不要停，也不要只交一份计划。

某条确实做不到时，把其余部分做完，然后单独说明是哪条、卡在哪里、需要什么才能解开。
不要因为一条卡住就停下整件事，也不要悄悄降低那条的标准。
```

需要真人决定的要求保留待人验状态，或用真实确认凭证证明。长时程工具无法承接时，
选择会话式交接或报告阻塞；不能为了工具能结束而自行改写或移出已确认的验收义务。

## 变体二：Codex `/goal` 长时程执行

`/goal` 的续跑机制每个 turn 都会重新注入 objective 文本并对它做完成审计，所以目标
端态应内联在命令里，同时指向完整契约。预算走 `/goal` 的参数传递，
接入真实记账；写进文档的预算数字不接入任何机制。

```text
/goal 完成 <goal contract 路径> 定义的目标：<目标节内容>。先读完整契约及引用，结合原始背景、范围和确认的对照物理解期望结果。完成须有证据支持目标、全部已确认验收条件及强约束；Verify 全过不能覆盖已发现的目标偏差。围绕目标和实际影响选择验证，考虑准备、执行、诊断和维护的时间成本；不擅自降低已确认的要求。计划外的事按该文档「自主边界」节自行判断。
```

最后那句只在契约真的有「自主边界」节时才加，`finalize` 会自己判断。指向一节不存在的
内容比不提更糟：执行 Agent 会去找，找不到，然后自己编一套边界出来。

它值得占这几十个字符，是因为它管的正是长时程执行里最贵的两种失败——为一件小事停下来
等人，和自作主张把改动摊大。别的东西执行 Agent 遇到了才需要查，这一条它每一轮都在用。

本地生成器对这条指令设有 4000 字符兼容限制。超限时，改用会话式交接，或在不丢失
已确认内容的前提下压缩表达。不要为工具长度限制删减目标或验收义务；目标可以用必要的
段落、列表和具体例子表达。生成器会提示切换交接方式，不截断契约。

### 交付后人工复核不进 objective

只有既有授权允许交付后复核时，才将对应事项这样安排。清单交给用户本人，
不把待人验记成已通过。原本属于交付完成条件的要求，不因换执行工具而自动移到审计之外。

## 为什么只有这么短

任务记录带着背景、目标、范围、验收条件和强约束。启动指令
再抄一遍，两处就会各自漂移，而落盘的记录比聊天里的指令活得久。

指令指向权威材料，提醒执行者围绕目标判断完成、按证据与时间成本选择验证，并在已有
授权内推进。具体标准留在契约里，不再复制一份通用 QA 清单。
