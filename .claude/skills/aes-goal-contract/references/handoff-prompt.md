# 启动指令模板

任务记录落盘并通过校验后，按执行 Agent 的类型二选一。两个变体都把落盘的记录当作唯一
权威，不复述它的内容。复述一份就会漂移一份。

## 变体一：会话式执行 Agent

把下面这段发给执行 Agent。把 `<goal contract 路径>` 换成绝对路径，其余原样。

```text
按 <goal contract 路径> 执行。

这份任务记录是本次需求的唯一权威。先完整读它，它的「读什么」一节点名的文件也全部读，
那里有已经拍过板的取舍和用户确认版的对照物，绕开它们等于把定过的事重定一遍。

仓库里查得到的事实自己查，不要回来问我。

完成实现，逐条跑通「验收条件」里的 Verify 行，「强约束」列的东西一条都不许破。
review 最终 diff，在不改变行为的前提下 simplify。

撞上任务记录里没写的事，只回答一个问题：不做它，验收条件能不能达成。不做就达不成
就做，并且写清你做了什么、为什么非做不可；不做也能达成就不做。别把「要不要打扰我」
当判断标准。

全部验收条件满足之前不要停，也不要只交一份计划。

某条确实做不到时，把其余部分做完，然后单独说明是哪条、卡在哪里、需要什么才能解开。
不要因为一条卡住就停下整件事，也不要悄悄降低那条的标准。
```

## 变体二：Codex `/goal` 长时程执行

`/goal` 的续跑机制每个 turn 都会重新注入 objective 文本并对它做完成审计，所以一句话
端态必须内联在命令里，它是每 turn 的锚，光给路径不够。预算走 `/goal` 的参数传递，
接入真实记账；写进文档的预算数字不接入任何机制。

```text
/goal 完成 <goal contract 路径> 定义的目标：<目标节那一句话>。验收以该文档「验收条件」
节全部 Verify 通过、「强约束」节全部保持为准。
```

**这一句有 4000 字符硬上限。** `create_goal` 的 payload 只吃一个 objective 字符串，
超了直接拒收，不会截断。生成后数一遍长度，超了就压缩「目标」那句话——压的是这句话，
不是契约。`session.mjs finalize` 会替你数并在超限时报错。

这也是「光给路径不够」的另一面：路径省字符，但 `/goal` 每 turn 重注入的是 objective
文本本身，端态必须内联在里面。两个约束一起把这句话夹在「必须自足」和「不能超长」
之间，所以「目标」节本来就该是一句话。

## 为什么只有这么短

任务记录自己带着「验收条件」和「强约束」，完成标准和不许碰的东西都在里面。启动指令
再抄一遍，两处就会各自漂移，而落盘的记录比聊天里的指令活得久。

所以指令只做四件事：指路、确立权威、给出计划外情况的判据、点名最常见的两种失败。
那两种失败是停在计划，和拿一条卡住当作整件事的借口。其余交给记录本身。
